## 1. 已确认的产品方向

1. 产品是按周或按月更新的个人财务助手，不依赖每日手工记账；
2. 支付宝、微信是第一核心入口，银行文件是可选覆盖增强；
3. 默认先看结果，但自动处理必须可核对、纠错和撤销；
4. 清晰事件先完成，异常按文件、账户、身份或关系隔离；
5. 资金方向、经济性质、生活分类、关系和判断状态分开；
6. 贷款和分期保留但按需出现，不阻塞普通账单；
7. 核心正式账本不变，不引入第二套账本；
8. 小程序、CloudBase 和商业化暂缓，不永久关闭。

## 2. 当前系统已经具备

- 原文件、批次、原始行、来源账户和稳定来源身份；
- 支付宝、微信自动解析，通用银行 CSV 映射，光大信用卡 PDF 专用解析；
- 同文件防重、同来源精确去重、跨来源候选和人工决定；
- 原子 posting、证据下钻、幂等和三库兼容；
- 账户发现、沿用、忽略和单行不入账；
- 唯一交易计划、49 组跨渠道证据、明确退款和信用卡还款账户选择；
- 贷款/分期合同、计算、计划、实际结算和撤销；
- 财务总览、覆盖、信用卡账期和待还摘要。

这些能力优先复用或隐藏，不因主流程简化而删除。

## 3. 当前实现与目标需求差异

| 差异 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 完成粒度 | 整理任务级确认 | 事件级独立整理，默认整批原子入账，部分入账需用户主动选择 |
| 普通转入 | 清晰收支可能直接按方向入账 | 方向与经济性质分开，性质未知待处理 |
| 主流程 | 五步和五张数据卡 | 三步结果流，高级核对按需展开 |
| 贷款入口 | 固定主导航 | 有债务或主动启用时突出 |
| 分期候选 | 可进入整理待办 | 非阻塞债务建议 |
| 银行文件 | 光大专用 PDF + 通用 CSV | 结构化优先、失败隔离、覆盖缺口 |
| 文档 | 历史和当前混杂 | 当前、目标、未来、归档分层 |

## 4. 共享设计硬约束

- 事件级状态、批次入账、关系、迁移和 API 在实现前必须由主负责人串行冻结；
- 所有新用户表、查询和唯一约束带 `uid`；
- 只凭金额和时间不得自动合并；
- 旧人工决定、已入账交易和原始证据不得被新规则静默覆盖；旧任务、todo 和自动候选允许备份后重建；
- 新 schema 只能使用连续 forward-only 显式迁移；
- 数据正确性同时在 SQLite、MySQL、PostgreSQL 成立；
- 账单工作流允许破坏性替换，不维护旧 API、页面和状态机适配层；仍须提供事实保留、备份和整库回滚方案；
- 原始账单和真实敏感夹具不进入提交、普通日志和聊天。

## 5. DESIGN-1501 冻结结果

| 决策 | 结论 |
| --- | --- |
| 经济性质未知 | 持久 `EconomicEvent(needs_action)`，不进正式账本和报表 |
| 入账与幂等 | 默认整批原子入账；显式部分入账；更新版本、事件版本、动作键和请求摘要共同裁决 |
| 多次退款 | `refund_of` 关系累计不得超过原消费金额，关系版本和数据库条件更新处理并发 |
| 用户纠错 | 按字段锁定人工事实，自动规则只重算未锁定字段 |
| 数据保留 | 保留正式账本、原始证据、账户映射、来源身份和人工事实；旧任务、todo 和自动候选重建 |
| 总览 | 只统计正式交易；未入账和部分入账通过覆盖与批次状态明确展示 |
| 页面 | 结果摘要和守恒计数优先，事件、证据、字段来源和历史按需下钻 |
| 迁移与回滚 | v009 一次切换，无旧 API 兼容层；三库显式迁移，正式切换前备份，失败整库回滚 |
