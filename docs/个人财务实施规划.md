## 0. 文档使用与当前看板

### 0.1 唯一事实源

- 根目录 `AGENTS.md`：长期协作、安全、分支、数据和验证硬约束；

- [个人财务待处理问题与关系裁决设计.md](./个人财务待处理问题与关系裁决设计.md)：DESIGN-1701 冻结设计，描述问题工作台、批量决定、同一事件、退款关系、服务端可入账校验和报表语义；v010 已落地问题投影与关系裁决，报表语义仍按看板收口；
- 本文：当前生产状态、任务、未决项和下一步；
- `现行说明/`：当前代码实际行为；
- `归档/`：旧版原文与完成证据，只在追溯时读取。

任务看板由主负责人维护。执行会话只领取一个明确任务并报告待验收；只有集成、验证、文档和资源清理完成后才能标记已完成。

### 0.2 仓库与产品边界

- 本仓库是长期受控 fork，`origin/main` 是产品权威；
- `upstream/main` 只作为安全、数据损坏和数据库兼容修复来源；
- 正常部署保持一个 Go 模块化单体和 SQLite/MySQL/PostgreSQL 三选一；
- 现有 `Transaction`、`Account`、分类和标签是唯一正式账本；
- `personalfinance` 保存证据、解释、关系、债务计划和覆盖，核心账本不得反向依赖；
- 当前权威客户端是 Web/PWA，小程序保留在未来规划。

### 0.4 状态定义

- `未开始`：未领取或依赖未满足；
- `进行中`：已有负责人、分支和工作区；
- `待验收`：候选已交付，等待复核或集成；
- `已完成`：已集成、按风险验证、更新文档并安全清理；
- `阻塞`：存在已记录且无法在授权内解决的外部依赖或用户决策。

## 3. 当前实现与目标需求差异

| 差异 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 待处理主体 | 事件列表，前端按展示字段临时折叠相似记录 | 服务端稳定问题列表，一张卡片对应一个用户决定 |

| 退款 | 主要在当前规划范围内自动候选，界面缺少完整历史原交易选择 | 跨当前更新、历史事件和正式交易搜索，确认关系后才能入账 |

| 完成粒度 | 事件可整理、批次确认，但问题对象不稳定 | 事件级整理、问题级处理、默认整批原子入账 |
| 贷款入口 | 固定主导航 | 有债务或主动启用时突出 |
| 分期候选 | 可进入整理待办 | 非阻塞债务建议 |
| 银行文件 | 光大专用 PDF + 通用 CSV | 结构化优先、失败隔离、覆盖缺口 |
| 文档 | 已完成阶段和新缺口分散 | 当前、目标、候选设计、未来和归档分层 |

## 4. 共享设计硬约束

- 事件级状态、问题、批次入账、关系、迁移和 API 在实现前必须由主负责人串行冻结；
- 所有新用户表、查询和唯一约束带 `uid`；
- 内容完全相同也不得单独自动合并；无稳定来源标识时，不同物理行默认是不同来源记录；
- 批量应用同一答案不得改变独立事件身份；同一事件必须通过显式身份裁决或强稳定证据确定；
- 退款关系未确认、转账双方账户不完整或其他阻塞问题未解决时，不得进入 `ready`；
- 旧人工决定、已入账交易和原始证据不得被新规则静默覆盖；旧任务、todo 和自动候选允许备份后重建；
- 新 schema 只能使用连续 forward-only 显式迁移；
- 数据正确性同时在 SQLite、MySQL、PostgreSQL 成立；
- 账单工作流允许破坏性替换，不维护旧 API、页面和状态机适配层；仍须提供事实保留、备份和整库回滚方案；
- 原始账单和真实敏感夹具不进入提交、普通日志和聊天；
- DESIGN-1701 对应实现和生产副本验收完成前，不执行当前正式批次第一次真实入账。
