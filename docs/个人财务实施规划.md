## 4. MINI-1903 冻结契约

1. `bootstrap` 是首个业务动作。客户端只发送动作名，云函数必须从 `cloud.getWXContext().OPENID` 取得身份；请求中出现 `uid`、`openid` 或同义身份字段时直接拒绝。
2. 数据库不保存明文 OpenID。服务端将 `wechat-mini:<OPENID>` 计算为 SHA-256 身份摘要，通过 `catledger_user_identities(provider, subject_hash)` 唯一约束映射到内部 UUID；响应、日志和客户端缓存均不返回内部 `uid` 或身份摘要。
3. 首版迁移只建立 `catledger_schema_migrations`、`catledger_users`、`catledger_user_identities` 和 `catledger_categories`。除迁移表外，每张业务表均带 `uid`；表、索引和环境变量全部使用 `catledger_` / `CATLEDGER_` 命名空间。
4. 初始化在单个 MySQL 事务中创建用户、身份映射和默认分类；重复、并发请求只能产生一个用户和一套默认分类，任一步失败必须整体回滚。迁移编号连续、forward-only、可重入并校验 SHA-256 checksum。
5. 默认分类只覆盖支出和收入；转账由交易类型表达，不伪装成分类。系统键稳定，中文名称可在后续版本中由用户调整；退款不作为普通收入默认分类。
6. 数据库使用官方推荐的 `mysql2` 连接池，通过云函数私有环境变量和 VPC 内网连接。仓库不保存数据库地址、账号、密码或云环境 ID。
7. 当前 AppID 下已有云环境包含其他项目函数。本任务只允许新增 `catledger-api` 和 `catledger_*` 表，不删除、重命名、部署或读取其他命名空间资源；部署前必须确认 MySQL 已初始化且猫账数据库配置独立。

候选验证：`catledger-api` 的 5 个身份/隐私单元测试及 5 个 MySQL 5.7 集成测试通过；覆盖迁移重跑与 checksum、重复初始化、8 路并发唯一裁决、双用户隔离、明文 OpenID 不落库和失败整体回滚。微信开发者工具已打开任务 worktree 并在模拟器编译展示新版启动页；因云端尚未迁移和部署，页面按预期显示“尚未配置完整云环境”。`wx-server-sdk@4.0.2` 仍是当前最新版，`npm audit` 的 1 个中危与 5 个高危来自其 CloudBase 传递依赖，只有降级到破坏性版本的修复建议；当前入口不接收 URL、代理配置或任意对象合并参数，暂不执行 `--force` 降级。CloudBase 插件已启用，但当前会话无法热加载其 MCP；云端环境核验、迁移和部署仍待后续会话完成。
