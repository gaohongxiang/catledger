# 招财猫记账本文档

> 英文及技术代号为 `CatLedger`；中文正式产品名为“招财猫记账本”。

## 项目概览

招财猫记账本是以批量账单导入为主、手工记账为辅的微信原生小程序。系统先把支付宝、微信支付和后续银行等不同资料整理成可追溯的正式账本，再基于正式交易计算余额、收支、净值和未来资金状态；不替用户执行付款、转账、投资或借款。

当前已经具备微信可信身份、账户、分类、手工支出/收入/转账/退款、余额校正、交易查询和基础统计。MINI-1905/1906 多账单统一导入候选已经合入主线，支持私有上传、独立解析、跨来源关联、FinanceUpdate 待确认和整批原子入账；当前下一步是 MINI-1906V 真实微信身份完整验收，尚未提交审核或正式发布。

```text
来源文件 → 原始证据 → FinanceUpdate → EconomicEvent / ReviewIssue
        → 用户确认 → Transaction / Account → 余额、收支和统计
```

只有正式交易影响余额和统计。多份资料可以是同一次现实资金活动的不同证据，不能因此重复入账；金额、时间或文本接近也不能单独触发自动合并。

当前后续阶段已经拆分为“真实验收 → 现有账本完整性收口 → 持续质量门禁 → 发布基础能力 → 分录影子写入与切换 → 财务状态”。原 `specs/mini-1906a-ledger-integrity/` 保留为总体设计来源，不再作为一个整体直接执行；近期执行规格以 `mini-1906v-import-acceptance` 和 `mini-1906a1-ledger-integrity-closure` 为准。

## 事实边界

- 入账逻辑说明负责通俗理解，不替代正式契约；
- 用户需求定义用户可感知行为和产品范围；
- 业务规则与验收定义财务、导入、身份和隐私的对错标准；
- 架构设计定义模块、公共数据关系和技术边界；
- 实施规划是阶段状态、任务、冻结契约和完成证据的唯一事实源；
- 阶段规格只在实施规划登记的依赖和授权范围内生效；
- 现行说明描述当前行为，若与代码、迁移或自动测试冲突，以已落地证据为准并修订说明。

具体账单模板由解析代码、脱敏测试夹具和现行说明共同维护，不在多个文档复制易漂移的字段表。迁移前 Web 版的完整资料保存在 `catledger-web` 分支和 `web-v2-final` 标签，不在小程序主线重复维护。
