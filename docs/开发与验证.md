# 开发、验证与交付

> 本文维护运行步骤和安全边界，不维护“本周哪个版本已上线”。当前状态看[实施规划](招财猫记账本实施规划.md)，业务全貌看[项目逻辑说明](招财猫记账本入账逻辑说明.md)。所有命令先核对当前目录、环境和授权，不对真实财务库尝试测试清理。

## 1. 开工前

读取 [AGENTS](../AGENTS.md) 和当前任务，核对用户实际项目目录、微信开发者工具打开的路径、本地修改、分支、worktree 与远端差异。小修不为形式另开 worktree；确需隔离时使用明确任务分支并保留并行成果。

以下只读取工作区和远端引用，不切换或丢弃代码：

```sh
git status --short
git branch --show-current
git worktree list
git fetch origin
git log -5 --oneline --decorate
```

禁止 `git reset --hard`、force push、未经确认可能丢工作的 rebase 或删除未知工作区。用户本次 `backup-docs` 是保全分支，不能拿来继续开发。工作分支和收敛结果以[实施规划](招财猫记账本实施规划.md#2-分支收敛与保全)为准；合并与清理依据用户明确授权，不重建已收敛的同任务分支。

## 2. 本机环境与配置

使用微信开发者工具打开仓库根目录，[project.config.json](../project.config.json) 定义小程序与云函数目录；个人 AppID/环境覆盖、AppSecret、数据库和云密钥不提交。云函数配置由部署环境提供，客户端不持有数据库凭据。

函数使用以下私有环境变量；值由当前已授权环境取得，不能把示例当真实配置：

```text
CATLEDGER_DB_HOST
CATLEDGER_DB_PORT
CATLEDGER_DB_USER
CATLEDGER_DB_PASSWORD
CATLEDGER_DB_NAME
```

先安装两函数的锁定依赖，再执行根目录检查。不要顺手升级依赖、重写 lockfile 或切换项目框架。

```sh
npm ci --prefix cloudfunctions/catledger-api
npm ci --prefix cloudfunctions/catledger-import
npm run check
```

当前 CI 的 Node 和 MySQL 版本以 [verify.yml](../.github/workflows/verify.yml) 为准；整理基线为 Node 18 / MySQL 8.4。它们是项目已配置的验证环境，不是在此推荐永久使用某个运行时版本。

## 3. 文档与工程检查

```sh
npm run check:docs
npm run check
```

文档检查验证现行入口的本地链接、章节锚点和源码行引用；不访问外部链接，不证明文字语义一定正确。现行手册变化要人工核对代码；旧 specs 正文保持当时上下文，从固定历史提交阅读其旧章节链接。

工程检查继续覆盖 JS/JSON 语法、微信项目配置、函数入口、独立部署包依赖、CommonJS 循环、纯规则边界、平台语义边界、共享领域实现一致性及 Page 显式绑定。新增文档检查不替换或削弱这些门禁。

检查器自身的受控样例可执行：

```sh
node scripts/check-docs.js --self-test
```

## 4. 单元测试与隔离数据库

```sh
npm test
```

根入口按现有脚本运行根测试与两函数测试。非数据库模式主动清理测试数据库环境变量，数据库用例会明确跳过；**跳过不是通过，也不能声称已验证事务。**

数据库回归会迁移并清理测试表，只能连接明确可清空的隔离实例。先确认配置全部属于测试环境，再执行：

```text
CATLEDGER_TEST_DB_HOST
CATLEDGER_TEST_DB_PORT（可选）
CATLEDGER_TEST_DB_USER
CATLEDGER_TEST_DB_PASSWORD
CATLEDGER_TEST_DB_NAME
```

```sh
npm run test:db
```

缺少必要配置会失败，不能为了通过去借用真实云库。隔离库创建与安全检查参考 [isolated-mysql.js](../scripts/isolated-mysql.js)，实际套件行为看 [test.js](../scripts/test.js)。数据库串行门禁与真实用户隔离、版本、幂等、关系和回滚反例必须保留。

生产依赖审计分别运行：

```sh
npm run audit:prod --prefix cloudfunctions/catledger-api
npm run audit:prod --prefix cloudfunctions/catledger-import
```

审计结果需绑定具体提交和执行日期，不是长期无漏洞承诺。

## 5. 选择哪些行为验证

| 改动范围 | 必须覆盖 |
| --- | --- |
| 仅文档 | 链接/锚点、源码入口、事实分层、旧资料保全与分支差异 |
| 规则或解析 | 正例、相似反例、未知/冲突、版本、逐行归宿和证据关系 |
| SQL 或事务 | 约束、并发、回滚、用户隔离、版本、幂等及关联依赖 |
| 页面与会话 | 真实 Page 入口、迟到响应、隐藏/卸载、换用户、编辑保护和原请求恢复 |
| 缓存与性能 | 实际请求/SQL/字节/派生/setData 与预算，热冷路径分别比较 |
| 贷款与分期 | 金额构成、计划与流水分离、费用防重、来源有效性和连续进度异常 |
| 整组删除与重建 | [删除DB](../test/loan-deletion-db.test.js)覆盖创建归属、认领保留、共享／退款阻塞、600期完整撤销、重建和旧键重放；[真实Page/DB](../test/loan-deletion-ui-db.test.js)覆盖一次确认、响应丢失与只读刷新，导出恢复检查0029列 |

详细场景看[业务规则与验收](招财猫记账本业务规则与验收.md)。复用已有真实行为测试，只补缺口；不能为重构方便而删掉金融反例。结构/字符串断言不是事务正确性的证据。

贷款 A0～A5 的新增套件为 `loan-charges*`、`loan-charge-*-db`、`loan-charge-pages` 和 `loan-period-payment-db`；最后一项验证期内付款与关联原子提交、部分付款、并发、故障回滚和已有扣款复用。L01～L18 对照只维护在实施规划。原有导入等价、付款组、来源、退款与旧UID迁移回归继续执行；0011 夹具生成时临时提供现代空表，移除前断言全部为空，实际迁移仍只验证原29张非空表。

### 长计划同环境计量

复现入口为 [installment-performance-db.test.js](../test/installment-performance-db.test.js)：在配置好隔离 MySQL 后执行；只打印请求/SQL/读取行数/字节/派生/耗时，不打印账目字段。调用真实 Page、handler 与 MySQL，统计 execute 次数（不含 BEGIN/COMMIT），读取行是数据库返回行数，不冒充内部扫描行。Page setData 是数据桥输入字节，不是原生绘制耗时。短计划12期、历史36/600期、多贷款11笔（含288条来源、24笔付款）使用固定合成数据。

```sh
node --test test/installment-performance-db.test.js
```

| --- | --- | --- | --- | --- | --- | --- |
| 12期详情 | 6→5 | 22/107→21/106 | 25254→18022 | 3/2→2/2 | 21029/10572→相同 | 41.6→40.6 |
| 36期历史详情 | 7→5 | 27/85→21/82 | 42881→24682 | 4/3→2/2 | 34159/11644→相同 | 17.5→13.4 |
| 600期历史详情 | 21→5 | 97/114→21/83 | 935844→166326 | 18/17→2/2 | 310624/193128→相同 | 125.4→55.6 |
| 11笔贷款列表 | 3→3 | 11/612→相同 | 28638→相同 | 11/11→相同 | 30640/30523→相同 | 28.4→21.7 |

600期确认事务单独计量：4824次SQL、662返回行、4208受影响行不变，原计划计算602→2次，视图1次，请求19819字节、回执80字节，1942.8→1637.1ms；一个用户锁事务提交全部600期。保存后刷新另计，正常路径7→6请求；后置页面现在保留全部600行，数据桥最大194324字节（原仅展示20行），仍低于256KiB预算。故障测试在第300期强制失败，验证全部回滚、草稿保留后重试，不拆成多笔保存。完整快照最大响应117325字节，低于256KiB；不增加跨请求服务端缓存。

### 本轮审查同环境计量

使用 [review-performance-db.test.js](../test/review-performance-db.test.js) 加载包含.git的基线/当前检出，在同一专用本机MySQL中各重复3次。每次独立schema与API/import最小权限角色；五文件共1000行导入、600期一次原子保存。计量下一次操作前等待已发候选读取全部完成，避免把上一操作的后台查询混入保存。SQL轮次包含BEGIN/COMMIT/ROLLBACK，另列纯语句数；用户持锁时间从取得用户行锁至提交/回滚。响应和setData均为UTF-8 JSON字节；不表示云端或手机绘制耗时。

```sh
CATLEDGER_PERF_RUNS=3 CATLEDGER_PERF_OUTPUT=/private/tmp/catledger-review-perf-current.json node --test test/review-performance-db.test.js
CATLEDGER_PERF_SOURCE_ROOT=/path/to/verified-baseline-checkout CATLEDGER_PERF_RUNS=3 CATLEDGER_PERF_OUTPUT=/private/tmp/catledger-review-perf-baseline.json node --test test/review-performance-db.test.js
```

2026-09-30：Apple M2 Max、Node24.14.1、MySQL8.4.11，本地各3轮，基线为 `c4e04a8`。测量脚本摘要 `c88079d7aafcde37cfcac45794262e68c83bd467d82067502ab8dbe966a413df`，修复源文件摘要 `f0391f93460ac136e11c69feec842cc7a1382324b3ee41d83e2b252c27d0c654`；测试在每轮首尾核对源文件不变。

## 6. 原生工具与手机

核对开发者工具工程路径后编译，再用合成数据验证相关页面。保留用户已打开的窗口和工作区，不将隔离验证目录误当用户真实工程。

真实 Page VM 测试仍替代了网络、存储及微信数据桥；原生编译只证明入口可以运行。触摸、键盘、滚动、后台切换、弱网和完整业务时序需要相应原生/手机走查。没有执行时明确写“待验收”，不能用上传或预览成功代替。

合成原生验证可复用 [native-local-bridge](../scripts/native-local-bridge.js) 的 `loans` 场景：专用本机隔离库、API/import 最小角色、127.0.0.1 桥；临时项目禁用云调用/云存储并使用隔离内存存储。结束关闭桥回收其库和私有临时状态，不刷新用户真实项目。该验证覆盖真实 Page、微信数据桥和本地 handler，不能代替真机与云网络。

真实账单盘点仅在用户授权后进行，原件只读，脱敏报告放在约定的安全位置；不得把原文、完整账号或数据库绑定值写入仓库和普通日志。

## 7. 迁移与部署需另有授权

数据库迁移使用 [migrations](../migrations) 中连续、向前且可重入的显式脚本。**下面是部署阶段的命令，不是普通测试或打开项目时执行的步骤。**

```sh
# 仅在已核对目标数据库、备份和迁移授权后执行
npm run migrate --prefix cloudfunctions/catledger-api
```

运行时应用角色与迁移角色分开，权限调整使用现有最小权限方案。失败先确认迁移状态和重入能力，不通过删表、清库或删除审计列恢复。

普通永久删账无需结构迁移；部署阶段只按已核实的实际API运行账号补三张表级DELETE。以下命令仅生成SQL，不执行授权；检查输出后仍需获得线上授权才能执行。先准备权限与支持缺失链接重核的import函数，再部署API和验证客户端，避免新删除结果遇到旧重导逻辑。若分开账号，import账号不增加正式交易DELETE。

```sh
node scripts/print-permanent-delete-grants.js VERIFIED_DATABASE VERIFIED_API_USER VERIFIED_HOST
```

云函数各自部署。使用仓库已有发布工具时，`functionRootPath` 指向项目的 `cloudfunctions` 父目录，`functionName` 指向实际函数目录；发布后读取函数详情确认状态、运行时及必要网络/配置项，不输出凭据。客户端与服务端接口配套，新增接口先准备服务端再验客户端，不能让新版页面调用尚未发布的接口。

当前工作分支、任务状态和授权边界统一看实施规划；历史迁移部署记录不能作为后续任务的自动授权。

## 8. 提交、CI 与交付

提交前检查差异只属于本任务，没有敏感数据、构建产物或用户配置；运行必要门禁并记录通过、失败和跳过。按当前任务分可运行小提交，不混入其他任务。

按用户授权推送指定分支后核对精确 SHA 的 CI，不使用前一个 SHA 的成功冒充当前。分支保护要求 PR 时遵循保护；创建审阅 PR 不等于合并。

交付说明至少给出分支/提交或 PR、主要变化、实际验证、仍待验收项和是否发生部署。用户授权合并且确认无未合入工作后再正常清理临时分支/worktree，不强制删除。用户备份和旧 Web 归档不属于默认清理范围。
