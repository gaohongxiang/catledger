# 架构与代码导航

> 这是一份现有实现的定位图，不是待实施的大架构。完整业务顺序见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，当前任务状态见[实施规划](招财猫记账本实施规划.md)。整理基线：`b804bfc4`。历史设计见[归档](归档/README.md)。

## 1. 部署边界

```text
miniprogram（微信原生 UI 与客户端服务）
    ├── catledger-api（普通账本、贷款、统计、导出）
    └── catledger-import（账单解析、整理、核对、入账）
                     ↓
                CloudBase MySQL
原始文件另外使用私有云存储；它不是权威余额来源。
```

两个函数分别打包、部署，不跨函数目录 require。不使用常驻应用服务、云托管或新增数据库；是否改变部署形态须另有实测与授权。未来资金预测、决策模型、复式分录和影子双写不是这张现状图中的运行组件。

| 层 | 职责 | 权威入口 |
| --- | --- | --- |
| 小程序路由与导航 | 页面注册、中央记账选择、实际可访问入口 | [app.json](../miniprogram/app.json)、[custom-tab-bar](../miniprogram/custom-tab-bar/index.js) |
| handler | 可信微信身份、请求验证、公开错误边界 | [API handler](../cloudfunctions/catledger-api/src/handler.js)、[import handler](../cloudfunctions/catledger-import/src/handler.js) |
| 动作注册 | 公开 action 到服务方法的明确映射 | [API registry](../cloudfunctions/catledger-api/src/action-registry.js)、[import registry](../cloudfunctions/catledger-import/src/action-registry.js) |
| 契约 | 请求字段、返回形状、允许值及限制 | [shared](../shared) |

| 要修改的职责 | 从哪里进入 |

| 两级分类、分配、停用和恢复 | [category-service](../cloudfunctions/catledger-api/src/category-service.js) |

| 贷款资料、实际借还与计划入口 | [loan-service](../cloudfunctions/catledger-api/src/loan-service.js)及其直接依赖 |

## 4. 导入服务的真实分层

```text
解析器 + profiles → 标准行语义 → 证据与关系 → organizer-planner
                                              ↓
                            FinanceUpdate / Event / ReviewIssue
                                              ↓
        review-issue-service（命令事务入口）→ review 场景模块
                                              ↓
            policy / event-store / issue-store / reconciliation
                                              ↓
                       finance-update-posting（正式入账）
```

| 职责 | 实现入口 | 不应承担 |
| --- | --- | --- |
| 文件容器和来源模板 | [parsers](../cloudfunctions/catledger-import/src/parsers)、[profiles](../cloudfunctions/catledger-import/src/profiles) | 直接写正式交易 |
| 平台语义 | [row-semantic-resolver](../cloudfunctions/catledger-import/src/row-semantic-resolver.js) | 由通用事件层再次解释平台文本 |
| 来源身份、强弱关系 | [evidence-matching](../cloudfunctions/catledger-import/src/evidence-matching.js)、[relation-resolver](../cloudfunctions/catledger-import/src/relation-resolver.js) | 仅靠相似自动合并 |
| 计划协调 | [organizer-planner](../cloudfunctions/catledger-import/src/organizer-planner.js) | 另建通用插件或外部 AI 工作流 |
| 批次创建、读取与维护 | [finance-update-core](../cloudfunctions/catledger-import/src/finance-update-core.js)、[finance-update-read](../cloudfunctions/catledger-import/src/finance-update-read.js)、[finance-update-maintenance](../cloudfunctions/catledger-import/src/finance-update-maintenance.js) | 为公共能力反向依赖核对总服务 |
| 核对事务入口 | [review-issue-service](../cloudfunctions/catledger-import/src/review-issue-service.js) | 把事务拆成各模块独立提交 |
| 确定性规则 | [review/policy](../cloudfunctions/catledger-import/src/review/policy.js)、[organizer-values](../cloudfunctions/catledger-import/src/organizer-values.js) | SQL、连接池、页面与存储 |
| 事件和问题存取 | [event-store](../cloudfunctions/catledger-import/src/review/event-store.js)、[issue-store](../cloudfunctions/catledger-import/src/review/issue-store.js) | 把有校验的保存简化成无业务 CRUD |
| 投影与收尾 | [reconciliation](../cloudfunctions/catledger-import/src/review/reconciliation.js) | 读路径无意执行历史同步和计数写入 |
| 场景步骤 | [account-mapping](../cloudfunctions/catledger-import/src/review/account-mapping.js)、[event-decisions](../cloudfunctions/catledger-import/src/review/event-decisions.js)、[repayment](../cloudfunctions/catledger-import/src/review/repayment.js) | 互调公开命令或新开事务 |
| 正式入账 | [finance-update-posting](../cloudfunctions/catledger-import/src/finance-update-posting.js) | 绕过历史、来源、现金与关系门禁 |

`saveEvent/saveEvents` 负责引用校验、可入账重算、原因、版本与操作来源；旧升级的引用保护与 semantic 来源是契约的一部分。`recalculateUpdateCounts` 还涉及历史核对、草稿可达性和批次版本，不是无副作用统计函数。需要改这些函数时先读完整调用链和测试。

## 5. 数据分层与事务

正式账本为账户、分类、交易。导入保存文件/批次、原始行、来源身份、事件证据、事件关系、问题与成员、用户行动、事件—交易关系及副作用。贷款保存资料、付款与分配、计划与修订、分期编号绑定和分项来源。表与列的完整事实在迁移和导出清单中，不在文档再复制一份易漂移的 schema。

用户业务查询、复合外键、唯一键及幂等回执都有用户边界。客户端 uid 不能成为授权依据；原文和 SQL 绑定值不进入普通日志。

写操作在既有用户锁与事务内执行，业务变化和回执共同提交。金额、版本、约束、锁序及读取隔离级别以对应事务入口为准：不要把一致只读快照与持锁后的当前账本检查混为一谈。批量 SQL 分块不等于分批提交。

只读汇总需要同一快照内的内部一致性；导出还将多页绑定到同一数据修订。余额守恒和退款/贷款依赖在写入时再次确认，不信任之前页面或预览中的数值。

## 6. 前端职责

| 层 | 负责的状态与流程 |
| --- | --- |
| 工作台 index | 初始数据、生命周期和 WXML 处理者逐项绑定；没有 enhance 覆盖链 |
| runtime | 页面活动、首次恢复、摘要/主分页协调、共享状态和资源释放 |
| upload/account-review/transaction-review/posting-flow | 各自操作流程，复用既有服务，不维护第二份持久命令 |
| model/presentation | 展示转换，不充当业务账本 |
| import-view-session | 读视图版本、分页和缓存 |
| import-draft-session | 草稿队列、原请求、幂等键、postFlight 和恢复 |
| read-cache / read-policy / read-snapshot-store | 普通查询去重、屏障、失效、有限展示快照 |

页面/登录/批次有效性与列表读取令牌分开。旧读结果可以废弃，已发送的写入仍要按原请求确认；不得用清空缓存或页面卸载当成服务端回滚。

## 7. 版本、预算与验证边界

解析、语义和计划版本看 [domain-versions](../cloudfunctions/catledger-import/src/domain-versions.js)及 profiles；接口看 shared；数据库看 migrations；导出格式看 export-manifest。本文不再列一个可能过时的“当前版本号”。

预算看 [performance-contract](../cloudfunctions/catledger-import/src/performance-contract.js)及真实页面测试。两个独立函数中的 `repayment-booking`、`installment-items` 保持同一领域语义，并由工程检查验证一致性；不为共享而新增跨部署 require。

工程检查验证依赖图、部署边界、平台语义层和页面显式装配；行为测试验证账务与恢复。当前代码是否部署、真机是否通过，均不由本架构图推断。运行方法只维护在[开发与验证](开发与验证.md)。
