# 微信小程序未来规划

> 状态：暂停实施，保留为未来客户端候选
> 原提案：[微信小程序架构设计-20260821-重整前.md](../归档/微信小程序架构设计-20260821-重整前.md)

## 当前结论

微信小程序、CloudBase、云托管、微信登录、备案、流量主广告和完整移动端账单整理都不进入当前产品主线。它们没有被永久关闭，而是等待 Web/PWA 核心闭环经真实用户验证后重新决策。

当前优先级是：

1. 让支付宝、微信账单更新形成稳定价值闭环；
2. 实现结果优先、按需核对和事件级异常隔离；
3. 验证用户是否愿意按月更新并持续查看财务结果；
4. 再决定小程序是否值得成为主客户端。

## 启动条件

满足以下条件后才能进入正式设计：

- Web 核心流程已经由非开发者用户完成并复用；
- 手机选取支付宝、微信账单文件的实际路径验证可行；
- 账号迁移、微信登录绑定和数据托管边界获得确认；
- 部署成本、隐私说明、审核与商业化路线重新评估；
- 小程序不要求重写核心账本或建立第二套后端语义。

## 保留原则

- 现有 Go 模块化单体和三库兼容保持权威；
- CloudBase/微信云托管可以作为部署候选，但不是必选依赖；
- 小程序复用领域模型和 API 语义，不在客户端重新实现会计判断；
- 备份恢复等低频重度操作可继续留在 Web；
- 原提案中的个人主体、广告和技术栈结论不再视为当前已确认决策，重新启动时逐项复核。
