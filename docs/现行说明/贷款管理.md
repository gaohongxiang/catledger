# 贷款管理

## MINI-1914 当前分期流程

2026-09-24 已迁移并发布开发云，手机待验收：一笔分期直接展示完整方案、总成本、连续进度及四列逐期表，采用用户提供的浅绿 loan 布局。第 N 期账单入账且关联或手动确认至 N，前 N 期变灰；缺失来源不自动判逾期。正常分期无登记借还、计划对账、借还记录三个独立入口，点对应期次查看来源、确认进度、补记缺失费用或调整异常；底部为编辑记录信息、删除记录。没有完整分期方案的旧普通借款仍保留原借还维护能力。

银行映射确认信用卡账单及明确期号/分项后，本金只保存分期明细，利息/费用写一次支出。待建来源可从贷款列表及导入完成页进入，新建时带入已知账户/期数/进度，原本金和首期日期等未知信息由用户补齐。已有明确分期编号绑定后，其余期次自动归入；不以金额相似猜分期。手动费用与随后银行账单可以复用；独立银行来源身份、金额冲突进入明确错误处理，不吞并交易。

逐期表首次展示 20 期，底部居中“显示更多”每次向下追加最多 20 期，保留已展开内容，取消页码和前后翻页。追加失败保留原表重试，全部展开后按钮隐藏。所属账户移到详情最上方；保存成功显示短暂轻提示，不在顶部常驻成功卡片。“修改已完成期数”是紧跟“逐期还款”标题、随文字收缩的同排小按钮，用于一次修正连续进度，本身不记费用。

分期进度只改变管理视图，不改变账本本金或余额。来源撤销后回读有效进度，保留手动确认和明确异常。已有旧付款/分配仍可在对应期次查看维护。单期计划变更保存历史修订，来源金额与方案不同就在该行提示。删除记录为归档，来源和正式账目保留。

删除确认明确说明“解除关联，账单和已入账金额保留，可重新关联或新建分期”。归档、来源解除、编号释放和幂等回执在同一事务内完成；有效账单回到待建立分期，可重新建立或关联，金额不重复计入。同一正式费用的手动/导入来源一起重新归属；旧删除请求重放不影响新的关系。0025 修复旧归档残留，失败回退、重试及代码入口见 [入账逻辑说明](../招财猫记账本入账逻辑说明.md)。

数据新增 `0024` 的 `progress_json` / `archived_at` 与用户范围的分期绑定、来源表；导出 schemaVersion=25 包含全部新字段/表。写入与既有可信身份、用户锁、版本及幂等事务一致，费用防重复领域代码在两函数独立打包并检查一致。源代码、验证及发布边界见 [MINI-1914 记录](../../specs/mini-1914-installment-flow/README.md)。下方 MINI-1912 / A～F 保留历史实现说明，当前分期入口与连续进度以本节为准。

## MINI-1912 贷款详情

详情改为贷款信息/进度卡、预计成本/年化卡、逐期还款表。原本金和历史期次通过既有只读试算恢复，后续期次从 loans.periods 分页读取并核对贷款版本，成本是原方案预计值；历史已还与实际对账已还分别计数。未知值或失败不能冒充零。每页 20 行、最多 5 个返回位置；同版本页面内复用，重新读取、身份变化和离开页面遵守原会话屏障。

普通页底部仅显示“编辑资料”“更多操作”。更多里的登记借还负责新建真实借还或关联/更正已有账目，计划与对账负责维护应还和把实际付款分配到期次，借还记录负责查看来源与整组维护。三项仍是已有独立账务流程，并未因为收起按钮而自动对账；来源关联保留直接继续入口。源码 pages/loan-detail，回归 test/loan-detail.test.js；当前开发状态与验证见 specs/mini-1912-loan-detail/README.md。

当前新增入口采用 MINI-1908F 分期表单（pages/loan-form）：名称/分类、关联负债账户、原借款金额、期数、还款方式与依据、首次日期、历史已还、可选优惠/费用。统一分期，不再显示普通借款/消费分期切换。先只读核对，确认剩余本金和基准日后，资料与后续计划一次保存，不增加流水或负债。

历史 N 期由用户明确填写，只保存第 N+1 期起的正额应还任务，保留原期号；不根据日期自动已还、不补历史资金流水。原本金与接入本金分别保存；一次性费用只留原资料，后续计划合计不重复包含。计划页分开显示接入前历史进度和接入后按实际分配结清期数，撤销实际还款不改变历史。新分期可改名称/分类，原参数锁定，具体计划在“还款计划与对账”维护。

0021 installment_setup_json 保存版本化原本金、历史、分类与优惠；升级 CHECK 的费用比较对象为原本金，旧资料仍按原基准比较；既有 NULL 不回填。导出 schemaVersion=21 包含新字段。旧客户端省略扩展字段不会清空。实现/反例见 loan-installment.js、test/installment-entry.test.js、test/ui-all-pages.test.js；验证与发布证据在 specs/mini-1908f-installment-entry。下文 A～D 是兼容旧资料及历史阶段记录，新增入口以 F 为准。

当前 A1/A2a 支持独立列表、详情、资料编辑、实际借还和整组撤销。主入口为“账户管理 → 负债账户”，负债区提供“全部贷款与还款”；现有账本余额和收支仍来自 Account/Transaction。资料不会自动登记借款到账或余额调整。

本金基准表示基准日的日初已确认本金；金额未知时留空并显示待补充，明确零值与未知不同。同一账户多贷款按各自基准核对，不把本金明细重复加入净值。所有资料及游标受服务端可信微信身份隔离。

数据契约及状态见实施规划 19.5；接口 shared/catledger-api.json；新增迁移 0013_loan_metadata.sql。页面保存使用 pending-ledger-write 的原请求核实/重试，详情成功后单独回读；网络错误保留表单，不以缓存余额判成功。

### MINI-1908A2a 实际放款、还款与整组撤销

独立贷款详情新增“登记实际借还”和按需读取的实际记录；仍不修改记一笔、导入或底栏入口。loans.record 的 new 模式要求明确资产账户、发生时间、总额及最多 20 笔贷款各自的当前版本、本金/利息/费用和费用入账情况。未知构成不提交，明确零可以提交，各分项的整数分总和严格等于实际总额。

新放款仅限普通借款：负债转入资产，不计收入；消费分期资料不生成重复消费或借款到账。还款中本金以及已计入负债的利息/费用转账清偿，尚未入账的利息/费用各写一笔现有分类的 expense。100000=80000+18000+2000 时资产减少 100000、本金减少 80000、支出增加 20000；已计费用不二次支出。资料基准与所有活动实际本金变化推导剩余本金，数据库窗口计算验证每个历史时点不出现负值，回溯登记或撤销也不能透支之后的还款。

0014 新增实际批次、逐贷款分配和正式交易关系；用户范围的生成列唯一约束禁止一笔活动正式交易属于两个贷款批次。写入、各贷款版本、正式账目、现金检查及幂等回执共用同一用户锁和事务。loans.reverse 校验整批/全部贷款/全部交易版本；外部复用或退款依赖时阻止，成功后整组软删除新增账目、停用关联、恢复本金并保留撤销历史。活动借还存在时资料接口拒绝直接改基准、日期、类型和账户。普通交易编辑/删除/分类/退款、导入更正/撤销/退款/已有单笔关联均检查活动贷款关系并提示前往贷款管理；两支函数独立打包相同的最小分块保护查询，未跨部署目录 require。

loans.payment 返回最多 20 分配/60 正式账目；loans.payments 按贷款与用户签名游标，每页最多 40，页面只显示当前 20 条。原请求持久化、只读核实、同键重试继续使用 pending-ledger-write；一旦确认成功即锁定结果视图，随后读取失败也不能再次新建付款。全部失败原子回滚，现金不足不能部分扣款。

源码：loan-payment-domain/repository/service.js、loan-transaction-guard.js、pages/loan-payment；真实隔离 MySQL 反例 test/loan-payments.test.js，页面/原请求反例 test/ui-all-pages.test.js。本批实现 new 与 reverse；associate、correctExisting 及贷款整组更正仍由紧接的 A2b 完成，A 保持进行中，未来期次留 B。无云迁移、部署或真实账本写入。

### MINI-1908A2b 已有来源与整组更正

贷款实际借还页可选择“关联已有账目”或“更正已有账目的本息费”，按月分页挑选正式账目（当前页 40、最多选 60）；服务端将导入成员展开为一个经济事件的完整活动组。核对时固定实际账户、时间（含秒、毫秒和原时区）、总额与全部版本，金额相同不自动认为是同笔。关联只在原账目资金方向、负债账户、分类和各分项金额都吻合时成立，不产生第二笔付款。全额转账尚未拆出未计利息费的，必须选择整组更正。

更正先检查净现金与最终本金，再在同一用户锁、MySQL 事务内软删除被替换账目、创建正确分项、保存贷款关联和小回执；保留原经济事件、来源原文及旧关系快照。整组撤销恢复更正前的原交易及来源语义；单纯关联的撤销只解除贷款关系。更正记录保留旧付款（已撤销）与新付款的关系，资金账户保持一次实际总额。

手工登记之后才导入同一笔时，可从原付款选择“与后来导入的同笔还款核对”，明确选择新导入完整组后去掉重复付款。已关联贷款的历史来源再次出现，整理及入账禁止另挂单个历史成员（LOAN_TRANSACTION_LOCKED），保留待核对原始文件，不再次扣款；也不会制造阻断原贷款更正/撤销的外部半组引用。跨来源组、已有退款或外部复用保留证据并拒绝不安全更正。旧导入页及记账页布局、导航未动。

接口：loans.source / record / correct / reverse；迁移 0015 只新增三张用户范围审计关系表，未执行云迁移。来源解析在 loan-source.js，写入和维护在 loan-payment-write/maintenance.js；真实隔离反例在 test/loan-sources.test.js，页面来源/秒与时区/迟到响应/确认后读失败在 test/ui-all-pages.test.js。A2a 中未完成的关联与更正由本节替代；未来期次仍属 B。

### MINI-1908B 确认期次和实际对账

贷款详情进入“还款计划与对账”；实际还款记录按所属贷款进入期次分配。计划记录明确期号（1～9999，贷款内唯一）、到期日、应还本金/利息/费用。创建或修改计划不写 Transaction，不改变资产、负债余额或统计支出。金额必须明确填写，允许零但合计须为正；旧计划修订单独保留，有付款的期次不能取消或把任一分项改小到已付以下。

一次还款可以部分分配或跨期分配，每个贷款最多 40 期。每个分项分别受实际付款该贷款份额与期次剩余约束，本金不能补贴超出的利息；未分配本金/利息/费用明确列出。替换分配停用旧行并保存新行，付款、贷款和涉及期次版本同事务维护，余额和支出不变。来自其他贷款、其他用户或旧版本的分配拒绝，失败全部回滚。

已付/部分支付从活动付款与活动期次分配计算，日期到期不自动已付；列表展示下一到期日、确认计划未付金额，以及计划本金与实际剩余本金的差额，缺基准时差额仍未知。整组更正或撤销会停用原期次分配并递增涉及期次版本；新更正付款需重新对账，旧分配及计划修订仍可分页核对。提前还款登记明确实际本息费后，手动修订未付计划，不预测银行结清金额。

0016 为期次、修订、实际分配三张新表，用户范围外键分别锚定贷款和付款贷款份额；未迁移云数据库。API 见 shared/catledger-api.json 的 periods/savePeriod/planAllocation/allocatePeriods/periodHistory；loan-period-service/repository.js 负责规则，页面 loan-plan 复用原请求恢复和会话屏障。列表及历史最多 40，页面当前 20；最多 40 选择，跨 20 贷款撤销最多 800 引用、每 100 ID 更新。真实数据库与边界反例 test/loan-periods.test.js，页面丢响应/读取失败/分项不足见 ui-all-pages。原记账/导入/底栏入口保持原样。

### MINI-1908C 账单关联入口

loans.transaction/loans.unassigned 提供只读查询，loans.list 支持账户过滤。无活动贷款关联的资产→信用账户（credit）转账按信用卡整单还款处理：详情不显示贷款关联或新建分期入口，不进入待关联还款列表，全局筛选器也不列信用账户；旧客户端用信用账户筛选仍可读取，但结果为空。资产→其他负债（other_liability）也保持普通转账；只有入账时明确确认实际本息费并暂不关联的还款才进入待办。所有过滤在数据库分页前执行，不改变账目、余额或统计。

已有活动贷款关联和更正替换关系优先读取，信用账户历史记录仍显示整组本息费、实际期次及借还/计划入口。撤销关联后，信用账户还款恢复为普通转账，不回到候选列表；其他负债的普通转账同样不自动恢复待办。信用卡分期资料应根据银行账单或明确分期明细单独核对，不能从支付宝/微信的整单支付推断。本轮未新增银行账单解析，也不回写已有关系。

关联页保留所选交易ID，按目标负债账户筛选贷款；补充普通借款或分期资料后继续关联同笔实际还款。实际借还页自动读取完整来源并固定为已有账目模式，不允许切回 new。来源中的显式期次及本息费字段与商品/备注限量展示、仅供核对，缺失项不推断。分期类型由用户选择；旧更正原交易可定位当前活动付款，撤销后关联重读。

源码：repayment-query-service.js、repayment-evidence.js、pages/loan-link、transaction-editor/loan-context.js、loan-payment/source.js。接口见 shared/catledger-api.json，设计与当前验证状态仅以实施规划19.13为准；数据库结构、写入模式和幂等规则不变。反例：test/repayment-link-query.test.js、test/repayment-link-ui.test.js。

### MINI-1908D 分期参数与计划生成

贷款资料可选填分期参数：scheduleMethod（flat 等本等息／equal_payment 等额本息／equal_principal 等额本金／interest_only 先息后本）、scheduleTerms（总期数 1～600）、measurementKind（rate 按利率／repayment 按每期还款额）、quoteType（annual／monthly／daily 360 天口径／installment 每期费率，仅限 flat）、ratePpm（利率 ×10⁶）、repaymentMinor（按还款额时的每期或首期应还，整数分）、feePerTermMinor（每期费用）、feeUpfrontMinor（一次性费用，只作资料与试算汇总）和 firstPaymentDate（首次还款日）。参数全有全无，随 loans.create/loans.update 保存；修改参数不影响既有期次。loans.update 整组覆盖分期参数：编辑时分期区回填已存参数，全部留空后保存即整组清空（费率、还款额、费用与首次还款日一并清除）。

loan-detail 表单新增“分期参数（选填）”区，保存成功后可到还款计划页生成期次。loan-plan 在贷款无任何期次且参数齐备时显示“按参数生成还款计划”入口：先 loans.previewPlan 只读展示逐期本金/利息/费用与汇总（不落库），用户确认后 loans.generatePlan 在同一用户锁事务内批量写入期次及修订快照并递增贷款版本；已有任何期次（含已取消）时入口不显示，服务端以 LOAN_PLAN_EXISTS 拒绝。

生成的期次与手工录入完全等价：不产生 Transaction、不改变余额或收支统计，逐期修订、部分/跨期分配、更正／撤销和修订历史沿用既有 B 批机制；期次状态不按到期日自动已还，未分配金额保持待对账。不推算银行最终结清金额，提前还款后的未付计划仍手动修订。普通信用卡还款不强制建分期不变。

### MINI-1908E 明确还款与暂缓关联

手动“记一笔”的其他负债转账可进入“这是借款还款，确认本息费”；导入整理的单笔资金流转详情可设置普通转账/借款还款。银行账单解析仍未接入。普通转账默认不建贷款待办，信用账户整单还款不提供贷款分项确认。

实际还款必须填写本金、利息、费用（没有填 0，未知不能提交），本次计支出或已计负债及对应支出分类；合计等于实际付款。可关联已有贷款，或明确暂不关联。导入本息费待核对通过 mode=review 保留阻塞，不能用“暂不关联”绕过财务核对。

0020 仅新增确认明细表；复用 loan_payments / loan_payment_transactions 保存实际付款及完整财务分组。pending 是 active、存在确认明细且没有贷款分配；不从交易方向扫描、不回填旧转账。loans.list 返回真实待办数量，首页仅 count>0 显示入口；unassigned 按完整付款分组分页，总额是整组实际付款。明确确认但尚未关联的分项仍受整组维护保护。

loans.bookRepayment 与 financeUpdates.post 把资金流水、确认明细和可选贷款分配放在同一用户锁事务中；按借款本金基线/日期和全部历史时点核对本金，失败全部回滚。loans.assignRepayment 只分配已确认构成并递增付款/贷款版本，不再写流水。不再关联贷款（releaseRepayment）只解除待办确认并保留原财务流水；已有分配仍由原更正/撤销接口整组维护。

原始导入字段不变，决定存在事件 field_sources_json；时间、账户、金额后续变动造成不匹配则重新待核对。入账后 source 保存原事件和关系快照；重试沿用冻结请求，冲突不降级为暂不关联。用户隔离、数据导出和最小运行角色覆盖新增表。

## MINI-1909L 账户内入口与读取边界

账户详情延续原底部详情面板；负债账户按需调用 loans.list(accountId, pageSize=3) 展示贷款与分期，更多记录或待办进入带 accountId 的独立列表。列表标题显示当前账户，待关联还款首个请求即固定同一账户；全局入口仍支持跨账户查询。loans.list 的 pendingRepaymentCount 同步应用账户条件，与列表及 dataRevision 共用只读一致性快照。无新表、无资料迁移。

新增表单接受账户上下文，目录确认前不能保存，选定账户固定；停用账户仅查历史。保存沿用 pending-ledger-write，刷新失败不生成第二次写入。返回账户详情重读贷款快照，列表返回时失效则回到第一页；迟到旧账户/旧会话结果不回填。资产账户只增加本月流水入口，负债账户额外提供贷款；普通信用卡欠款无需建立贷款明细。

账户流水使用带会话标记的一次性导航意图，进入 tab 时先初始化会话，再设置账户与本月条件，覆盖旧搜索/来源/日期条件并使旧请求失效；目录失败、缺失或停用均不放宽账户过滤。原始资金流水、余额、还款计划、关联更正撤销不变。源码入口：pages/accounts、loans、loan-form、loan-link、transactions、profile；服务端 loan-service.js；验证入口 test/account-loans-ui.test.js、test/account-loans.test.js 及原贷款账务回归。
