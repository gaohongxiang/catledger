# 贷款与分期：费用、付款与进度

> 本文描述 docs 分支实现；2026-09-26经用户追加授权完成0026及双函数云部署，原生真实会话只读验证通过，小程序尚未上传或完成真机验收。完整规则和 L01～L18 条件保留在[既有方案](../贷款与分期改造方案.md)，阶段与验证证据只看[实施规划](../招财猫记账本实施规划.md)。连贯业务流程见[主逻辑第6节](../招财猫记账本入账逻辑说明.md#loans)。

## 1. 建立方案与历史接入

创建保存资料、计划与明确来源，不直接记全期利息或自动放款。已记消费转分期保留原消费；现金借款可从零本金建立资料，有真实到账才登记负债到资产转账。新消费需按真实凭据另记一次；历史接入确认当前本金基准，不补造放款。

本金基准、账户欠款与费用起算日各有含义。剩余本金来自基准和真实本金变动，不与账户负债再相加；人工进度只能提供另标的计划估算。计算继续使用既有整数分和舍入规则；保存过的逐期分项优先于计划推算，已记费用不会被重算覆盖。

旧贷款没有默认授权。详情可以选择不补历史，从确认范围继续；可以认领已记同费、标明期初已含历史费用，或用一笔真实一次性收费覆盖明确多期。覆盖绑定当前用户、负债账户、金额与收费项，模糊归属不自动合并。一次性手续费有独立计费日。

## 2. 稳定收费身份与授权

迁移0026新增合同、收费、来源、清偿分配和只追加审计五张表。收费唯一键为 `(uid, contract_id, charge_key)`；`period:N:interest/fee`、`upfront:fee`、明确一次实收和独立追加项各有稳定身份。金额、方案版本、请求号和管理 loanId 不决定费用是否是新的一笔。

`loans.chargePlan` 只读展示费用、历史候选、待核对实单和授权预览。每页最多40项，游标绑定用户、贷款、数据修订、期次及配置；预览区分已有覆盖、范围外、未来和本次到期缺项，显示本次金额。执行时仍逐项核验覆盖。

`configureCharges` 在用户锁内确认起源、固定分项、计费日、负债账户、分类、起止与历史处理方式，保存授权及审计，不写正式支出。自动授权和仅本次确认分开；暂停保留已记历史。归档会暂停授权；重建必须认领旧合同，不能用新 loanId 再收费。

## 3. 无文件记费与恢复

用户进入或刷新首页、统计、明细、贷款/详情，以及完成导入时，共用一个[同步协调器](../../miniprogram/services/loan-charge-sync.js)。先纯读 `dueCharges`，再明确调用 `syncCharges`，成功后读取摘要。普通读取、缓存校验和导出不隐式写账。

服务端按上海业务日和授权范围找未记缺项，每批最多40项，客户端一次前台最多3批。费用归属原计费月；只增加支出与负债，标“方案来源未核对”，不扣银行卡、不还本金、不生成付款。未到日期、已覆盖、已抑制、已暂停/取消、停用账户/分类不会写入；一次确认仅处理指定合同。没有离线后台定时承诺。

费用交易、收费状态、版本、数据修订、审计和回执在原用户锁内共同提交，数据库唯一键兜底并发。待发请求先持久化，响应丢失沿用原键核实；批次已成功不重做，后批失败保留未完成提示。隐藏/切后台/换用户停止后续批次，旧结果不能回填。写成功而摘要失败保留成功状态。

## 4. 银行实单核对与实际付款

明确账户、编号、期次和分项的同费实单优先查费用身份：同额补来源，期初覆盖仅补证据；20元方案遇18元实单需签名预览并确认净调-2，不再额外记18。不同银行身份的独立追加费须明确确认，不能按同额吞掉。只有出账/应还本金行不能证明资金支付；真实放款和扣款不套用本金省略规则。

已记费用清偿必须引用对应收费或有效实际费用证据，并受未清偿容量约束；单独的 `accrued` 标志不成立。付款520、本金500、已记利息20时只转账520，费用不重记；尚未记息则转账500并记资产端费用20，登记收费身份防止后续补费。已有整组付款优先复用；部分、跨期付款继续沿用实际分配。

信用卡整单还款是已发生转账，只有明确选择才能归入分期。各贷款本金/利息/费用加未分配余额严格等于总额；同一真实付款不能再次整额挂接。暂不清楚归属不会改写银行转账事实。明确还款待办继续保留其既有来源与账户边界。

## 5. 统一详情与进度

详情保持一张逐期还款表。表头仅显示费用净额/待核对摘要和“管理”入口；点某一期查看本期利息、费用与待核对账单，点费用再选择调整方式，返回仍在该期。实际一次性收费按非期次范围单列，不混进某一期；费用与来源有界翻页。

自动记费授权、历史覆盖、暂停、提前结清和批量进度统一收在“管理”中。主页面没有单独的“记录实际借还”按钮；打开某一期后用“记本期还款”，金额与明确费用依据带入未提交草稿，保存或关联已有扣款时，在同一事务中完成该期的真实付款关联。部分还款只更新实际已付金额，不补成全期；账单已有扣款可关联，不能重复登记。

“仅确认本期已还”收在本期调整中，仍只改进度。实际已付/部分付款优先于旧人工状态展示，人工标记保留，撤销真实付款后按原依据显示。借款到账和跨期/整单还款收在管理中；消费转分期不出现借款到账入口。批量操作另有范围确认；输入/失败草稿保留，关闭页面、切换期次或调整方式后，迟到响应不能覆盖新状态。

出账最大期号不再推进已还。单期完成只写该期；“已还至N期”必须明确批量确认，保留未还、部分未还和范围外单期确认。schema2 保留旧 through 待核对记录，明确历史确认与实际付款分别显示，不伪造银行流水。仅资料缺失显示还款待确认；明确未还且过到期日才称逾期。

## 6. 维护、退费与终止

普通交易编辑、改分类、单笔/混选删除不能绕过收费关系。详情的调费、抑制和恢复先取 `chargeImpact`，执行重验收费/交易/贷款版本、付款、退款、来源及一次实收的覆盖子项。费用删除留抑制；明确恢复才允许再次补记，旧请求只返回原回执。

撤销后到银行补证来源保留原方案费用，并在无有效实单后恢复方案未核对依据。一次性费用覆盖多期时不能直接删掉父费用。已付费用禁止普通调减/删除，真实退费是独立退款，显示净额与不低于零的未清偿额。减免、利率改变、提前结清和终止暂停/取消未来项，不伪造退款；商品退款不自动还贷款。

授权与费用全部纳入完整导出、版本失效和最小权限。紧急暂停新同步可使用 `CATLEDGER_LOAN_SYNC_DISABLED=1`，原成功回执与历史关系保护保留；发布顺序和数据不倒迁原则见[迁移说明](../../migrations/README.md#0026-贷款费用生命周期)。
