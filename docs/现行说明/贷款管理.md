# 贷款与分期：费用、付款与进度

> 本文描述当前代码的逐期实现；部署与真机验收状态以实施规划为准。完整规则和 L01～L18 条件保留在[既有方案](../贷款与分期改造方案.md)，阶段与验证证据只看[实施规划](../招财猫记账本实施规划.md)。连贯业务流程见[主逻辑第6节](../招财猫记账本入账逻辑说明.md#loans)。

## 1. 逐期操作

首次从第6期账单建立分期时，来源直接关联第6期。填写原本金、总期数和每期金额后，在原预览表第1～6期各行勾选已还，默认勾选、可逐期取消；不另列一份期次。保存创建就是一次提交，无第二个授权或确认弹窗。预览覆盖全部可勾选期次，包括超过24期的历史范围。服务端在同一事务保存方案、关联来源、补记缺失费用和已还选择。空白/未知金额仍必须补全，不能按0保存。

以后导入第8期，在原逐期表尚未选择的期次行（包含漏掉的第7期）“还款”列显示勾选项，默认已还，可改。已选未还、部分实付及实际已还不会被后期账单覆盖。历史已还选择覆盖全部期次，不在第20期截断。详情一次读取带版本的紧凑完整快照，在原表展示全部期次；校验行数、期号和版本后才允许保存。旧服务分页兼容保留，跨页失败、快照不完整或版本变化都不能提交半份选择，重试/刷新保留用户草稿；只读和迁移不会自动补历史账目。

没有后续账单时，点逐期列表该行“记本期还款”，直接进入新增还款草稿，已带入未付金额；选实际付款账户、日期和金额后一次保存，不再显示“这笔钱记过了吗”的选择。本金/利息/费用明细可展开修改，日常不再要求选择费用处理方式或授权。付款账户沿用上次同笔贷款的有效付款账户；未明确时由用户选择。已有账目的关联或更正从原账目入口处理；已记付款在对应期次查看，不设独立记录页签。

## 2. 费用账户与历史余额

费用默认归属该分期绑定的信用卡或其他负债账户，即导入时明确选择的账本账户，不能把文件所属平台当作付款银行卡。实际新还款从用户选定的资产账户扣总额，转入贷款账户；缺失本期息费先记在贷款账户，同一事务完成本金与期次关联。已有息费只清偿一次。

历史“已还”补记按原期次日期计支出；每笔新费用对应一笔同额、同账户的余额保全记录。两者通过0027的 `balance_adjustment_id` 关联，所以当前资产、负债和净资产都不改变，过去月份收支获得缺失的费用。已有明确同费交易直接复用，不再补一份费用或余额调整。历史补记的费用不能再当作待付款费用分配。

每次确认在既有进度与审计中保存当时本金金额、贷款/期次版本。首次确认扣减本金基准，撤回始终加回原确认金额；计划上调或下调不会改写历史。所有基准变动校验实际借还的完整时间线。这一校正不改变账户余额。明确后补同一期真实凭证时，保存被替换的历史本金与费用份额；撤销凭证恢复历史覆盖，不重复增减。未知旧确认保留状态并提示待核对，读取不猜金额。费用历史清偿独立于余额保全保存；已有费用确认已还只补清偿依据。调费同步历史覆盖，退款只扣一次净额；撤回遇实际付款或新补费用的银行来源/退款依赖时拒绝拆散关系。

## 3. 防重、事务与旧功能兼容

收费唯一键仍为 `(uid, contract_id, charge_key)`，不随金额、请求号、方案版本或管理ID变化。已有明确编号且旧管理记录已归档时沿用原收费合同；无明确身份不猜旧合同。来源、费用、付款和审计各自保留；不同流水即使同额也不能被吞并。

`loans.confirmInstallments` 一次接收具体期次及 paid 选择，写入进度、缺失费用、余额保全、审计、版本和回执；所有写入在可信用户锁和同一事务内。真实付款/部分付款不能被人工选择覆盖；未勾选期次保持未还。默认复选框、切页、读取、导出和迁移都不写账。网络结果未知时查原回执，不用新请求重复扣款。

旧 `configureCharges`、`syncCharges` 及历史数据保持兼容；仅改进度入口对已接入逐期流程的贷款明确拒绝，需使用同一确认规则，原 L01～L18 保护继续回归。普通界面不再提供新建自动授权；此前启用的自动记费可在列表底部停止，保存新流程选择也会停止该设置。后台同步只处理既有授权，不自动给旧贷款开启。停止不会删除已有账目。

## 4. 后导入与特殊费用

后到同一期同分项账单只核对已记费用：金额一致复用交易，差额需先看调整影响再保存；不同独立收费需明确区别。没有现成收费项的新一期按原导入原子流程记一次，随后在逐期表询问还款情况。账单读取不会自动勾成已还。

计划有一次性手续费时，详情“一次性费用 → 处理已发生的一次性手续费”可补记实际费用或认领已有支出；明确实际日期和账户，尚未发生时不保存。记在贷款账户表示计入负债，资产账户表示已实际支付。已有支出保持身份和余额；首期历史或实际还款均不会再记这笔一次性费。可填写覆盖起止期次，守恒合计后只记一次实收；资产已付的覆盖分摊不再作为逐期待付款。已有信用卡还款的路径为“账目详情 → 分配到分期 → 选择分期 → 输入期号、使用该期金额 → 核对本息费和未分配额 → 保存”。支持多笔分期，各份额与未分配额等于原转账；已有利息原位认领。已关联账目进入原整组更正，保持原转账身份，撤销只解除分配。费用及来源仍有界翻页，账户/分类停用、身份冲突及被删除/暂停的费用均受保护。

## 5. 页面与恢复

主页面只有一张逐期还款表，每一期只出现一行。待选择历史已还的期次在“还款”列直接勾选，页面底部固定条汇总待确认与已选期数并给出一次保存入口；勾选与初始值不同的期次标记“待保存”，离开页面前提醒尚未保存；点击勾选不打开期次详情。其余未完成期直接显示“记本期还款”，已还显示“已还”并可打开该期详情。主卡统一展示借款本金与实际已记利息及费用；不用预计成本冒充实际金额，不出现“尚未授权”“历史费用尚未核对”。历史旧进度通过可修改的已还选择补记，不能只改成已记金额。

编辑、删除直接放在逐期列表最下方，不设管理按钮或弹层；只有旧自动设置生效时才另显停止入口。期内调整可以补记本期已还或改回未还；真实已付请从对应付款更正/撤销。金额/日期计划调整在编辑资料中，差异与退款从具体费用进入。关闭、切期、换用户的迟到响应不能回填；失败保留草稿和原请求，读取最新版本后再处理冲突。

## 6. 维护、退费与终止

普通交易编辑、改分类、单笔/混选删除不能绕过收费关系。详情的调费、抑制和恢复先取 `chargeImpact`，执行重验收费/交易/贷款版本、付款、退款、来源及一次实收的覆盖子项。用户单独删除费用留抑制；明确恢复才允许再次补记，旧请求只返回原回执。

撤销后到银行补证来源保留原方案费用，并在无有效实单后恢复方案未核对依据。一次性费用覆盖多期时，单项维护不能直接删掉父费用；整组删除按完整范围处理。已付费用禁止普通调减/删除，真实退费是独立退款，显示净额与不低于零的未清偿额。减免、利率改变、提前结清和终止暂停/取消未来项，不伪造退款；商品退款不自动还贷款。

整笔计划删除另用 `loans.deleteImpact/delete`，先显示实际撤销数量与保留范围，再一次确认。最初由该计划新增且仍独占、没有有效银行来源认领的账撤销；历史费用与余额保全成对处理，父收费只撤销一次。原有手工／导入账目、银行已认领账及其必要配套记录保留，已更正账保持当前正确分项。共享付款、独立退款、关系失配或旧创建证据不足时整次阻止，页面给出原业务入口。详情的逐期修改、单项收费维护和旧 `archiveInstallment` 归档语义保持独立。

原创建归属在交易新增时保存，后续认领／改绑不覆盖；旧交易依原始付款、被替换原账、创建回执、导入创建链接与费用审计核实，缺证据不猜删。删除在同一用户锁和回执事务里解除有效付款、期次和来源，停用旧授权，并保存必要历史。已删除 loanId 不能写入或恢复；重放旧请求不影响后来的新关系。

重建使用新ID，以可靠编号或用户明确选择的旧合同复用费用。随整组撤销的费用有专属失效标记，可通过新操作再次入账；单独抑制／取消的项保持停止。保留费用可从账目详情查看、调费或登记实际退款，也可“关联到新计划”。保留付款仍可在新计划选择已有账目，按删除快照展开完整原组；本金与费用覆盖只替换一次，不重复记钱。没有可证明的身份和原组时由用户补充资料。删除成功后只读刷新失败明确显示“已删除，列表待刷新”。

授权与费用全部纳入完整导出、版本失效和最小权限。紧急暂停新同步可使用 `CATLEDGER_LOAN_SYNC_DISABLED=1`，原成功回执与历史关系保护保留；发布顺序和数据不倒迁原则见[迁移说明](../../migrations/README.md#0026-贷款费用生命周期)。
