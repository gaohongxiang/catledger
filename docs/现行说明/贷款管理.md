# 贷款与分期：现有实现接缝与改造边界

> 连贯阅读见[主逻辑第 6 节](../招财猫记账本入账逻辑说明.md#loans)；确定的新规则、漏月场景、数据约束和实施验收统一在[改造方案](../贷款与分期改造方案.md)。本专题说明代码基线 `b804bfc4` 的实际能力和待改接缝，不再把旧“有后期来源即连续已还”当作目标规则。

## 1. 当前已有能力

| 意图 | 基线实现 | 账务影响 |
| --- | --- | --- |
| 建立贷款/分期资料 | loan-service 保存资料、生成计划、可关联 sourceItemId | 不默认记全期利息或再次放款 |
| 真实借还 | 明确本金/利息/费用及账户、时间 | 新建或复用真实交易，分项守恒 |
| 已有账目关联/更正 | 展开完整交易组，关联或受保护替换 | 不重复扣款，保留关系审计 |
| 旧贷款期次分配 | 支持部分/跨期实际分配 | 不改变已有真实资金流水 |
| 信用卡分期来源 | 期号/分项/真实信用账户校验、编号归属和费用复用 | 本金不重记，费用按当前实际处理 |
| 人工进度与手动补费 | progress 与 installment_items | 进度不造流水，明确补费才新增费用 |

普通信用卡整单还款目前是资产到信用账户的转账，不自动成为贷款待办；其他负债普通转账也不凭方向扫描产生待办。明确本息费并暂缓贷款归属才进入相应待办。目标扩大关联能力时不得破坏已有来源和整组保护。

## 2. 可以复用的账务边界

本金基准表示已确认时点本金，未知不同于零；贷款明细不与账户负债再次相加。剩余本金要核对所有实际历史时点，不能今天足够就允许过去透支。

还款总额必须等于本金、利息与费用。repayment-booking 区分此前未记费用的 expense 与已计负债的 accrued，后者随转账清偿；新自动记费必须补上可追溯的覆盖关系，而不是只让用户填 accrued 标记。

已有来源固定账户、时间、总额及完整组版本；构成匹配才纯关联，不匹配走预览和整组更正。更正/撤销保留旧组、来源与修订，并检查外部退款、贷款关系、现金、本金和用户隔离。普通明细编辑/删除不能绕开这些保护。

只读计划计算复用既有等本等息、等额本息、等额本金、先息后本及整数分舍入。完整计划与实际交易分开，未知结清额不猜。新费用授权的计费日、生效范围和历史覆盖需要独立明确，不能把还款日直接当实际计费凭据。

## 3. 必须改变的三个接缝

**费用：** 基线没有按授权方案自动到期记费/漏月补齐。新增正式费用前必须先完成收费身份、覆盖、授权、账务端点和删除抑制；复用 installment_items 等现有关系，必要的表/字段在 A0 冻结。后导入实单只关联或确认净差，不再额外记一份。

**证据：** 现有本金特例依赖信用账单、credit 账户及期次分项，新目标必须区分已有消费转分期与现金借款/新消费。只收到应还本息行不能据此生成已付款，更不能通过本金省略规则漏掉真实借入或新消费。

**进度：** installment-view 将有效来源最大期号并入 through，且单期 completed 会扩大连续 through。这只是旧代码行为；目标不再接受。改为单期确认只该期、批量确认显式范围、真实分配独立依据；旧来源推算作为旧规则待核对保留，不清除真正的人工确认/实际付款，也不把资料缺失直接标逾期。

## 4. 无文件的正常流程

用户确认固定方案和自动记费授权后，专用幂等命令在使用时补齐到当前业务日。费用归属各原计费月，并标“方案来源未核对”；只有费用和负债变化，不自动扣银行卡。

无授权只做缺项预览，一次确认可处理多个漏月。用户不补历史就从确认起算范围继续，基准前不造流水；已有费用、期初欠款覆盖先核对，不能再增一份负债。没有明确贷款归属但费用/付款事实充分，可以先保存真实记录待关联。

归档停止后续记费但保留既有账目和收费覆盖；删除方案费用必须留抑制，重新建立不能重记。提前结清取消未来计划不伪造退款，真实退费才调整。详细规则和边界不在本专题重复，见[统一方案](../贷款与分期改造方案.md#rules)。
