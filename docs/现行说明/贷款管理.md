# 贷款管理

当前 A1/A2a 支持独立列表、详情、资料编辑、实际借还和整组撤销。入口为“我的”分类管理后的“贷款管理”；现有账本余额和收支仍来自 Account/Transaction。资料不会自动登记借款到账或余额调整。

本金基准表示基准日的日初已确认本金；金额未知时留空并显示待补充，明确零值与未知不同。同一账户多贷款按各自基准核对，不把本金明细重复加入净值。所有资料及游标受服务端可信微信身份隔离。

数据契约及状态见实施规划 19.5；接口 shared/catledger-api.json；新增迁移 0013_loan_metadata.sql。页面保存使用 pending-ledger-write 的原请求核实/重试，详情成功后单独回读；网络错误保留表单，不以缓存余额判成功。

本阶段源码入口：catledger-api/src/loan-service.js、loan-domain.js；miniprogram/pages/loans、loan-detail。行为验证：test/loans.test.js、test/ui-all-pages.test.js。已有交易关联/更正与还款计划由后续 A2b/B 实现。

A1 本机验证：650 项全回归通过，0 失败/跳过；语法/配置/契约通过，两支生产依赖审计 0。未做云迁移/部署/真实账本操作。原生验收在实际借还、计划和生命周期批次稳定后统一补齐。


### MINI-1908A2a 实际放款、还款与整组撤销

独立贷款详情新增“登记实际借还”和按需读取的实际记录；仍不修改记一笔、导入或底栏入口。loans.record 的 new 模式要求明确资产账户、发生时间、总额及最多 20 笔贷款各自的当前版本、本金/利息/费用和费用入账情况。未知构成不提交，明确零可以提交，各分项的整数分总和严格等于实际总额。

新放款仅限普通借款：负债转入资产，不计收入；消费分期资料不生成重复消费或借款到账。还款中本金以及已计入负债的利息/费用转账清偿，尚未入账的利息/费用各写一笔现有分类的 expense。100000=80000+18000+2000 时资产减少 100000、本金减少 80000、支出增加 20000；已计费用不二次支出。资料基准与所有活动实际本金变化推导剩余本金，数据库窗口计算验证每个历史时点不出现负值，回溯登记或撤销也不能透支之后的还款。

0014 新增实际批次、逐贷款分配和正式交易关系；用户范围的生成列唯一约束禁止一笔活动正式交易属于两个贷款批次。写入、各贷款版本、正式账目、现金检查及幂等回执共用同一用户锁和事务。loans.reverse 校验整批/全部贷款/全部交易版本；外部复用或退款依赖时阻止，成功后整组软删除新增账目、停用关联、恢复本金并保留撤销历史。活动借还存在时资料接口拒绝直接改基准、日期、类型和账户。普通交易编辑/删除/分类/退款、导入更正/撤销/退款/已有单笔关联均检查活动贷款关系并提示前往贷款管理；两支函数独立打包相同的最小分块保护查询，未跨部署目录 require。

loans.payment 返回最多 20 分配/60 正式账目；loans.payments 按贷款与用户签名游标，每页最多 40，页面只显示当前 20 条。原请求持久化、只读核实、同键重试继续使用 pending-ledger-write；一旦确认成功即锁定结果视图，随后读取失败也不能再次新建付款。全部失败原子回滚，现金不足不能部分扣款。

源码：loan-payment-domain/repository/service.js、loan-transaction-guard.js、pages/loan-payment；真实隔离 MySQL 反例 test/loan-payments.test.js，页面/原请求反例 test/ui-all-pages.test.js。本批实现 new 与 reverse；associate、correctExisting 及贷款整组更正仍由紧接的 A2b 完成，A 保持进行中，未来期次留 B。无云迁移、部署或真实账本写入。
