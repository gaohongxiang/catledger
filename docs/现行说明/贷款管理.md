# 贷款与分期：费用、付款与进度

> 本文描述 docs 分支的逐期实现；部署与真机验收状态以实施规划为准。完整规则和 L01～L18 条件保留在[既有方案](../贷款与分期改造方案.md)，阶段与验证证据只看[实施规划](../招财猫记账本实施规划.md)。连贯业务流程见[主逻辑第6节](../招财猫记账本入账逻辑说明.md#loans)。

## 1. 逐期操作

首次从第6期账单建立分期时，来源直接关联第6期。填写原本金、总期数和每期金额后，在原预览表第1～6期各行勾选已还，默认勾选、可逐期取消；不另列一份期次。保存创建就是一次提交，无第二个授权或确认弹窗。预览覆盖全部可勾选期次，包括超过24期的历史范围。服务端在同一事务保存方案、关联来源、补记缺失费用和已还选择。空白/未知金额仍必须补全，不能按0保存。

以后导入第8期，在原逐期表尚未选择的期次行（包含漏掉的第7期）“还款”列显示勾选项，默认已还，可改。已选未还、部分实付及实际已还不会被后期账单覆盖。旧历史进度每批最多20项，同样放在原表对应行；下一批可从表底“显示更多”继续查看。保存只提交已展示的选择，翻页保留草稿，不把未展示项误当未还；只读和迁移不会自动补历史账目。

没有后续账单时，点逐期列表该行“记本期还款”，直接进入已带入未付金额的草稿；选实际付款账户、日期和金额后一次保存。本金/利息/费用明细可展开修改，日常不再要求选择费用处理方式或授权。付款账户沿用上次同笔贷款的有效付款账户；未明确时由用户选择。已记付款在对应期次查看，不设独立记录页签。

## 2. 费用账户与历史余额

费用默认归属该分期绑定的信用卡或其他负债账户，即导入时明确选择的账本账户，不能把文件所属平台当作付款银行卡。实际新还款从用户选定的资产账户扣总额，转入贷款账户；缺失本期息费先记在贷款账户，同一事务完成本金与期次关联。已有息费只清偿一次。

历史“已还”补记按原期次日期计支出；每笔新费用对应一笔同额、同账户的余额保全记录。两者通过0027的 `balance_adjustment_id` 关联，所以当前资产、负债和净资产都不改变，过去月份收支获得缺失的费用。已有明确同费交易直接复用，不再补一份费用或余额调整。历史补记的费用不能再当作待付款费用分配。

新流程的本金基准在创建时扣除已选期次本金；后续选择改变时，同步增减已确认本金基准中的对应本金，使将来实际还款不因旧基准被误判超还；这一校正不改变账户余额。实际付款继续扣减本金且不会重复扣已确认历史。费用调整与撤回同时维护成对记录，有实际付款、退款或来源依赖时受原保护约束。

## 3. 防重、事务与旧功能兼容

收费唯一键仍为 `(uid, contract_id, charge_key)`，不随金额、请求号、方案版本或管理ID变化。已有明确编号且旧管理记录已归档时沿用原收费合同；无明确身份不猜旧合同。来源、费用、付款和审计各自保留；不同流水即使同额也不能被吞并。

`loans.confirmInstallments` 一次接收具体期次及 paid 选择，写入进度、缺失费用、余额保全、审计、版本和回执；所有写入在可信用户锁和同一事务内。真实付款/部分付款不能被人工选择覆盖；未勾选期次保持未还。默认复选框、切页、读取、导出和迁移都不写账。网络结果未知时查原回执，不用新请求重复扣款。

旧 `configureCharges`、`syncCharges`、仅改进度接口及历史数据保持兼容，原 L01～L18 保护继续回归。普通界面不再提供新建自动授权；此前启用的自动记费可在管理中停止，保存新流程选择也会停止该设置。后台同步只处理既有授权，不自动给旧贷款开启。停止不会删除已有账目。

## 4. 后导入与特殊费用

后到同一期同分项账单只核对已记费用：金额一致复用交易，差额需先看调整影响再保存；不同独立收费需明确区别。没有现成收费项的新一期按原导入原子流程记一次，随后在逐期表询问还款情况。账单读取不会自动勾成已还。

实际一次性费用覆盖多期时，分摊不重复记费；首期历史补记中的一次性手续费只记一次。已知真实付款可使用已有账目，信用卡整单付款按明确份额关联，各贷款份额和未分配余额等于原总额。费用及来源仍有界翻页，账户/分类停用、身份冲突及被删除/暂停的费用均受保护。

## 5. 页面与恢复

主页面只有一张逐期还款表，每一期只出现一行。待选择历史已还的期次在“还款”列直接勾选，表头出现一次保存入口；点击勾选不打开期次详情。其余未完成期直接显示“记本期还款”，已还显示“已还”。表头显示实际已记费用，不用预计成本冒充实际金额，不出现“尚未授权”“历史费用尚未核对”。历史旧进度通过可修改的已还选择补记，不能只改成已记金额。

管理保留编辑、删除；只有旧自动设置生效时才另显停止入口。期内调整可以补记本期已还或改回未还；真实已付请从对应付款更正/撤销。金额/日期计划调整在编辑资料中，差异与退款从具体费用进入。关闭、切期、换用户的迟到响应不能回填；失败保留草稿和原请求，读取最新版本后再处理冲突。

## 6. 维护、退费与终止

普通交易编辑、改分类、单笔/混选删除不能绕过收费关系。详情的调费、抑制和恢复先取 `chargeImpact`，执行重验收费/交易/贷款版本、付款、退款、来源及一次实收的覆盖子项。费用删除留抑制；明确恢复才允许再次补记，旧请求只返回原回执。

撤销后到银行补证来源保留原方案费用，并在无有效实单后恢复方案未核对依据。一次性费用覆盖多期时不能直接删掉父费用。已付费用禁止普通调减/删除，真实退费是独立退款，显示净额与不低于零的未清偿额。减免、利率改变、提前结清和终止暂停/取消未来项，不伪造退款；商品退款不自动还贷款。

授权与费用全部纳入完整导出、版本失效和最小权限。紧急暂停新同步可使用 `CATLEDGER_LOAN_SYNC_DISABLED=1`，原成功回执与历史关系保护保留；发布顺序和数据不倒迁原则见[迁移说明](../../migrations/README.md#0026-贷款费用生命周期)。
