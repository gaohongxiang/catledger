# 暖橘界面与导入展示

> MINI-1906UI2 任务分支候选，尚未进行微信开发者工具和真机验收。代码基线、负责人和验收状态见《实施规划》第 23 章。

本次是第一版视觉参考的原生小程序展示实现，不是账单语义升级。首页保留净值、完整金额、账户方向、三条最近记录和现有入口；六主题 registry 与财务颜色不改。首页样板和导入页使用局部排版，不覆盖其他页面的样式。

## 状态显示

文件为空时显示可点击的选择区；已选文件后显示列表与追加入口。仅排队非空或 uploading 时显示解析主按钮。队列归零且处于 files_ready、selected（例如移除最后一个待解析文件后）或 organizing 时显示结果；至少一个 ready 才可继续。成功、失败和已入账文件仍用原分类，失败文件不会进入整理。

账户项区分建议、已选择、已保存及历史排除；新建项纵向展示名称和类型，所有输入继续绑定现有处理器。业务保存仍由 `completeAccountMapping` 发起一次批次请求。界面折叠或查看不触发保存，不自动确认匹配。

核对和分类仍有各自的筛选和计数。记录数量等式通过 `recordSummaryExpanded` 展开，排除和重复总数始终可见。付款问题的原始账单通过 `issueSourceExpanded` 同层展开，分页、读取错误和重试保留；其他问题仍直接显示原始证据。

## 付款核对

页面优先显示付款总额和分配差额，再显示用途、目标账户及组成金额。核对说明仍必填、最大 300 字，仅换成多行输入。`paymentValidationHint` 与 `issueFieldsReason` 解释已有 model 输出，不参与有效性计算。

“全部分配”沿用原有 fill 函数，不代表剩余金额。组合付款把总额分配给该项、其他项置零；聚合还款把总额分配给该项、其他项清空。两账户自动补差继续使用整数最小货币单位算法。只确认账户时仍不要求分配金额和依据。
