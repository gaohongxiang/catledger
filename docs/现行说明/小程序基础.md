# 小程序基础

## 当前行为

- 仓库根目录可被微信开发者工具识别为原生小程序项目，项目使用 AppID `wx958ebc33591b2bab`；
- 小程序未登录时可以浏览首页、明细、账本和“我的”的公开结构，不调用 `catledger-api.bootstrap` 或其他个人业务接口，也不以零值或演示数据伪装个人账本；
- `catledger-api` 只从微信云函数可信上下文取得 OpenID，将其摘要映射到内部用户，响应和日志不返回 OpenID、摘要或内部 uid；
- 首次初始化在一个事务中创建用户、身份映射和 16 个常用收入/支出分类，重复或并发调用复用同一套数据；
- MINI-1904 本地开发版新增账户创建、改名、停用、余额校正，支出/收入/转账创建、修改、软删除，以及月份列表、搜索、筛选、净值和月度统计；
- 本地页面包含暖橘色首页、明细、账本、我的、记一笔、账户管理和分类管理；底栏使用“首页 / 明细 / 中央记账 / 账本 / 我的”。账本页以两个同规格可点击行分别进入账户管理和分类管理，微信身份连接、隐私与应用信息归入“我的”。中央仅显示暖橘大号加号，点击后以“导入账单”为主选项、“手动记一笔”为次选项；当前导入仅提供本地文件选择并明确不上传，解析与入账待 MINI-1905/1906 接入；
- 导入、手动记账、账户管理、分类管理和个人数据入口统一按需打开暖色登录面板。用户点击“登录”后才调用 `bootstrap`；登录成功后留在触发页面并继续原操作，不统一跳转到“我的”，头像昵称不再前置阻塞登录；
- 登录面板使用微信现行 `chooseAvatar` 与 `nickname` 能力提供可选头像昵称，两项留空也可登录。选择的资料首版仅保存在当前设备用于“我的”展示；未选择时显示中性头像和“微信用户”，不使用品牌 Logo 冒充用户头像；
- “我的”提供退出登录，确认后清除本机登录许可、头像昵称和临时编辑状态，不删除或修改云端账本；退出后仍可公开浏览，受保护功能会重新打开登录面板；
- “我的”新增无需登录的“主题”入口；主题页提供暖橘手账、青绿清单、红印编辑、石墨秩序、墨绿留白和票据凭证六套原创方案。选择只写入本机 `catledger_theme_v1`，即时同步页面、微信导航栏和自定义底栏，不调用云函数、不修改账目；无效存储值回退暖橘手账；
- 首页只展示净值、本月收入、支出、收支结余、已有账户摘要和最近账目，不另设统计底栏；无账户时不显示创建卡，无交易时使用轻量文字空状态。首次加载失败时保留概览结构并以“—”表示未知，不使用零值或演示数据冒充真实账本；客户端屏蔽 `cloud.callFunction` 等平台原始错误；
- 首页账户摘要最多展示 3 个活动账户，按现金、银行卡、平台钱包、信用/负债和其他类型显示本地图标，不再使用占空间的横向大卡片，也不展示已停用账户；
- 首页的“统计分析”沿用迁移前产品的收入/支出趋势语义，以轻量双柱图展示截至当月的近半年；它与“账户余额”、“最近账目”共用缩小后的标题字体和右侧“全部”入口。完整页展示月度收支、每日支出趋势和收支分类排行；数据由服务端从正式、未删除交易聚合，不使用客户端分页列表估算；
- 明细页删除顶部“记一笔”和重复大标题，月份、横向收支摘要、账户/分类/备注筛选和明细列表紧凑排列；点击中间日期可选到具体日期，本地代码会将日期交给服务端按交易本地日期筛选；
- `app.json` 已启用 `requiredComponents` 组件按需注入，避免启动时注入未使用组件；
- 小程序通过 `miniprogram/config/cloudbase.js` 显式选择公开的开发环境配置，避免误调用同一 AppID 下的旧默认环境；
- MINI-1903 的首版 MySQL schema 和 `catledger-api` 开发版已部署，微信开发者工具已用真实微信身份完成首次与重复初始化；MINI-1904 的第二号迁移和当前函数已更新到同一开发环境，真实微信身份已走通账户、支出、收入、转账、修改、软删除、余额校正、停用、幂等重放、分页、搜索、具体日期筛选、首页近半年收支趋势和完整统计页。六套主题已通过注册表测试、逐文件编译、开发者工具实际切换与跨页持久化走查；既有业务流程已通过模拟器视觉走查与真机预览推送。当前仍是未上传审核的开发版。

## 数据流

“未登录公开浏览 → 用户在受保护动作中打开登录面板 → 可选头像昵称 → 点击登录 → `bootstrap` → 云函数可信微信身份 → SHA-256 身份摘要 → MySQL 身份映射 → 初始化或读取账本 → 原动作继续 → 账户/交易事务 → 服务端余额与统计 → 返回公开字段”。客户端不能传入 uid 或 OpenID，头像昵称只作本机展示，数据库连接只读取云函数私有环境变量。

## 扩展点

- 常规业务进入 `cloudfunctions/catledger-api/`；
- 账单文件处理进入 `cloudfunctions/catledger-import/`；
- 公共请求/响应契约进入 `shared/`；
- MySQL 迁移进入 `migrations/`。
- 小程序视觉主题进入 `miniprogram/theme/`：`registry.js` 只保存纯主题元数据、语义令牌和序列化函数，`service.js` 独占本机存储与微信系统栏适配；业务页面不判断主题 ID。

开发环境部署读取根目录 `cloudbaserc.json`：`catledger-api` 随包上传本地依赖并关闭云端重复安装，部署前需在函数目录执行 `npm ci`；配置文件不保存数据库地址、账号、密码或其他私密环境变量，部署会保留云端既有 VPC 与私有变量。每次迁移新增业务表后，须显式复核受限应用账号权限；当前三个 MINI-1904 新表只授予 `SELECT`、`INSERT`、`UPDATE`，不授予 `DELETE`、DDL 或全库权限。

旧宠物项目的业务函数与 NoSQL 集合已按用户授权清理；云环境、AppID 绑定、认证配置和平台静态文件继续保留。当前开发云环境的 MySQL、七张 `catledger_*` 表、迁移 checksum、唯一索引、外键和受限应用账号均已验收。开发版保留 1 个内部用户、1 条摘要身份映射、16 个默认分类和本轮合成验收账目；没有保存明文 OpenID，也没有上传真实账单。

## 版本规则

开发阶段只维护一个当前 `catledger-api` 和一份 `shared/catledger-api.json` 契约，直接覆盖更新，不建立并行接口。小程序正式上传时再使用语义化版本号；数据库迁移按四位编号递增且已登记文件不可修改。开发版未经过微信审核和发布时，不视为正式可用版本。
