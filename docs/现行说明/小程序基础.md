# 招财猫记账本小程序现行说明

## 当前行为

### 工程与身份

- 仓库根目录可被微信开发者工具识别为原生小程序项目，项目使用 AppID `wx958ebc33591b2bab`；
- 小程序未登录时可以浏览首页、明细、账本和“我的”的公开结构，不调用 `catledger-api.bootstrap` 或其他个人业务接口，也不以零值或演示数据伪装个人账本；
- `catledger-api` 只从微信云函数可信上下文取得 OpenID，将其摘要映射到内部用户，响应和日志不返回 OpenID、摘要或内部 uid；
- `catledger-api` 使用公开动作注册表和薄交易门面组织模块：交易领域校验、正式写入、明细查询和报表统计相互分离。写动作使用用户范围的幂等事务，明细摘要、首页和完整统计分别在同一 MySQL `REPEATABLE READ` 只读快照内完成；`accounts.createBatch` 仍是普通账本兼容动作，但多账单导入不再调用它提前创建账户；
- 首次初始化在一个事务中创建用户、身份映射和 16 个常用收入/支出分类，重复或并发调用复用同一套数据；

### 正式账本

- MINI-1904A 开发后端已在既有账户与手工交易底座上增加分类新增、改名、排序、停用、恢复和关联原支出的手动退款；退款作为到账流入并冲减支出、趋势及原分类统计，不计为收入，累计金额受原支出约束；开发环境已应用 `0003` 并更新 `catledger-api`，正常 AppID 项目窗口的真实微信身份回归已经通过；

### 页面与视觉

- 本地页面包含暖橘色首页、明细、账本、我的、记一笔、账户管理、分类管理和多账单统一导入工作台；底栏仍使用“首页 / 明细 / 中央记账 / 账本 / 我的”。中央“导入账单”入口完成按需登录后进入独立工作台；
- 多账单工作台本地候选一次最多选择 5 个支付宝 App/Web CSV、微信 CSV/XLSX；单文件不超过 5 MiB、规范化记录不超过 5000 条。服务端用一次 `imports.prepareMany` 签发全部用户隔离随机路径，客户端最多 5 条“直传→逐文件解析”流水线并行执行，瞬时网络或上传超时会沿用同一路径自动补传；单次上传没有完成回调时主动中止，页面收口为可独立重试的中文错误，不透传平台底层信息。云函数按内容探测并独立持久化文件摘要、原始行、解析版本和错误；单文件失败可重试或移除，不污染其他来源。文件内容相同不直接等于已入账：明确重新上传时，上传和正文解析仍执行，持久化前按内容摘要裁决；未提交来源复用原不可变解析批次，若它仍在未入账更新中则保留审计并把旧 FinanceUpdate 标为 `abandoned`，旧资金方向、账户草稿和待整理决定不进入新更新。重复裁决由系统内部处理，未入账文件仍以普通“解析完成”收口，不向用户展示 FinanceUpdate、批次复用或作废术语；只有已随正式交易提交的来源才提示“已经入账”。用户只是返回同一工作台且仍持有 `updateId` 时才恢复原 FinanceUpdate，不能与明确重新上传混用。首次进入账户步骤只调用一次 `financeUpdates.prepare`，服务端在一个幂等事务中建立 FinanceUpdate 并完成首次整理，不再暴露 create / organize 两段半流程。页面只展示打开的 ReviewIssue，不再展示逐行“将入账 / 不新建”；账户归属由一个 `reviewIssues.resolveAccountMappings` 请求和一个 MySQL 事务整批保存，Update 只锁一次、批内共用当前映射索引，全部决定完成后仅重算受影响事件、计数一次并返回一次完整视图。新建账户和支付工具映射在此阶段只保存为 FinanceUpdate 草稿，正式账户和规则不变。所有阻塞问题清零后只有一个“整批入账”动作，一笔 MySQL 事务物化新账户、提升映射并写完全部正式交易和链接，失败整体回滚。入账前可常驻入口放弃整批，成功后清空工作台并释放来源，正式账户、映射、交易、余额和统计不变。退款、转账、还款保留各自经济语义，不再默认跳过；
- 页面采用“暖橘编辑式轻账本”视觉基线：统一 `32rpx` 页边距、主要操作 `88rpx` 触控区、固定字阶和安全区；普通内容以留白、金额对齐和细分隔线建立层级，不使用格纸背景，也不堆叠阴影卡片。净值区保留主题色与原有高度，本月摘要、趋势、账户和账目改为连续信息流；六套主题共享中等字重、细边界和柔和浮层阴影，中央加号与底部面板保留必要的强层级；

### 登录与连接

- 导入、手动记账、账户管理、分类管理和个人数据入口统一按需打开暖色登录面板。用户点击“登录”后才调用 `bootstrap`；登录成功后留在触发页面并继续原操作，不统一跳转到“我的”，头像昵称不再前置阻塞登录；
- 登录面板已抽为共享原生组件；账户、分类、记账和统计子页面被直接打开时也先走同一产品许可门禁，未许可不会调用个人 API；
- 登录面板使用微信现行 `chooseAvatar` 与 `nickname` 能力提供可选头像昵称，两项留空也可登录。选择的资料首版仅保存在当前设备用于界面展示；首页与“我的”只有在已登录且用户主动选择头像后才显示该头像，其余情况统一回退品牌 Logo，已登录但未填写昵称时显示“微信用户”；
- “我的”提供退出登录，确认后清除本机登录许可、头像昵称和临时编辑状态，不删除或修改云端账本；退出后仍可公开浏览，受保护功能会重新打开登录面板；
- “我的”只保留主题、数据与隐私、关于和退出登录，不再重复提供账本设置；账户与分类统一从“账本”进入；
- 客户端云调用统一保留稳定的公开错误码：只读动作遇到网络、超时或云端明确瞬时错误时自动短重试一次；只有公共契约已声明为幂等且携带有效 `requestId` 的写动作才允许自动恢复一次，其他写动作绝不盲目重放。两个云函数对连接重置、超时、死锁和锁等待使用新连接有限重试，并把可恢复故障映射为 `SERVICE_TEMPORARY_UNAVAILABLE`；失败日志只记录 action、平台追踪 ID、稳定错误类别和耗时，不记录请求 data、账单正文、身份或 SQL 绑定值。开发者工具缺失 AppID 时返回可识别的项目上下文错误；客户端命中新动作而开发云函数仍是旧版本时明确提示“导入服务版本过旧，请更新云函数后重试”，不再误报“操作尚未开放”；"我的"只以 `bootstrap` 判断个人账本连接，局部账户摘要失败时保持已连接并提示重新同步，不重复显示同一连接错误；

### 主题、首页与明细

- “我的”新增无需登录的“主题”入口；主题页提供暖橘手账、青绿清单、红印编辑、石墨秩序、墨绿留白和票据凭证六套原创方案。选择只写入本机 `catledger_theme_v1`，即时同步页面、微信导航栏和自定义底栏，不调用云函数、不修改账目；主题只改变品牌色和受控圆角，不改变字阶、间距、触控尺寸或信息架构，六套主题统一使用收入绿 `#477153` 与支出红 `#B54738`，无效存储值回退暖橘手账；
- 首页只展示净值、本月收入、支出、收支结余、已有账户摘要和最近 3 条账目，不另设统计底栏；更多交易统一从“全部”进入明细。既有用户回访直接调用一次 `dashboard.get`，只有服务端明确返回 `INITIALIZATION_REQUIRED` 才初始化后重试；服务端从近半年趋势结果复用当月汇总，不重复扫描当月交易。无账户时不显示创建卡，无交易时使用轻量文字空状态。首次加载失败时保留概览结构并以“—”表示未知，不使用零值或演示数据冒充真实账本；客户端屏蔽 `cloud.callFunction` 等平台原始错误；
- 首页账户摘要最多展示 3 个活动账户，按现金、银行卡、平台钱包、信用/负债和其他类型显示本地图标，不再使用占空间的横向大卡片，也不展示已停用账户；现金账户历史负数保留负号便于纠正，服务端不允许新的手工交易或整批导入新增/加深现金负余额，不用界面取绝对值或归零掩盖；
- 首页的“统计分析”沿用迁移前产品的收入/支出趋势语义，以轻量双柱图展示截至当月的近半年；它与“账户余额”、“最近账目”共用缩小后的标题字体和右侧“全部”入口。完整页展示月度收支、每日支出趋势和收支分类排行；数据由服务端从正式、未删除交易聚合，不使用客户端分页列表估算；
- 明细页删除顶部“记一笔”和重复大标题，月份、横向收支摘要、账户/分类/备注筛选和明细列表紧凑排列；点击中间日期可选到具体日期，本地代码会将日期交给服务端按交易本地日期筛选；

## 数据流

常规账本流为“未登录公开浏览 → 用户在受保护动作中打开登录面板 → 可选头像昵称 → 点击登录 → `bootstrap` → 云函数可信微信身份 → SHA-256 身份摘要 → MySQL 身份映射 → 初始化或读取账本 → 原动作继续 → 账户/交易事务 → 服务端余额与统计 → 返回公开字段”。导入流为“`prepareMany` 一次签发随机对象路径 → 最多五条私有上传/解析流水线并行 → 各文件独立内容探测、规范化和证据持久化 → `financeUpdates.prepare` 单事务建立并首次整理 FinanceUpdate → `resolveAccountMappings` 单事务保存账户/映射草稿并定向重算受影响事件 → 其他 ReviewIssue 决定与服务端 postability → 整批 posting 单事务物化账户、提升映射、写正式交易和链接 → 尽力逐来源清理临时文件”。入账前放弃则关闭 FinanceUpdate、释放来源并清空工作台，不跨越正式账本写屏障。客户端不能传入 uid、OpenID 或事件状态，数据库连接只读取云函数私有环境变量。

## 扩展点

- 常规业务进入 `cloudfunctions/catledger-api/`；
- 账单文件处理进入 `cloudfunctions/catledger-import/`；
- 公共请求/响应契约进入 `shared/`；
- 服务端公开动作、客户端静态调用与 `shared/catledger-api.json`、`shared/catledger-import.json` 由仓库测试检查漂移；
- MySQL 迁移进入 `migrations/`。
- 小程序视觉主题进入 `miniprogram/theme/`：`registry.js` 只保存纯主题元数据、语义令牌和序列化函数，`service.js` 独占本机存储与微信系统栏适配；业务页面不判断主题 ID。

开发环境部署读取根目录 `cloudbaserc.json`：`catledger-api` 与 `catledger-import` 均随包上传本地依赖并关闭云端重复安装，部署前需分别在函数目录执行 `npm ci --omit=dev`；配置文件不保存数据库地址、账号、密码或其他私密环境变量，部署必须保留云端既有 VPC 与私有变量。`catledger-import` 同时需要从 VPC 访问 MySQL、从私有云存储读取上传对象，因此保留公网出站能力，但不配置 HTTP 触发器。每次迁移或 SQL 写路径变化后都须以 `npm run check:db-permissions` 复核受限应用账号的运行权限，不再只核对表级 GRANT；账户归属批处理对 `catledger_review_issue_members` 只持有 `UPDATE(object_version)` 列级权限，其他字段不可更新。

`wx-server-sdk@4.0.2` 保持当前正式版本，`axios` 与 `@cloudbase/database` 通过兼容版本覆盖消除了历史传递依赖告警；两个事件函数的 `npm run audit:prod` 当前均为 0 个已知漏洞。事件函数不接收任意 URL、代理参数、请求头或 SDK 配置对象，客户端公开数据限制为 1000 个对象节点并拒绝身份字段，响应与日志不回传事件、上下文、环境变量或数据库绑定值。正式上传前仍须重跑依赖审计并复核上游 SDK 是否已吸收安全版本，届时应移除临时覆盖。

旧宠物项目的业务函数与 NoSQL 集合已按用户授权清理；云环境、AppID 绑定、认证配置和平台静态文件继续保留。当前开发云环境的 MySQL、19 张 `catledger_*` 表、迁移 checksum、唯一索引、外键和受限应用账号均已验收。开发版保留内部合成验收数据，包括本轮单文件导入创建的 1 条合成交易及其证据链接；没有保存明文 OpenID。用户本次真实账单仍处于逐笔确认阶段，原文件按私有临时文件策略保留，只有提交、取消或生命周期清理后才删除。

## 版本规则

开发阶段只维护一个当前 `catledger-api`、一个当前 `catledger-import` 及各自的 `shared/` 契约，直接覆盖更新，不建立并行接口。小程序正式上传时再使用语义化版本号；数据库迁移按四位编号递增且已登记文件不可修改。开发版未经过微信审核和发布时，不视为正式可用版本。


### MINI-1906UI：字阶、主题和导入导航

全 11 页与底栏、登录弹层使用正文 26rpx、辅助 22–24rpx、区块 30rpx、标题 34rpx，装饰角标 20rpx、首页辅助文字 18rpx；关键金额单独放大。页面使用共同左右留白、可换行账户名和主题变量，保留 Logo 与用户头像回退。六套主题保留原主色与 hero 配色，首页净资产、记账金额区和主题缩略图使用有辨识度的主色块；问题卡片保留柔和主题底色。收入绿、支出红保持语义。

导入第三步分交易核对与分类，核对内含待核对、按原因展开的已排除、可对照来源的重复记录。分类使用已有 ReviewIssue 冻结分组和决定接口；计数标为待分类笔数／组数，搜索摘要，完整成员在处理弹层查看。浏览证据不修改账目，分类仅写分类字段。所有阻塞问题与分类门槛仍在整批入账前校验。


用户补充后的主题色阶：暖橘（纸白／浅橘／暖灰）、青绿（薄荷／青绿／深绿）、红印（浅粉／砖红／深红）、石墨（浅灰／石墨／深灰）、墨绿（浅苔／苔绿／墨绿）、票据（奶油／麦金／赭棕）。普通边线、标签、说明和按钮使用同主题深浅色；财务收入／支出与危险操作单独保留语义色。主色摘要与浅色列表同时存在，避免所有页面统一淡化。部分深色 hero 稍加深，确保浅色数字与说明可读。


密度以完整信息优先：首页主卡保留原有 166rpx 最小高度与 22／26rpx 内边距，账户行 80rpx、最近交易行 92rpx，常用手机尺寸优先同时露出三条最近账目。关键金额 48rpx，月度与列表金额 26–28rpx，首页区块标题 30rpx／600，条目名称 24rpx／400，时间和余额标签 18rpx；其他页面共享字阶但不一律放大行高。特别长名称和系统字体放大时允许自然滚动，不截断正式金额。


所有页面采用两条横向基线：卡片外沿距屏幕 32rpx，卡片外的标题／说明／列表文字再内收 20rpx；卡片已有的内部留白保持。通过公共 content-inset 类统一首页、明细、账本、我的、账户、分类、统计、主题、记账、导入与维护页的相关区块，右侧金额和操作同样内收，避免文字贴着圆角外框显得突出。

首页返回切页时保留已有余额和账目，刷新状态在“账户余额”标题后的固定宽度按钮中旋转，失败在同一位置提供重试，不插入状态行。统计绘图区增至 168rpx，柱形区 136rpx；柱形以绘图区百分比呈现，避免放大后比例或顶边溢出。

六主题的卡片、筛选器、按钮和边线统一由 theme/registry.js 提供。暖橘使用中性纸白底、浅橘问题卡头和暖灰说明文字，红印浅层使用浅红；导航、账户与管理图标使用各主题的本地 SVG，图标色板变更后运行 node scripts/generate-theme-icons.js，同步生成产品资源。收入绿／支出红继续表达财务语义。

刷新稳定性：已加载页面保留已有数据和空结果；“我的”返回时不清零数量、不暂时撤销已连接状态。首页、明细、账本、账户、分类、统计与个人页仅在固定位置显示更新图标，删除数据流中的临时加载行。主题切换标记保留固定宽度与边框厚度；系统栏不重复播放颜色过渡。账户证据和统计分类弹层在读取前后保留同一高度，长内容在内部滚动。

首页账户余额标题后保留固定刷新槽，仅更新期间显示细线圆环，结束后隐藏，失败时原位重试。容器使用透明 view，避免微信原生 button 的禁用样式覆盖主题底色；重复点击仍由 loading 守卫拦截。

导入步骤轨道使用纸白卡面，选中项用浅主题色与实色步骤圆点区分；核对筛选减少重复色块和粗下边线。账户步骤标题与说明、账户名共用左侧基线，不叠加 content-inset。

分类列表与交易核对复用同一紧凑卡片：单行浅色状态头、右侧分类操作、日期／交易内容／来源／金额行；不再重复展示大商户标题和第二行笔数。商户只用于搜索和排序，问题组与批量保存边界不变。点击卡头进入分类，点击交易行查看原始证据且不同时打开分类；多笔省略提示在原卡片底部显示。

分类下提供「未分类／已分类」，默认未分类并显示各自总笔数。已分类从当前批次有分类的有效收支／手续费事件生成，展示现有分类、前置日期和交易证据；原始识别已有分类同样可查看。搜索作用于当前列表但不修改总数；分类保存重读后更新两个列表，最后一组完成时留在分类页，点击下一步进入入账确认。已分类本轮提供只读复查，不新增改分类接口。
整理默认待核对，分类默认未分类，不设置全部筛选或额外进度卡。两视角共用有效／排除／明确重复来源集合，顶部拆分总数与入账确认／成功页一致；有效数按唯一经济事件计算，明确重复数按 duplicate 证据关系计算，不等同于文件原始行数。核对支持只读已核对，含自动通过；分类只保留待分类／已分类／无需分类，已排除／重复只在核对查看，所有有效交易均有归属。前置核对未完成的未分类记录可跳到已有问题；待处理数按真实成员去重而非问题组数。搜索匹配完整组成员但不改批量保存范围与总数；同批保存后留在当前页签，下一步由原完整性与阻塞门槛控制。
整理页核对／分类的二级状态栏统一单行，选中态仅用浅色背景与文字强调，不带底边框；核对四项、分类三项均等宽同屏显示，状态名称与数量不换行。

顶部数量说明使用 18rpx 双等式，每个等式固定一行：有效＋已排除＋重复＝全部记录；有效＝待核对＋已核对＝待分类＋已分类＋无需分类。均取未受筛选影响的总数，整理／确认入账／完成页保持一致。

整理标题复用账户页层级：「账单整理 · STEP 03」／单行标语「核对每笔交易，按需补全分类，让收支更清晰。」，不另设重复说明。分类为非阻塞建议，入口保留批量选择与证据，下一步和入账只以必须核对事项及服务端完整性为门槛。入账后可从现有补分类入口继续完善。

核对弹层的普通字段保存按钮与提交共享 `buildIssueFieldsDraft` 校验：账户占位、无效新名称、未知性质、缺少或相同资金端点均禁用，字段修改后即时重算；组合支付与合并还款沿用各自完整性门槛。两端都缺的资金卡提供两个独立账户选择器。组合支付复用相同资金卡，左侧展示所选付款账户，右侧在还款时选择真实目标、消费时展示用途，不增加虚构账户；目标与分项表单共用状态。
