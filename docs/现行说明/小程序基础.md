# 客户端会话、分页与读取

> 文件保留旧路径，职责收敛为客户端运行规则。产品导航看[界面说明](界面视觉与导入状态.md)，账务主流程看[项目逻辑说明](../招财猫记账本入账逻辑说明.md)，环境安装与命令看[开发与验证](../开发与验证.md)。原来的阶段追加记录见[归档](../归档/README.md)。

## 1. 身份与页面进入

启动与受保护操作复用既有微信身份和登录保护。身份未确认、用户取消或退出后，不读取或展示别的会话数据。用户在受保护动作中完成登录后继续原意图，不能通过迟到登录回调打开已放弃的批次或页面。

昵称属于账号资料，头像与本机展示配置不作为权限依据。客户端会话标识用于隔离缓存和异步结果，真正授权始终由云函数可信身份完成。不存在“从本机缓存得出一个 uid 就可以操作云库”的路径。

实现：[app](../../miniprogram/app.js)、[login-guard](../../miniprogram/services/login-guard.js)、[API handler](../../cloudfunctions/catledger-api/src/handler.js)。

## 2. 普通读取链路

```text
页面查询 → catledger-api 客户端服务
        → 查询键 / 内存缓存 / 并发单飞 / 读取屏障
        → 需要时调用云函数或校验修订
        → 当前会话仍有效才更新展示
```

`read-policy` 定义动作的读取/写入范围，`read-cache` 管理缓存、请求去重和失效；服务端数据修订和读取元数据帮助判断有效性。标签失效、全局修订、写入屏障与前台校验分别有作用，不能因某一次测量看起来重叠就直接删除其中一层。

列表游标与筛选、用户、版本绑定，改变月份、账户或筛选后必须丢弃旧分页链。全选是基于同一筛选范围的完整读取，不是把当前页缓存当成全部。缓存边界仍由实现限制，不因全选取消笔数上限就允许无限缓存。

代码：[catledger-api](../../miniprogram/services/catledger-api.js)、[read-cache](../../miniprogram/services/read-cache.js)、[read-policy](../../miniprogram/services/read-policy.js)。

## 3. 有限持久展示快照

`read-snapshot-store` 保存近期完整页面结果及环境、用户、查询、版本和时间，供已确认身份的页面恢复展示。它不是另一套本地数据库，不能据此确认写入成功或跨用户恢复。

失效、过期或存储失败最多丧失展示加速。旧结果必须保留“待刷新”含义，不把错误后的占位零显示为真实余额。原始账单、附件和整份账本不进入这种快照。

详细清理与导出关系见[数据生命周期](数据生命周期.md)。

## 4. 导入页面的状态所有权

| 状态 | Owner | 禁止的替代做法 |
| --- | --- | --- |
| 首次恢复意图、页面活动及资源 | runtime | 多个流程各维护一份页面生命周期 |
| 摘要版本、页游标、响应缓存 | import-view-session | 在 Page.data 常驻整批业务数据 |
| 待发决定、在途命令、postFlight | import-draft-session | runtime 复制或自行清除持久请求 |
| 上传与文件进度 | upload-flow | 因一个文件失败重置所有文件 |
| 账户选择、核对项与表单 | 对应 account-review / transaction-review | 通过对象合并覆盖顺序决定真正处理者 |
| 最终确认、成功事实与明细刷新 | posting-flow | 成功后读取失败又生成新入账请求 |

index 显式绑定 Page 生命周期和 WXML 事件，`paged.enhance` 已移除。model/presentation 只做所需展示转换；boundedSetData 与差异 patch 控制数据桥负载，不意味着所有派生或网络查询都免费。

## 5. 读取消和写恢复必须分开

读取回填要检查当前用户、页面、批次、视图和局部令牌。过期读取、关闭面板后的原文、旧步骤的列表都可停止展示。

已发送命令则沿原请求和回执确认。页面隐藏不证明服务端回滚；写成功而摘要失败保留成功事实。重新开始有未确认 flight/postFlight 时保留可恢复请求，不能为了清界面直接删除。

`_viewEpoch` 表示页面活动世代，`_pageEpoch` 用于分页/步骤读取；正常摘要更新不取消合法入账。刷新有自己的操作令牌，旧错误与 finally 不覆盖新状态。第 1/4 步没有列表也必须结束加载。

首次恢复通过 `_pendingInitialLoad` 保持进入意图。普通隐藏延后到返回再继续；明确放弃成功或重新开始则终止该意图。放弃失败保留批次与原请求，不谎报成功。

代码：[runtime](../../miniprogram/pages/import-workbench/runtime.js)、[posting-flow](../../miniprogram/pages/import-workbench/posting-flow.js)、[import-view-session](../../miniprogram/services/import-view-session.js)、[import-draft-session](../../miniprogram/services/import-draft-session.js)。

## 6. 维护和验收

编辑中后台投影应延后，不覆盖输入；关闭编辑后按原版本/批次规则应用。订阅、分页器、定时器按生命周期释放；页面实例不得共享可变单例状态。失败保留可重试内容，不用一套“无条件 finally 清 busy”掩盖所有竞态。

测试入口：[import-paged-workbench](../../test/import-paged-workbench.test.js)、[import-async-review](../../test/import-async-review.test.js)、[import-initial-recovery](../../test/import-initial-recovery.test.js)。性能结论必须分别报告网络、SQL、派生、数据桥和耗时；没有实测不能把一次结构调整写成提速。
