# 数据生命周期

## 个人导出（MINI-1907-0 C1）

入口为“我的 → 数据与隐私”。0013～0017 迁移、必要权限和两函数代码部署已完成，本机及原生合成验证通过；云端业务联调和手机验证尚待执行，证据见主看板 19.8。导出不更改账本余额、来源字段或贷款计划。

`dataExports.start` 使用 UUID 请求号，在当前用户锁内创建一份一小时有效的临时任务；同请求重放，同用户新任务替代旧任务。0017 增加 `users.data_revision` 和 `catledger_data_exports`，每用户最多一行任务。所有普通 API/import 写事务在 READ COMMITTED 下先取得用户锁并核对 active，再递增修订、保存回执并提交；失败整体回滚，回执重放不递增。bootstrap 仅在缺少默认分类时补写并升修订。原始文件回收状态也进入同一写边界。解析 CPU 仍在事务外。

导出不长期锁账。`dataExports.page` 每次使用一致只读快照，要求任务修订仍等于用户修订；期间有任何正常写入即返回 EXPORT_CHANGED，过期返回 EXPORT_EXPIRED，客户端删除未完成文件后重新生成。`finish` 在用户锁内再次核对修订，只接受签名终点；成功结果可重放，不能把未完成分页标为完整导出。

`export-manifest.json` 显式列出 33 张业务表的全部非生成列及主键，按外键依赖顺序排列；包括归档/软删除交易、原始行、来源与整理审计、幂等回执、贷款、实际付款、更正、期次与分配历史。排除认证身份、用户表、迁移记录和导出任务；不导出云文件二进制。后续 schema 改动必须同步清单及元数据覆盖测试。

分页签名绑定服务端 uid、任务、表、主键和 UTF-8 分段位置；客户端不能提供任意表名。每页最多完成 50 行、正文最多 65536 UTF-8 字节，SQL 逐行获取避免聚合宽 JSON。宽行保持字符边界，客户端只保留当前未完行，不在页面 data 或本机 KV 存整份账本。JSONL 保持原始字符、整数分和关系 ID，首尾分别包含格式/表清单和完整性结果；交易 CSV 对文本公式前缀及控制前缀加单引号并正确转义引号，CSV 不用于完整恢复。

文件写入 `wx.env.USER_DATA_PATH` 下本功能专有文件名。成功后用户主动点击才调用 `wx.shareFileMessage`；代码不选择接收人或自动发送。过期、退出、离开页面及主动清理回收本机临时文件；应用被终止时在下一次启动/前台清理过期文件。已分享副本由用户管理，不能远程撤回。设备文件权限或空间错误中止生成，不把残缺文件当作完成。

## 本机恢复核对

`test/data-export.test.js` 只通过 `isolated-mysql` 创建两个 loopback、`_test` 隔离库及独立 API/import 角色。使用合成导入、退款、贷款和部分期次分配，导出后逐表核对非生成列；在另一库保持外键开启、按依赖插入，退款自引用待交易插入后补回并保留 `updated_at`。再逐表及通过公开接口对比账户、收支、贷款本金和期次。这是验证夹具，不是生产恢复入口或云端备份。

客户端分段、公式防护、关闭/失败及自有文件清理见 `test/export-files.test.js`；统一门禁反例见 `test/lifecycle-write-barrier.test.js`。主看板记录本批完整验证结果。用户决定本版不加入注销及其专属云端删除流程，既有文件回收行为保留；备份保留与其余发布事项按主看板后续范围处理。不能把导出完成等同于云端与手机验收通过。
