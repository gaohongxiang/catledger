# 数据生命周期与个人导出

> 本文说明保存、清理、导出和恢复的边界；不重复记录每次迁移或发布。当前状态见[实施规划](../招财猫记账本实施规划.md)，旧全文见[归档](../归档/README.md)。

## 1. 哪些数据不能混在一起清理

| 数据 | 保存用途 | 清理边界 |
| --- | --- | --- |
| 私有云文件原件 | 上传、解析重试及短期追溯 | 未入账状态统一保留 24 小时；已入账/重复/丢弃尽快删；新导入时当前用户有界清扫，全局 Timer 按时间与批次数预算轮转，失败退避；部署状态只看实施规划 |
| 原始行、来源身份、事件与决定关系 | 可追溯、防重和审计 | 不因清理原件或删除某笔交易一并抹除；48 小时硬清理只删派生核对图，保留来源行与身份 |
| 本地完整快照与决定 | 同设备未入账恢复 | 最后活动超过 12 小时不自动打开；超过 24 小时须完整读取确认无待处理提交后才清理；未知结果、损坏或读取失败均保留 |
| 服务端未入账草稿 | 跨设备和重新下载恢复 | 24 小时内自动接续，24～48 小时仅手动继续，48 小时后 Timer 有界硬清理；状态置为 `abandoned`，保留回执与来源 |
| 本地核对的服务端快照、决定与补充对象 | 分块传输、未入账恢复和最终复核 | 成功入账时同事务删除该批次全部代次及分块；废弃沿派生回收，原来源证据及回执保留 |
| 正式交易 | 余额、收支和历史账目 | 用户主动删除普通账目为受保护的物理删除；系统更正、替换、撤销仍保留原软删除历史 |
| 账户停用状态 | 保留原账户与历史，暂限新增/编辑和还款 | 可在原账户详情恢复同一 accountId；不恢复已删交易、不写余额或费用 |
| 贷款/分期管理关系 | 方案、实际借还、来源与进度 | 归档与解绑不等于删除真实资金流水 |
| 贷款收费合同、费用、覆盖与审计 | 稳定身份、授权、同费核对及清偿 | 不随管理归档/重建删除，不随金额或方案版本重建身份 |
| 本机读取快照 | 有限的展示加速 | 可失效/丢弃，不当权威余额 |
| 本机待确认写请求 | 幂等核实与恢复 | 不能随普通缓存清理删除未确认命令 |
| 导出临时任务与文件 | 生成一致版本的个人副本 | 过期/中断按专有临时文件流程清理 |

### 1.1 草稿续接、版本与清理边界

| 对象 | 最后活动 | 行为 |
| --- | --- | --- |
| 本机完整快照 | <12 小时 | 自动恢复；打开/继续/保存刷新活动时间 |
| 本机完整快照 | 12～24 小时 | 不自动打开，真实 Page 提示继续查看或放弃重启 |
| 本机完整快照 | ≥24 小时 | 完整读取后确认无待处理提交才清理；未知 `postFlight` 先核实，损坏或读取失败保留 |
| 服务端未入账草稿 | <24 小时 | 可自动接续；重新打开时按需下载 |
| 服务端未入账草稿 | 24～48 小时 | 不自动接续，用户确认后手动继续 |
| 服务端未入账草稿 | ≥48 小时 | Timer 有界硬清理派生核对图，状态 `abandoned`、`DRAFT_EXPIRED` |
| 已入账/重复/丢弃原件 | 立即 | 删除云存储对象，不等待草稿 TTL |
| 已入账请求回执/幂等记录 | 现有正式策略 | 不随草稿清理删除 |

本机快照恢复时还比较解析器、归一化、来源身份与整理规则版本。解析/身份版本变化不能被旧行静默复用，必须重新上传原文件；语义规则变化可基于已保存原文行重新整理，按明确对应关系迁移已保存选择，冲突保留并重核。新快照及迁移决定同时成为可恢复代次。未知提交先核实原请求，不先续租或升级；其他新鲜本机草稿按需用 `prepareSnapshot` 刷新服务端租约，保护正在核对的草稿。

损坏记录不能靠反复读取保证修复。用户可联网核实并恢复：服务端确认已入账则显示正式结果；未入账须通过 `prepareSnapshot(force:true)` 在同一用户锁内推进版本，使旧提交失效后再发布新本机代次，本机未同步选择可能需要重做。另一入口通过 `abandon` 确认终止旧批次后重新选择账单，完整日志但提交结果未知的冻结状态也可使用此出口。两者与旧入账互斥，未知网络结果保留原文件及恢复请求；查询未找到回执或 `NOT_FOUND` 不构成清理依据。重建成功保留旧损坏代次，随最终成功/确认终止统一清理。

用户隔离和最小权限适用于查询、关系、文件对象和回执。凭据、原始账单、完整账号/交易内容不进入普通日志与提交。用户选择分享之前不自动发送任何导出文件。

普通永久删除只移除所选正式交易及其专属事件链接/交易候选，保留共享原始行、来源身份、事件证据、账户、分类、上传原文件和“当时入账成功”的历史。旧软删除退款仅在无受保护贷款历史时解除失效的原消费引用，自身保留。最小删除回执仅含身份、请求摘要及结果，不新增可恢复的账目副本；既有审计与回执中的历史 ID 不授权恢复或再次删除。没有回收站或永久忽略名单；重新添加/主动重导仍受现行校验与有效交易防重。

修复重复补费或错误清偿的未来行为不自动修正存量。旧数据只能先通过费用详情、对应交易/来源、原付款及删除快照逐笔只读核对；同月同额不是重复证据，不批量删账或清零进度。真实修复须另行明确授权。

当前不批量清除旧软删除行、系统审计或数据库备份；原件定时清理是独立的有界任务，不承担归档搬迁或 OPTIMIZE TABLE。空间清理和复用由 MySQL 管理，物理删除不承诺磁盘占用或费用立即下降。

## 2. 个人导出流程

```text
用户发起 → dataExports.start（绑定用户和数据修订）
         → 多次 dataExports.page（签名游标、表与分段位置）
         → dataExports.finish（再次核对版本与完整终点）
         → 本机文件完成 → 用户主动选择分享
```

start 使用原请求号，在用户锁内建立有时限的任务；同请求可重放，同用户新任务按原规则替代旧任务。导出不长期锁住账本；每页使用一致只读快照，并要求数据修订仍匹配。正常写入导致修订变化时返回 EXPORT_CHANGED，过期返回 EXPORT_EXPIRED，未完成文件丢弃后重新生成。

finish 只能接受经过验证的完整终点，不能把只取了第一页的任务标成完整。分页参数绑定当前用户和任务，客户端不能自行指定任意数据库表。

实现：[data-export-service](../../cloudfunctions/catledger-api/src/data-export-service.js)、[export-manifest](../../cloudfunctions/catledger-api/src/export-manifest.json)、[公共契约](../../shared/catledger-api.json)。

## 3. 导出内容与格式

JSONL 保留受支持业务表的非生成字段、整数分、原始字符、关系 ID 及完整性信息，包括必要的软删除/归档、来源和整理审计、贷款、实际付款、期次与分配历史。认证身份、内部迁移和任务等按清单排除；不导出云文件二进制。

永久删除后的正式交易不再导出；系统内部及既有软删除历史仍按清单保留。导出中的共享证据与历史入账数量不等于当前有效明细数量。删除递增数据修订，进行中的旧导出必须重新开始。

0026 的五张新表及0027历史费用余额保全关系已纳入完整导出：合同授权、收费/抑制/覆盖、来源、付款分配及审计。自动补费也递增数据修订，导出中的同步会触发原 EXPORT_CHANGED 规则。0035 的清理重试时间/次数是维护状态，不进入账本导出、不推进数据修订；恢复时使用数据库默认值重新调度。

表、列、依赖顺序以 export-manifest 为准，格式版本由 data-export-service 返回。结构变化必须核对导出清单与恢复覆盖；仅维护状态变化不冒充账本格式升级。

宽行按 UTF-8 字符边界分段，客户端不在 Page.data 或 KV 中常驻整份账本。交易 CSV 正确转义引号，对可能被电子表格解释为公式的文本前缀作防护；CSV 不是完整关系恢复格式。

## 4. 文件分享和清理

文件写入微信用户数据目录的本功能专有名称。只有用户主动触发才调用分享能力；代码不选择收件人或自动发送。退出、离开、中断、到期及下次启动/前台按既有流程清理本功能临时文件，不能清除其他功能的数据。

权限或空间错误中止生成，不保留“导出完成”假状态。已经分享出去的副本由用户管理，应用无法远程撤回。

## 5. 恢复验证不等于生产恢复功能

[可重复隔离演练](../开发与验证.md#隔离恢复演练仅合成数据) 复用既有导出文件与双库恢复测试，只生成合成夹具，不接受真实备份或现有恢复目标。JSONL 先核对头部格式/版本/表清单、正文完整性和末尾完成记录；未完成、过期、用户不符或导出中发生修订的包不能视为可恢复副本。CSV 不是关系恢复来源。

[双库恢复验证](../../test/data-export.test.js) 先证明目标库为空，在同一恢复连接保持外键开启，按导出清单恢复业务 ID 和依赖；测试身份单独绑定，不从个人导出中恢复登录凭据。分类先恢复一级，再恢复二级；不能把子类暂改一级来绕过同名作用域。退款自引用按受控步骤回填；收费覆盖先恢复父收费再恢复被覆盖项，不能临时清空 covered_by_charge_id 破坏 CHECK 约束。

完成后逐表逐列对照非空来源、事件、决定、退款、收费覆盖和付款分配图，并核对余额、收支、贷款、期次和收费读模型。已恢复的 API 与导入原请求必须返回原回执，不能新增交易或递增修订。0035 清理维护列不导出，恢复后以默认值重新调度；恢复历史回执和来源不等于重新执行历史入账。

失败只留下本次隔离演练的待回收资源，不覆盖真实库；正常结束和异常均回收两个临时库与测试账号，无法清理时按操作手册核对归属再处理。演练通过须有实际执行与清理证据，配置检查、测试跳过和文档更新都不算完成恢复验证。

这是测试方法，不是向真实云库导入备份的授权，也不是产品已有一键恢复入口。本版不提供账户注销及其专属云端删除流程。

## 6. 有界展示快照

`read-snapshot-store` 以 schema、环境、已确认用户、查询、数据版本与时间隔离展示快照。身份确认前不展示；版本校验后才可视为新鲜结果，失败应保留“旧结果/待刷新”含义。容量、页数和有效期由实现限制，不保存导入原文、附件或整份账本。

退出清理相应快照；首次整理原 requestId 与载荷也由现有 pending-ledger-write 保存，确认后先保存原 updateId 的用户范围恢复指针。原待核实写请求位于独立存储，不因缓存回收消失。快照存储失败只损失加速，不能改写已经确认的业务结果。
