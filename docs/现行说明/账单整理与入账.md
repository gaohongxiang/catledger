# 账单整理与入账

> 本页描述系统当前行为；与代码冲突时以代码为准并修订本页。冻结契约（表结构、字段、checksum）见实施规划，此处不复制。

## 用户流程

桌面「账单整理」采用同一路由内的紧凑工作台，只包含「交易核对」和「账单记录」两个内部视图，切换不写查询参数、不跳转页面，也不挂载旧重复/转账工作台。「账单记录」保留原始文件、解析行、来源账户和支付方式映射，并提供上传、重解析和隐私删除；它不再提供绕过统一整理流程的逐行直接入账。用户从状态为 `ready` 的记录批次中选择本轮来源，系统创建财务更新并直接整理。

结果页只把本轮账单份数、待处理问题组数和可入账交易数作为主数字。整理后总数、已排除、已入账以及证据守恒均降为次级摘要；完整核对数字默认收起，按需展开后核对两条守恒关系：

- 有效证据 − 重复证据 = 最终事件；
- 最终事件 = 已入账 + 待入账 + 必须处理 + 已排除。

事件按状态筛选。列表直接展示日期、经济性质、商户、商品或备注、付款方式、记账账户、生活分类、来源记录数、金额、状态和必要原因，日常核验不需要逐卡展开。待处理列表中，日期、金额、币种、账户、商户、商品、支付方式和原因等展示字段完全相同的事件合并为一个「相似记录」问题组；这只是界面分组，每笔事件仍保留独立身份、证据和处理动作，展开后逐笔确认，不会自动合并或批量入账。经济性质、来源类型和原因码统一转换为当前语言的用户文案，未知内部码只显示通用核对提示，不直接暴露英文枚举。原始账单中的商户、商品和付款方式保持来源原文，不做错误翻译；完整原始行、来源内容及关系仍通过「查看证据」按需下钻。事件列表按页批量读取证据摘要，不逐事件请求。移动端使用相同摘要与状态口径，保持结果只读；上传和复杂处理进入对应页面。

## 数据流与语义

创建更新时锁定所选批次的不可变来源快照，同一活动批次不能被另一更新重复领取。统一整理引擎从原始证据和正式账户快照生成经济事件、证据归属、关系与守恒计数；规划阶段不创建正式 `Transaction`。

相同来源身份先归入同一判断单元；跨来源自动合并还必须有稳定业务引用和金额、币种、账户、方向、时间等语义共同支持。仅金额相同或时间接近不会自动合并。普通转入不会只凭资金方向认作收入；退款保持独立事件并受原消费累计退款上限约束；信用卡还款和内部转账只有关系明确时自动配对。

经济性质、资金方向、记账账户、对方账户、生活分类和事件状态彼此独立。未分类支出可以入账；经济性质未知、关键字段缺失或关系歧义进入 `needs_action`。处理弹窗同时核对经济性质、记账账户和分类；内部转账与还款还必须选择不同的对方账户。确认后通过字段掩码持久化性质、方向、账户、对方账户、分类和就绪状态，后续自动整理不能覆盖；用户也可以明确排除。

## 入账、纠错与撤销

默认「全部入账」只在本轮没有 `needs_action` 时执行，把所有 `ready` 事件作为一个原子动作写入正式账本。显式部分入账由独立资源接口提供，但不是默认按钮。正式余额、现金流和报表仍只认现有 `Transaction`、`Account`、分类和标签。

入账在同一用户隐私事务中写正式交易、事件交易链接、事件状态、守恒计数和动作结果。更新版本、事件版本、幂等键和请求摘要共同裁决重放与并发；任一账本写入或 CAS 失败都会整体回滚，不留下半成品。

尚未入账的事件可按字段纠错或排除。已入账事件不能直接改写；必须先检查该事件的正式交易是否存在、是否被修改或共享、是否有贷款/分期引用以及转账双方是否完整。安全时，同一事务历史化旧链接、软删旧交易并重建；不安全时持久化 `action_required`。

整轮撤销同样先做只读影响检查。只有所有正式交易仍完整且未被其他事实引用时才允许执行；成功后账本软删除、事件回到待入账，历史证据链接继续保留。

## API 与扩展边界

前端只调用三组资源接口：

- `updates`：创建、列表、详情和重新整理；
- `events`：状态分页、证据下钻、字段纠错和排除；
- `actions`：默认整批入账、显式部分入账、撤销影响检查和撤销。

旧 billflow 路由、HTTP handler、前端 service、模型和页面均已删除，不提供别名、双读、双写或兼容字段。历史 billflow 数据表只作为迁移前事实来源，不是运行时接口。

扩展新来源时只增加解析和规范化能力，不得绕过来源身份、守恒计数和隐私仓储。新增关系、入账门槛或状态语义时，先更新需求与业务规则，再冻结迁移及 SQLite/MySQL/PostgreSQL 契约。

## 版本与回滚

schema v009 保存更新、来源、经济事件、证据、关系、正式交易链接和动作审计投影，并一次性回填旧流程中仍有效的已入账证据关系。正式切换前必须备份；数据库级回滚使用切换前备份，不依赖旧页面或旧 API。未入账任务、todo 和自动候选允许在备份后按新规则重建。
