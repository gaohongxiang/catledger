# 已入账账单维护

> 先区分“当前用户界面”与“保留的后台能力”。完整流程见[项目逻辑说明：维护](../招财猫记账本入账逻辑说明.md#maintenance)，旧维护页及各次发布记录见[归档](../归档/README.md)。

## 1. 当前入口

| 用户操作 | 当前处理 | 不应误认为 |
| --- | --- | --- |
| 点击一笔明细 | 打开被点交易，按手工/导入/关联性质展示 | 找不到时选择另一条替代 |
| 编辑手工交易 | 按现行字段、版本、账户、退款/贷款规则保存 | 所有历史关联都可任意修改 |
| 编辑普通导入交易 | 主要修改分类；退款沿原支出分类 | 旧 import-maintenance 全量更正页仍开放 |
| 多选/全选删除 | 手工和导入可混选，按完整筛选范围及版本原子删除 | 只删除当前页，或遇到冲突静默跳过 |
| 查看导入记录 | 查看剩余正式账目、证据与重新导入入口 | 一定提供旧整批撤销按钮 |
| 待关联退款补原消费 | 验证原消费与累计关系后建立关联 | 把任意同额消费当作原交易 |

实际路由见 [app.json](../../miniprogram/app.json)，当前公开接口见 [API registry](../../cloudfunctions/catledger-api/src/action-registry.js)和[导入 registry](../../cloudfunctions/catledger-import/src/action-registry.js)。旧 `import-maintenance` 未注册。

## 2. 分类修改与历史账户

`transactions.setCategory` 在用户范围幂等事务内锁定交易，检查版本和分类可用性/类型，只改变分类与相应版本；原支出的退款同步分类。金额、账户、余额、原始账单、整理快照和分类映射不因此重写。

未分类筛选限定相应收入/支出，与指定 categoryId 互斥，并与月份、日期、账户、来源、搜索条件共同形成游标范围。退款、转账不是待补分类的普通收支。

停用账户不能用于新增或编辑。删除既有账目可以按原删除资格处理，但仍检查身份、版本、退款、贷款和现金约束；删除不把账户恢复为活动。

## 3. 全范围选择与批量删除

全选读取当前筛选的全部可选分页，排除不适用类型；未完成全部读取不标作已全选。读取失败保留当前选择和继续入口，换筛选或刷新按原规则处理选择，不能让旧查询结果混入新范围。

确认时冻结完整 ID/version/requestId。服务端按需分块查询、加锁和更新，但只提交一个事务。退款需要满足完整关联组约束；活动贷款关系必须先走相应贷款维护；删除后的整组净现金变化必须合法。后块冲突或异常全部回滚。

结果未知时查原回执或原键重试，不重新读取选择后悄悄替换原请求。成功软删除退出当前余额与统计，仍保留来源证据、账户、映射、导入历史和必要审计。

删除后重导同一文件可复用原始解析证据并形成新的整理批次；仍有效来源继续防重。不能通过删一笔正式交易绕过其他有效关系。

保护测试：[transaction-bulk-delete](../../test/transaction-bulk-delete.test.js)、[read-pagination](../../test/read-pagination.test.js)、[cached-page-requests](../../test/cached-page-requests.test.js)。

## 4. 保留后台能力：先预览，再锁内复核

`economicEvents.correctionImpact/correct` 与 `financeUpdates.undoImpact/undo` 仍是保留的后台契约，不是另一套现行用户流程。

预览返回完整交易集合、账户净影响、冲突、规则/对象版本和 previewToken。执行必须带匹配的决定与 token，在锁内重新核对完整集合、账户和批次。token 保证一致性，不代替可信用户身份。

单笔事件与聚合还款按现有支持范围更正；不支持的多交易类型不能拆开随意改。聚合更正软替换旧组并保存全部新分配，所有步骤共同回滚或提交。

整批撤销只作用于本批 created 的有效交易，reused 历史交易保留。外部退款、贷款关系、现金不足、对象版本改变或无法证明归属的旧副作用可以阻断。账户停用和映射恢复仅对能够证明本批独占且版本适用的对象执行；后续使用或变更的对象保留并展示影响。

历史批次缺少副作用证据时不能猜测归属。恢复旧状态也不能回删审计列或清空账本。

实现：[finance-update-maintenance](../../cloudfunctions/catledger-import/src/finance-update-maintenance.js)、[maintenance-policy](../../cloudfunctions/catledger-import/src/maintenance-policy.js)、[maintenance-side-effects](../../cloudfunctions/catledger-import/src/maintenance-side-effects.js)。

## 5. 与贷款和分期的交界

普通交易删除/更正不能破坏一个活动贷款付款组；应从贷款入口核对或整组维护。信用卡分期的管理记录删除则只解除管理关系，不能删除原消费、费用和还款。

导入来源与某笔手动费用复用时，撤销本次来源不应删除原手动费用；有效出账来源也不能推定已还。后到实单撤销只移除本次证据，原方案费用保留；无其他有效实单时恢复方案未核对依据。交易版本和关系改变会让原维护预览保守失效，需要重新预览。

已登记收费拒绝普通修改、分类修改、单笔/混选删除和独立退款绕过；详情通过签名影响预览执行调费、抑制/恢复或真实退费。锁内检查付款组、已清偿额、退款、导入来源和一次收费覆盖的子项，失败整批回滚。删除留抑制防止同步复活；实际退款冲减净费用，未来计划取消不生成退款。旧成功请求重放不能改动后来恢复的新交易。

对应验证：[费用付款](../../test/loan-charge-payments-db.test.js)、[导入核对](../../test/loan-charge-import-db.test.js)、[综合保护](../../test/loan-charge-integration-db.test.js)。

## 6. 验收重点

核对过期预览、外部退款、贷款依赖、现金不足、并发、中途失败、回执重放、同笔复用和用户隔离。测试不得通过放松原删除/更正断言制造成功。页面展示成功、随后读取失败以及离开后的迟到响应也要覆盖。

执行方式见[开发与验证](../开发与验证.md)；当前云端及真机状态见[实施规划](../招财猫记账本实施规划.md)，不沿用历史维护页演示结果证明现行入口已验收。
