# 界面、导航与状态表达

> 本文只维护用户能看见的现行行为和展示约束；业务分支见[项目逻辑说明](../招财猫记账本入账逻辑说明.md)，任务完成与手机验收见[实施规划](../招财猫记账本实施规划.md)。历史逐页修复记录见[归档](../归档/README.md)。

## 1. 当前导航

底部常驻：首页、明细、统计、我的。中央记账菜单选择账单导入或记一笔；打开、取消菜单本身不写账。需要登录时完成后继续原选择，取消留在原流程。

账户、分类、贷款、分期来源、数据隐私等有独立页面。`pages/ledger` 路由仍存在，不代表它仍是底部常驻入口；旧 `import-maintenance` 不在路由注册中。页面存在、路由可达、用户实际入口分别核对。

权威入口：[app.json](../../miniprogram/app.json)、[custom-tab-bar](../../miniprogram/custom-tab-bar/index.js)。

## 2. 视觉实现原则

颜色、字号、间距、图标与主题复用现有全局和主题资源，不在文档复制一套 CSS 数值。金额、状态、主要操作和证据应有清楚层次；不能只靠颜色表达待确认或错误，必要文字与可访问标签保留。

主题与组件入口：[app.wxss](../../miniprogram/app.wxss)、[theme/service](../../miniprogram/theme/service.js)、[品牌资源](../../assets/brand/README.md)。视觉调整不应顺带改变账务状态或放宽保存门槛。

## 3. 读取、空值、错误和成功

| 状态 | 应呈现什么 |
| --- | --- |
| 尚未成功加载个人数据 | 加载/未知，不把初始化的 0 显示成实际余额 |
| 已成功加载后刷新失败 | 保留已有结果，提示待刷新或错误及重试 |
| 金额/本金/信用额度未设置 | 明确未知或未设置，不与真实零混同 |
| 当前必填选择未完成 | 保存不可用，补齐后立即按现行规则更新 |
| 命令成功但明细读取失败 | 保留成功事实，只提示明细待刷新 |
| 结果未知 | 显示核实/恢复路径，不显示成功或重新造请求 |
| 旧读取或旧 finally 到达 | 不覆盖新页面、输入、错误或新加载态 |

提交表单保留金额和备注等输入；目录失败不要求用户重新填写全部内容。实际保存成功的轻提示与需要持续处理的错误分开，不能让旧成功卡片掩盖新状态。

## 4. 导入四步与原文

选择文件显示逐份状态；确认账户聚焦归属；核对交易集中处理剩余歧义；确认入账展示所选范围和最终影响。服务端判定是权威，不能靠前端隐藏问题让按钮可用。

账户卡片默认收起明细，需要时在同层查看当前成员及原始列值。交易核对中表单与证据在可理解的同一流程内；不要让用户反复进入多级弹层才看到原文。一次只读取必要页，部分证据失败可单项重试，超长原文沿已有分段入口查看。

原字段顺序、空值、零、重复列、额外列和编码含义保留。退款候选的原消费只是候选证据，不混入当前待裁决事件集合。关闭/切换面板后旧读取停止回填。

实现：[工作台](../../miniprogram/pages/import-workbench)、测试：[import-inline-evidence](../../test/import-inline-evidence.test.js)、[import-history-review-ui](../../test/import-history-review-ui.test.js)。

## 5. 分期详情

当前分期是一份资料及一张逐期表。账户上下文清楚显示；“显示更多”向下追加，失败保留已经展开的期次。进度确认、缺失凭证、明确未还、部分未还和当前期样式区分，不能把缺账单直接染成已逾期。

点某期处理它的来源、费用与计划，底部保留现行编辑/删除。分期详情读取失败显示未知与重试，不能切回旧普通贷款入口。普通贷款的兼容操作仍按资料类型决定。

删除说明必须表达“解除管理关系，保留账单和已入账金额，可重新关联/新建”，而非模糊的“删除全部”。详细账务规则见[贷款专题](贷款管理.md)。

## 6. 验证界线

字符串、class 和绑定断言只能保护部分结构；真实 Page 行为测试验证加载、选择、回执和恢复；原生编译检查运行入口；手机走查验证真实触摸、滚动、键盘、网络及后台切换。四者不能互相冒充。

当前文档整理没有更改 WXML、WXSS、图片、页面代码或主题。任何将来的视觉修改仍须在实际工程路径和用户授权范围内验收。
