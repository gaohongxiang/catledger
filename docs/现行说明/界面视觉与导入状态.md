# 界面、导航与状态表达

> 本文只维护用户能看见的现行行为和展示约束；业务分支见[项目逻辑说明](../招财猫记账本入账逻辑说明.md)，任务完成与手机验收见[实施规划](../招财猫记账本实施规划.md)。历史逐页修复记录见[归档](../归档/README.md)。

## 1. 当前导航

底部常驻：首页、明细、统计、我的。中央记账菜单选择账单导入或记一笔；打开、取消菜单本身不写账。需要登录时完成后继续原选择，取消留在原流程。

主导航由 [shell/index](../../miniprogram/shell/index.js) 常驻原生 Page 承载四个独立业务组件。点击底部四项只切换同一窗口内的业务面板，首次切换不再为目标主入口新建页面窗口；各面板保留独立数据、滚动位置和原业务入口。原四个页面路径仍可兼容进入对应面板。实现与验收进度以[当前任务](../招财猫记账本实施规划.md#theme-20261028)为准，不能把组件提取完成视为整体交互已通过。

账户、分类、贷款、分期来源、数据隐私等有独立页面。`pages/ledger` 路由仍存在，不代表它仍是底部常驻入口；旧 `import-maintenance` 不在路由注册中。页面存在、路由可达、用户实际入口分别核对。

权威入口：[app.json](../../miniprogram/app.json)、[shell/index](../../miniprogram/shell/index.js)、[主入口路由](../../miniprogram/shell/router.js)、[custom-tab-bar](../../miniprogram/custom-tab-bar/index.js)。

## 2. 视觉实现原则

颜色、字号、间距、图标与主题复用现有全局和主题资源，不在文档复制一套 CSS 数值。金额、状态、主要操作和证据应有清楚层次；不能只靠颜色表达待确认或错误，必要文字与可访问标签保留。

主题与组件入口：[app.wxss](../../miniprogram/app.wxss)、[主题架构](../招财猫记账本架构设计.md#theme-lifecycle)、[品牌资源](../../assets/brand/README.md)。视觉调整不应顺带改变账务状态或放宽保存门槛。

主题是当前设备的应用偏好，不随登录会话、业务加载或表单重置改变。选择成功保存后，所有已挂载页面和独立主题组件同步更新，包括常驻主 Page 中隐藏的业务面板；保存失败保留原选择并允许重试。页面或组件重新创建时以当前偏好为准，不能把模块注册时的快照当成永久初值。

窗口背景、下拉区和原生导航栏只由当前活动 Page 维护。常驻主 Page 统一拥有主导航的原生外壳，四个业务组件不各自声明 `<page-meta>` 或争用窗口；首次展示前先校准当前主题，每次激活先完成当前会话的同步清屏再开放业务内容，不等待网络。隐藏面板不触发显示或争用窗口，迟到回调遵守业务会话门禁，并保留主题订阅；返回时沿用原业务恢复规则；切换面板本身不修改账务状态。独立详情页仍在加载、显示时校准自己的原生外壳。

Page 的 `<page-meta>` 维护根节点及声明式外壳，与原生接口读取同一份有效主题。原生外壳使用字面色值，页面子树使用 CSS 变量。主宿主的导航标题与当前 Tab 同批进 data，由 `<navigation-bar title>` 声明；用 `wx.setNavigationBarTitle` 补会先看到上一个 Tab 的标题一帧。常驻壳消除四个主入口之间切换时创建新页面窗口的条件；它不等于已经证明冷启动或独立详情页首帧无闪色，也不能只凭声明存在或逻辑调用顺序宣告真机通过。

验收目标是六套主题首次进入页面和再次返回都不出现可见的错误配色，深色主题不闪浅底、浅色主题也不闪深底。窗口创建、WXML 初始渲染和数据更新是不同阶段，须按[验证矩阵](#theme-acceptance)分别取证。

页面自己的强调色、卡面、分隔线、警示底色都要从主题 token 派生，不写死某一种主题下的色值；同一个页面在六套主题下只应换色，不应换结构。收支色表达含义而非品牌，深浅底使用同色相的等价色，红为支出、绿为收入。CSS、SVG 图表和主题预览都读取有效配色；每张预览卡用自己的语义色，不继承当前页面的收支色。骨架屏高光使用主题 token，支出日历浓淡由语义色叠透明度形成，避免在深色底上沿用固定浅色阶。

## 3. 读取、空值、错误和成功

| 状态 | 应呈现什么 |
| --- | --- |
| 尚未成功加载个人数据 | 加载/未知，不把初始化的 0 显示成实际余额 |
| 已成功加载后刷新失败 | 保留已有结果，提示待刷新或错误及重试 |
| 金额/本金/信用额度未设置 | 明确未知或未设置，不与真实零混同 |
| 当前必填选择未完成 | 保存不可用，补齐后立即按现行规则更新 |
| 命令成功但明细读取失败 | 保留成功事实，只提示明细待刷新 |
| 结果未知 | 显示核实/恢复路径，不显示成功或重新造请求 |
| 旧读取或旧 finally 到达 | 不覆盖新页面、输入、错误或新加载态 |

提交表单保留金额和备注等输入；目录失败不要求用户重新填写全部内容。实际保存成功的轻提示与需要持续处理的错误分开，不能让旧成功卡片掩盖新状态。

## 4. 导入四步与原文

选择文件显示逐份状态；服务端完成解析和整理后下载完整草稿，显示准备进度，完整校验前不开放核对。随后确认账户、核对交易及分类在本地完成；确认入账提交全部最终决定，服务端按当前账本重验。不能靠前端隐藏问题让按钮可用，历史范围未覆盖显示待服务端复核。

账户卡片默认收起明细，需要时在同层查看当前成员及原始列值。交易核对中表单与证据在可理解的同一流程内；不要让用户反复进入多级弹层才看到原文。完整快照留在逻辑层和本机文件，页面一次只展示必要页，部分证据失败可单项重试，超长原文沿已有分段入口查看。

点击待核对项立即出现摘要或骨架，必需数据未齐时禁用确认；详情、目录和原文随后自动补齐。核对交易顶部是一张摘要卡：首行是带“性质”标签的性质行（普通资金事件显示并切换经济性质；分期本金默认“分期出账”，可改判为支出、费用、收入或待确认；分期利息和手续费显示来源角色且只读），下面一行标题在左、金额在右，再下面是时间；性质行是普通名目与值，不套药丸或描边；这一行常驻同主题浅底色，作为整张表的模式入口；性质未确定时换成待核对的提醒底色，选定后回到主题浅底色。点开的性质列表每行一项、整行可点，左侧是性质名和一句适用说明、右侧是勾选圈；选中行换浅强调底色并在左侧标一条强调线，勾选使用统一的对勾图标，列表下方用浅色提醒块说明改判后果。这些都是只读账单事实，切换性质会重建下面的资金与业务区域。账户始终在摘要卡下方单独成组，不并进时间行，也不因性质不同改换位置。分期本金的「本期利息归属」随后出现，候选是左侧勾选、右侧金额的清单，本期次两笔利息都列出来，已归到别的本金的置灰只读；其他性质只出现自己适用的业务判断。分期来源的期次放在这些判断之后，直接显示可编辑的「第 12 期 · 共 12 期」，居中且不画输入下划线；不是分期的性质没有这一行。期次、分类和备注同属一个收尾组，组首只画一条分隔线；分类只对有独立分类的性质出现，选好后不显示行尾清除按钮，改选直接点分类行；备注直接是输入框，名目和输入框随行高居中，不再有“添加备注”。账户卡片尾部不设清除选择动作；单账户的名称、行尾箭头和整行留白同属一个可点区域，点箭头也打开账户目录。原始交易是只读字段清单，来源条自己写明“原始交易 · 文件 · 行号”，不再重复一行标题。核对交易中的“建议配对”集中展示完整范围的唯一候选，页内预览与跨页已选数量分别显示，可取消例外后一次确认。单个银行候选项进入“选择具体配对”，每条候选边展示双方来源、时间、金额和依据，可选同笔或只拒绝这一对；历史重复保留“关联已有账目”的指定交易选择。

可选单选（退款原消费、历史对应、分期归属等）再点已选项即取消，回到未选或上一次已保存的状态；清除已保存关系另设明确动作。退款候选不另设「取消选择」按钮，提示与「本批原消费 N 笔」同行放在右侧，避免在暂记按钮旁再堆一个同义动作。必选模式没有空状态。暂记待关联是用户的决定，不是系统资格：只要这笔是退款且不是原单已关闭的来源冲突，候选多少、是否读完两个范围、候选读取成败都不影响可点；按钮旁固定说明“先入账、不冲减支出，之后可补关联”。来源冲突时按钮隐藏，改用“按已退回处理”。

分期来源区期次只出现一次，直接可编辑：「第 12 期 · 共 12 期」，总期数可留空，下方归属提示不再重复期号。费用行选计划与退款候选同一套单选卡片，整卡可点、右侧勾选，再点已选计划取消归属并回到待核对，不写“归入本计划／选它／已归属”，也不另设“取消指定”。本金卡卡头不标剩余笔数（别的利息归给谁跟这张卡无关），也不挂“同组 N 笔”（那会让一计划一笔的卡看起来要批量处理整组），也不在卡面给候选合计或列待指定利息；卡面只有本卡本金和本卡已归属的费用。本期次还没归属的利息不属于任何计划，自己在待核对里各占一张卡、卡头写「利息待归属」，点它选择归到哪笔本金；本金一旦确定就离开待核对，不陪等别的利息。本金卡打开后仍是完整的归属编辑器：打开后顶部一行只显示「本期利息归属 · 归到 计划名」，不汇总金额或笔数，下面把本期次全部利息列出来：未归属的可勾选，已归到本卡的默认勾选、再点一下即取消，已归到别的本金的那行写明「已归到 X · 不可选」且点不动。编辑器里每笔利息收在一个候选列表内，第一行是账单条目和金额，第二行是时间与账户，账单写的计划与本卡不同时再补一行提醒；整行可点选、再点取消，保存时才逐笔归到本计划。不再为每笔利息另设“详情”按钮，也不打开利息自己的编辑器，原始账单仍在交易详情里看。计划卡的卡头或「处理」直接打开本金编辑器，卡内已归属的利息行点开也是这笔利息的归属选择（可取消重选），待指定利息不占卡面行。整组关系入口只对同笔判断、来源冲突和字段冲突显示，收成原始交易区上方的一行提示；同笔判断已由底部按钮承接时不重复，利息待归属、退款和账户不显示这个入口。保存归属后，指定完的利息立刻退出待核对并归到对应计划；本期次还有别的利息没定时，只有那几笔留在待核对，本金和已归好的利息早已在已核对里——谁归给谁互不牵连。

已入账页在本次确有未归属分期来源时，入账标题下先写一行“本次有 N 条分期账单项还没有计划，例如计划名”，再给一个整行“补充分期记录”按钮，点开只列本批来源。列表里每条第一行是计划名（旧来源退回合同编号或“待确认所属分期”），第二行是账户与日期，第三行是分项与金额，下面两个按钮“新建分期／归入已有分期”，最后一行“查看原账单”。新建分期表单的名称已由计划名预填；“归入已有分期”的候选按同一套单选按钮列出期数相符的计划，同名计划排在最前并标“计划名相同”。

配对页明确当前只保存本机待入账决定；文件写入完成才显示已保存，失败保留可恢复内容并提示。关闭不表示不同笔或排除，原选择和跨页例外保持。最终冲突只标出受影响事项并补充必要事实；未知提交冻结原请求、显示核实入口，不能继续修改或直接放弃。成功回执保存后清理原文与草稿，补清失败不把已入账改为失败。

原字段顺序、空值、零、重复列、额外列和编码含义保留。退款候选的原消费只是候选证据，不混入当前待裁决事件集合。关闭/切换面板后旧读取停止回填。

实现：[工作台](../../miniprogram/packages/finance/pages/import-workbench)、测试：[import-inline-evidence](../../test/import-inline-evidence.test.js)、[import-history-review-ui](../../test/import-history-review-ui.test.js)。

## 5. 分期详情

当前分期是一份资料及一张逐期表。账户上下文清楚显示；“显示更多”向下追加，失败保留已经展开的期次。进度确认、缺失凭证、明确未还、部分未还和当前期样式区分，不能把缺账单直接染成已逾期。

点某期处理它的来源、费用与计划，底部保留现行编辑/删除。分期详情读取失败显示未知与重试，不能切回旧普通贷款入口。普通贷款的兼容操作仍按资料类型决定。

删除说明必须表达“解除管理关系，保留账单和已入账金额，可重新关联/新建”，而非模糊的“删除全部”。详细账务规则见[贷款专题](贷款管理.md)。

## 6. 验证界线

字符串、class 和绑定断言只能保护部分结构；真实 Page 行为测试验证加载、选择、回执和恢复；原生编译检查运行入口；手机走查验证真实触摸、滚动、键盘、网络及后台切换。四者不能互相冒充。

视觉修改须在实际工程路径和用户授权范围内验收；原生合成预览与物理手机验收分别记录在实施规划，不用模板编译通过替代触摸、滚动和弱网走查。

<a id="theme-acceptance"></a>
### 主题验证矩阵

| 场景 | 通过条件 | 证据要求 |
| --- | --- | --- |
| 六套主题分别冷启动，首次切换四个主面板，再次往返 | 四个入口共用同一主 Page；保存的选择贯穿内容、底栏、导航栏及下拉背景；首次和返回均无错误配色 | 核对主 Page 实例与面板活动状态，加模拟器逐帧画面；手机分别复核冷启动和首次切换 |
| 切换主题后返回隐藏面板、重新创建页面或组件 | 隐藏面板同步；新实例展示前采用最新选择，已销毁实例不再接收更新 | 生命周期回归及原生面板切换；核对首次内容开放时的主题 |
| 直接进入旧主入口、从详情返回及四面板业务恢复 | 路由指向正确面板；滚动、筛选、未保存输入、登录续接与原请求保护保持；隐藏后的迟到读取不能覆盖当前业务状态 | 路由与组件集成回归，原生返回和恢复场景 |
| 未登录、换用户、业务恢复与失败重试 | 业务数据按原规则重置，当前主题及输入保护不被旧快照覆盖 | 真实 Page 与会话回归，原生重置场景 |
| 原生配色失败、旧页面隐藏/销毁、旧主题回调迟到 | 只有活动 Page 控制原生窗口；失败在后续显示时重试，迟到回调不重涂旧色、不阻断业务 | 失败与乱序回归；模拟器核对当前页面 |
| 保存主题失败、异常偏好值、六主题预览与图表 | 保存失败保持原选择并提示重试；异常值安全回退；每张预览和 SVG 与各自有效配色一致；隐藏统计页同会话重画，换会话拒用旧缓存 | 存储、真实 Page 与配色回归，原生预览对照 |
| 物理手机前后台、触摸切页与下拉 | 前述配色和交互在实际设备成立，返回应用不闪旧色、不误改业务状态 | 单独记录设备、主题、步骤与结果；模拟器和逻辑测试不能代替 |

矩阵描述验收条件，执行状态与证据只在[实施规划](../招财猫记账本实施规划.md#theme-20261028)维护。逻辑测试可证明快照、生命周期和回调归属，不能证明屏幕第一帧的颜色。
