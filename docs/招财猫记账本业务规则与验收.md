# 业务规则与验收

> 本文定义正确性，流程见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，运行命令见[开发与验证](开发与验证.md)，历史案例见[归档](归档/README.md)。贷款新规则由[统一方案](贷款与分期改造方案.md)冻结，目标测试尚需实现；规则写入不代表当前代码已通过。

## 1. 不可破坏的规则

| 编号 | 不变式 | 典型反例 |
| --- | --- | --- |
| R01 身份 | 个人对象、读写、唯一性和回执都在可信用户范围 | 客户端换uid或猜ID访问别人 |
| R02 金额 | 整数分、币种、发生日期明确，组成守恒 | 浮点凑数，未知写零，改原文凑总额 |
| R03 账本 | 有效正式交易决定记账余额和收支；计划不直接相加，方案记录另标依据 | 预计总成本重复加进负债，未核对方案说成银行实付 |
| R04 证据 | 原文、身份、事件、决定和交易可追溯 | 删证据去重，过滤坏行称完整 |
| R05 去重 | 核验稳定身份及核心字段，弱相似只作候选 | 同额同日自动合并，不同账户编号裸匹配 |
| R06 语义 | 状态、动作与资金效果明确；出账不是实付 | 补分类解除语义阻断，导入期号就标已还 |
| R07 账户 | 真实账户、引用、端点分离，映射优先级统一 | 推断覆盖人工，虚构合并账户 |
| R08 分类 | 类型匹配、历史保留、退款沿用原消费 | 改分类顺便改来源或未经确认学习 |
| R09 退款 | 真实到账、原消费、金额/时间和累计校验分开 | 无关系伪造冲减，超额退，破坏外部引用 |
| R10 借还 | 资料/费用/实付分开，分项守恒、整组维护 | 单删还款成员，已记费用在付款时再计一次 |
| R11 分期 | 起源明确，本金不重记；费用身份不等于来源或付款身份 | 现金分期误当已有消费，缺单即逾期 |
| R12 写入 | 用户锁、版本、约束、业务与回执共同提交或回滚 | 后块失败前块仍记，换键重复写 |
| R13 异步 | 旧读不回填，已发命令保留恢复依据 | 页面关闭当事务回滚，旧finally解锁新操作 |
| R14 维护 | 删除/更正保留依赖、预览执行复查；方案费删除须抑制重生 | 删除reused交易、旧token绕过、自动复活已删费用 |
| R15 数据 | 一致导出，快照不是权威，分享主动，授权及费用可追溯 | 混合快照、跨用户恢复、导出漏授权和新关系 |
| R16 完成 | 目标、实现、部署、原生与真机分别记录 | 历史CI/跳过/上传代替当前验收 |
| R17 授权记费（新目标） | 明确方案/计费日/账户/分类/范围与用户授权，仅补已到期缺项 | 默认给旧贷款补全期费用，凭计划自动扣银行 |
| R18 历史边界（新目标） | 不补文件也可授权记费；不补历史按确认起算继续，基准覆盖不重复 | 后期账单替代授权，期初已含费用再加负债 |

R06/R11/R14中涉及来源进度和方案费用的新增约束属于本轮目标；基线代码差异见方案第2节，不能将旧断言通过当新规则已满足。

## 2. 导入验收

| 环节 | 必验场景 | 通过标准 | 主要入口 |
| --- | --- | --- | --- |
| 上传 | 多文件、失败重试、去重、超限 | 成功文件保留，无重复准备或越界 | [import-upload-flow](../test/import-upload-flow.test.js) |
| 解析 | 唯一/多模板、坏日期、方向、空零、未知列 | 不猜模板，不丢异常，原文可定位 | [导入测试目录](../cloudfunctions/catledger-import/test) |
| 语义 | 成功资金、非资金、未知状态、组合缺分项 | 正确归宿，无关字段不解除阻断 | [语义专题](现行说明/账单语义与工程验证.md) |
| 关系 | 身份重放/冲突、强关联、同额独立、历史弱候选 | 同笔有依据，证据保留 | [历史核对DB](../test/import-history-review-db.test.js) |
| 账户 | 精确/历史冲突/未知/新建/批量 | 人工优先，可达才物化，批量一次收尾 | [映射规则](../cloudfunctions/catledger-import/src/account-mapping-policy.js)及集成 |
| 分类 | 可用、未分类、停用、退款继承 | 类型正确，不改余额/金额 | [分类服务](../cloudfunctions/catledger-api/src/category-service.js)及API测试 |
| 范围 | 排除未知、缺观测、缺证据/阻塞 | 完整识别与可入账分开 | [coverage-report](../cloudfunctions/catledger-import/src/coverage-report.js)及测试 |
| 提交 | 并发/重放/过期/失败/历史变化 | 一次有效，整组回滚，不绕过复查 | [posting测试](../cloudfunctions/catledger-import/test/finance-update-posting.test.js) |

| 场景 | 通过标准 | 主要入口 |

| 本金起源与费用 | 已记消费不重记，现金借款不误省略，费用覆盖只一次 | [installment-flow-db](../test/installment-flow-db.test.js)及新L01/L07 |

| 无账单记费（新目标） | 有授权按原月补缺，无授权不写，从今起不补之前 | 方案L02～L04/L15 |
| 后导入核对（新目标） | 实际先/方案先净结果一致；20遇18确认净调-2 | 方案L05～L08/L10 |
| 归档/删除/重建（扩展目标） | 不删真实账，旧删除不破坏新关联，已删费用不复活 | [installment-flow-ui](../test/installment-flow-ui.test.js)与DB；L13/L18 |

## 4. 页面恢复

| 时序 | 预期 |
| --- | --- |
| flush后新viewVersion仍可入账 | post一次，不因分页令牌取消 |
| flush后新增阻塞 | 不发post，提示核对 |
| flush时隐藏/卸载/换用户或批次 | 不继续旧写，不回填 |
| post已发后离开，成功或失联 | 原请求可恢复，旧结果不覆盖 |
| 首次恢复中明确放弃，旧登录/摘要迟到 | 不复活旧批次或原文 |
| 放弃失败 | 保留批次与原请求，不虚报idle |
| 第四步刷新成功/失败 | 加载结束，可重试 |
| 旧刷新/旧finally晚于新操作 | 不覆盖新内容、错误或加载 |
| 编辑中后台更新 | 不覆盖输入 |
| 证据关闭/翻页/退出后迟到 | 不跨项、跨页、跨用户 |

入口：[async-review](../test/import-async-review.test.js)、[initial-recovery](../test/import-initial-recovery.test.js)、[paged-workbench](../test/import-paged-workbench.test.js)、[inline-evidence](../test/import-inline-evidence.test.js)。新费用同步复用这些原请求与生命周期原则。真实Page VM不代替真机。

## 5. 重构与性能

结构重构用固定输入比较事件、问题、来源、关系、金额、账户、状态、版本及回执。随机ID一致映射、外键随动，不删ID掩盖错绑；业务时间和确定性键不是噪声。

新贷款规则是有意改变行为，不要求与旧错误进度完全相同；用新规则金标及旧数据兼容验证，未涉及功能继续等价。实际SQL、云请求、响应字节、派生、setData和缓存都要测，低于上限不等于允许无解释增长，单次耗时不证明优化。

预算：[performance-contract](../cloudfunctions/catledger-import/src/performance-contract.js)、[页面测试](../test/import-paged-workbench.test.js)。边界断言不能代替行为测试；新同步有界，不能在每个只读请求中扫描全账或写交易。

## 6. 数据与交付

导出覆盖版本变化、过期、宽行、字符、半文件、主动分享与分类依赖；新授权/费用/付款关系同步入manifest和权限测试。只用隔离库恢复，见[data-export](../test/data-export.test.js)、[runtime-roles-db](../test/runtime-roles-db.test.js)。

每阶段记录精确SHA、环境、命令、通过/失败/跳过、未覆盖和部署事实。未做手机验收就保持待验收，完整命令只在[开发与验证](开发与验证.md)维护。用户验收前代码及文档留docs，不合main、不擅自云迁移或部署。
