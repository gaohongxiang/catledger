> 本文定义正确性，流程见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，运行命令见[开发与验证](开发与验证.md)，历史案例见[归档](归档/README.md)。贷款规则由[统一方案](贷款与分期改造方案.md)冻结；对应测试已实现，具体执行结果与未验证项见实施规划。

## 1. 不可破坏的规则

| 编号 | 不变式 | 典型反例 |
| --- | --- | --- |
| R01 身份 | 个人对象、读写、唯一性和回执都在可信用户范围 | 客户端换uid或猜ID访问别人 |
| R02 金额 | 整数分、币种、发生日期明确，组成守恒 | 浮点凑数，未知写零，改原文凑总额 |
| R03 账本 | 有效正式交易决定记账余额和收支；计划不直接相加，方案记录另标依据 | 预计总成本重复加进负债，未核对方案说成银行实付 |
| R04 证据 | 原文、身份、事件、决定和交易可追溯 | 删证据去重，过滤坏行称完整 |
| R05 去重 | 核验稳定身份及核心字段，弱相似只作候选 | 同额同日自动合并，不同账户编号裸匹配 |
| R06 语义 | 状态、动作与资金效果明确；出账不是实付 | 补分类解除语义阻断，导入期号就标已还 |
| R07 账户 | 真实账户、引用、端点分离，映射优先级统一 | 推断覆盖人工，虚构合并账户 |
| R08 分类 | 类型匹配、历史保留、退款沿用原消费 | 改分类顺便改来源或未经确认学习 |
| R09 退款 | 真实到账、原消费、金额/时间和累计校验分开 | 无关系伪造冲减，超额退，破坏外部引用 |
| R10 借还 | 资料/费用/实付分开，分项守恒、整组维护 | 单删还款成员，已记费用在付款时再计一次 |
| R11 分期 | 起源明确，本金不重记；费用身份不等于来源或付款身份 | 现金分期误当已有消费，缺单即逾期 |
| R12 写入 | 用户锁、版本、约束、业务与回执共同提交或回滚 | 后块失败前块仍记，换键重复写 |
| R13 异步 | 旧读不回填，已发命令保留恢复依据 | 页面关闭当事务回滚，旧finally解锁新操作 |
| R14 维护 | 普通用户删账物理删除所选交易及专属引用，退款/同源付款分配组/贷款/费用/现金保护与回执同事务；系统更正/撤销保留原历史与预览复查 | 部分删除、旧删除请求误删重添记录、整批撤销删reused交易、旧token绕过、自动复活已删费用 |
| R15 数据 | 一致导出，快照不是权威，分享主动，授权及费用可追溯 | 混合快照、跨用户恢复、导出漏授权和新关系 |
| R16 完成 | 目标、实现、部署、原生与真机分别记录 | 历史CI/跳过/上传代替当前验收 |
| R17 逐期保存 | 勾选已还后一次保存同时记缺失费用；默认勾选、读取和迁移不写账 | 另设重复授权；只变进度却漏记利息；凭计划扣银行 |
| R18 历史边界 | 第6期接入与第8期补漏均可逐期改；历史费用与余额保全成对保存、维护、导出 | 自动覆盖已选未还/部分；补历史重复改变当前余额 |
| R19 整组删计划 | 按最初创建及当前使用撤销独占新增账；有效银行认领、原有账与正确更正保留；费用／校正成对，完整预览和原事务执行 | 按manual/import、当前loanId或created_by_payment单独猜删；拆共享付款、只撤配套校正、复活已取消费用、旧键误删新记录 |

**R20 统一交易编辑：** 同性质、同资金结构、同业务阶段，不因自动识别/手动选择或入口不同改变表单与校验；当前卡片的 eventId 决定编辑主体，普通保存默认只改本笔；原始凭据只读，人工有效值可修正；字段与兼容关系同事务，保存草稿不得冒充完成或解除未解释阻断。完整字段权限和 UE01～UE60 验收矩阵见[统一编辑方案](导入交易统一编辑方案.md)；实现与各环境验收状态只在实施规划记录。

R06/R11/R14 的来源进度和费用约束已替换旧错误语义，原账务保护断言保留；旧进度兼容、收费身份与并发事务有独立验证。

## 3. 账本与贷款验收

历史确认必须保存实际采用的本金金额和版本；修订计划后撤回仍使用原确认金额，并验证全部有效借还时间线。费用的历史清偿与余额保全分开；已有费用不为标已还新增余额调整。后补明确同一期付款只替换历史覆盖，不重复冲减；未知旧本金不得按当前计划猜测。反例与原请求、失败回滚、后补凭证/退款组合验证见 [installment-history-db](../test/installment-history-db.test.js)。

| 场景 | 通过标准 | 主要入口 |
| --- | --- | --- |
| 首页全账本总览 | 卡片仅当前净资产、累计收入和累计支出，无月份或累计结余；加载与重试作用于整页；跨年份累计不随趋势月份缩小，关联退款减支出、转账/期初/删除不重计；净资产独立、其他用户隔离，读取不写账；旧本月结果不得冒充累计，失败可重试 | [首页Page](../test/home-overview.test.js)、[API集成](../cloudfunctions/catledger-api/test/integration.test.js) |

## 5. 重构与性能

结构重构用固定输入比较事件、问题、来源、关系、金额、账户、状态、版本及回执。随机ID一致映射、外键随动，不删ID掩盖错绑；业务时间和确定性键不是噪声。

新贷款规则是有意改变行为，不要求与旧错误进度完全相同；用新规则金标及旧数据兼容验证，未涉及功能继续等价。实际SQL、云请求、响应字节、派生、setData和缓存都要测，低于上限不等于允许无解释增长，单次耗时不证明优化。

长期分期详情用一次紧凑快照读取全计划，36期第21期取消、600期完整展示/原子保存、中段回滚及不完整快照门禁见[长计划真实Page/DB回归](../test/installment-performance-db.test.js)。固定列快照保留原成本与逐期期号；列表按贷款/期号分组来源，历史保存复用本次原计划，不逐期重算。单响应与单次数据桥保持256 KiB以内，实测口径见[开发与验证](开发与验证.md#长计划同环境计量)。

预算：[performance-contract](../cloudfunctions/catledger-import/src/performance-contract.js)、[页面测试](../test/import-paged-workbench.test.js)。边界断言不能代替行为测试；新同步有界，不能在每个只读请求中扫描全账或写交易。
