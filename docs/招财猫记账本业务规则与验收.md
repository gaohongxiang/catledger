# 业务规则与验收

> 本文回答“怎样才算正确”，不重复描述完整操作流程。流程见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，运行命令见[开发与验证](开发与验证.md)，历史完整案例见[归档](归档/README.md)。规则编号用于后续任务引用，不代表新增业务实现。

## 1. 不可破坏的规则

| 编号 | 不变式 | 典型反例 |
| --- | --- | --- |
| R01 身份 | 所有个人读写、对象、唯一性与回执都处于可信服务端用户范围 | 客户端换 uid 或猜 ID 即可访问别人的批次 |
| R02 金额 | 整数分、明确币种和发生时间；金额组成必须守恒 | 浮点误差、把未知写成零、为凑总额修改来源 |
| R03 账本权威 | 只有有效正式交易改变余额和实际收支 | 预览、贷款计划、分期本金再次加入余额 |
| R04 证据 | 原始行、来源身份、事件、决定和交易关系可追溯 | 为去重删除原文；无效行被过滤后称全部识别 |
| R05 去重 | 稳定身份还要核验核心字段；弱相似只作候选 | 同额同日自动合并；不同账户银行编号裸匹配 |
| R06 语义 | 明确状态、动作、资金效果优先；未知和冲突不能被补字段掩盖 | 填分类后解除多账户缺分项的阻断 |
| R07 账户 | 真实账户、来源引用和资金端点分离；映射优先级统一 | 推断覆盖人工决定；创建虚构的合并信用账户 |
| R08 分类 | 收入/支出类型匹配，停用不删历史，退款沿用原消费分类 | 将转账当消费；改分类顺便重写来源或学成未经确认映射 |
| R09 退款 | 真实到账、原消费、金额/时间及累计退款关系分别验证 | 无原消费就伪造收入或冲减；超额退款；外部引用被破坏 |
| R10 借还 | 实际资金、贷款资料、计划分开；不猜本息费；整组维护 | 单独删除还款组的一笔造成本金与资产不一致 |
| R11 分期 | 信用卡特例严格限定；本金不重记、费用不重复、明确异常优先 | 缺账单直接标逾期；删除分期顺带删除正式消费 |
| R12 写入 | 用户锁、版本、约束、业务变化与回执共同提交或回滚 | 后块失败前块仍入账；同键重试生成第二笔 |
| R13 异步 | 过期读不能回填；已发写命令保留原确认/恢复依据 | 页面关闭等于操作取消；旧 finally 解锁新操作 |
| R14 维护 | 软删除与关系保护明确，预览执行之间必须再次校验 | 删除 reused 历史交易；旧 previewToken 绕过新状态 |
| R15 数据 | 导出为一致快照；快照不是账本；分享由用户触发 | 混合版本导出；损坏文件当完成；跨用户恢复快照 |
| R16 完成 | 代码、测试、部署、原生与真机验收分别记录 | 用历史 CI、跳过项或上传成功代替当前验收 |

## 2. 导入验收矩阵

以下均使用合成或获授权且妥善隔离的输入；不得以真实财务写入作为默认自动化验证方法。

| 环节 | 必验场景 | 通过标准 | 主要测试入口 |
| --- | --- | --- | --- |
| 上传 | 多文件成功、单份失败、原位重试、重复选择、超限 | 成功文件不被清空；没有重复准备或越界写入 | [import-upload-flow](../test/import-upload-flow.test.js) |
| 模板与解析 | 唯一命中/多模板、坏日期、方向冲突、空值与零、未知列 | 不猜模板、不丢异常行、原始字段可定位 | [导入函数测试目录](../cloudfunctions/catledger-import/test) |
| 语义 | 成功资金、非资金、未知状态、组合资金缺金额 | 对应正确归宿；补无关字段不能解除阻断 | [语义与验证说明](现行说明/账单语义与工程验证.md) |
| 身份与关系 | 同来源重放、核心冲突、强跨来源关联、同额独立、弱历史候选 | 只合并有依据的同笔，所有证据保留 | [import-history-review-db](../test/import-history-review-db.test.js) |
| 账户 | 精确归属、历史类型不符、同级冲突、未知、新建、批量 | 人工优先；可达草稿才物化；批量事务一次收尾 | [账户映射规则](../cloudfunctions/catledger-import/src/account-mapping-policy.js)及导入集成测试 |
| 分类 | 可用分类、未分类、已停用、退款继承 | 分类不改变金额和余额；类型一致 | [分类服务](../cloudfunctions/catledger-api/src/category-service.js)及 API 测试 |
| 所选范围 | 未知行排除、缺当前文件观测、未决语义、证据缺失 | 完整识别与可入账不混淆；排除不抬高识别率 | [coverage-report](../cloudfunctions/catledger-import/src/coverage-report.js)及导入测试 |
| 提交 | 重放、并发、过期版本、中途异常、历史候选新增 | 单次有效结果；整组回滚；锁内复查不绕过 | [finance-update-posting 测试](../cloudfunctions/catledger-import/test/finance-update-posting.test.js) |

## 4. 页面恢复专项验收

| 时序 | 预期 |
| --- | --- |
| flush 得到新 viewVersion，仍满足入账条件 | 正常发送一次 post，不被分页 epoch 误取消 |
| flush 后新增阻塞 | 不发送 post，明确提示继续核对 |
| flush 等待时隐藏、卸载、换用户或批次 | 不继续发未发送的旧 post，不回填 |
| post 已发后离开，随后成功或响应丢失 | 原 postFlight/requestId 仍可确认；旧结果不覆盖新页面 |
| 首次恢复中明确放弃，随后返回或旧登录回调到达 | 不恢复已放弃批次，不打开旧原文 |
| 放弃失败 | 不谎报 idle；保留批次及原放弃请求用于重试 |
| 第四步刷新成功或失败 | 加载结束；失败可重试 |
| 旧刷新晚于新刷新，或旧 finally 到达 | 不覆盖新结果、错误或加载态 |
| 编辑中收到后台摘要 | 不覆盖输入；关闭编辑后按原规则应用 |
| 关闭证据面板、翻页或退出登录后原文读取返回 | 不跨项、跨页、跨用户回填 |

自动化入口：[import-async-review](../test/import-async-review.test.js)、[import-initial-recovery](../test/import-initial-recovery.test.js)、[import-paged-workbench](../test/import-paged-workbench.test.js)、[import-inline-evidence](../test/import-inline-evidence.test.js)。这些真实 Page 测试仍模拟微信数据桥和网络，不能替代手机验收。

## 5. 结构重构和性能的验收方式

固定输入比较事件、问题、来源归属、关系、金额、账户、状态、版本及回执，不能只比较数量。随机 ID 要一致映射，所有外键同步映射，不允许删掉 ID 字段掩盖错绑。业务日期、确定性身份键和摘要不是可任意剔除的噪声。

同时检查实际 SQL 次数、云请求次数、响应字节、派生计算、setData 次数与缓存占用。低于硬上限不代表允许无解释增长；一次耗时测量也不能证明性能提升。不同金融异常规模分别记录，不能把额外扫描藏在平均值里。

已有预算入口：[performance-contract](../cloudfunctions/catledger-import/src/performance-contract.js)、[页面测试](../test/import-paged-workbench.test.js)。边界断言检查依赖方向与绑定，不代替业务测试；整理测试前先证明真实行为已有等价保护，不能仅为变绿删除反例。

## 6. 数据、权限与交付

导出验证包括分页期间版本变化、过期、超宽行分段、特殊字符、失败半文件、用户主动分享和分类父子依赖。恢复对照只能用隔离测试库，生产没有因此获得自动恢复入口。见 [data-export](../test/data-export.test.js)、[runtime-roles-db](../test/runtime-roles-db.test.js)。

每次验收记录：精确提交、环境、实际命令、通过/失败/跳过、未覆盖项、部署状态。禁止把旧任务结果当本轮结果；未做手机操作就写待验收。完整运行方式统一在[开发与验证](开发与验证.md)，不在每个历史规格复制一遍。
