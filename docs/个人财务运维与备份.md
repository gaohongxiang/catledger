# 个人财务运维、备份与恢复

> 当前生产状态以[个人财务实施规划.md](./个人财务实施规划.md)为准。
> 重整前原文：[个人财务运维与备份-20260821-重整前.md](./归档/个人财务运维与备份-20260821-重整前.md)

## 1. 数据边界

- 正式交易、账户、分类和标签位于核心用户数据库；
- `pf_` 表保存证据、来源身份、关系、整理任务、覆盖和债务计划；
- 原始账单字节位于配置指定的对象存储；
- 数据库、对象存储和只读配置共同组成可恢复实例，CSV/TSV 导出不是完整备份；
- `pf_schema_migration` 是全局迁移账本，不属于单个用户清理范围。

## 2. 本机正式运行目录

macOS 本机正式实例不在用户主目录散放项目副本或运行配置。固定布局为：

- 配置：`~/Library/Application Support/ezBookkeeping/production/conf/ezbookkeeping.ini`，只读挂载到容器；
- 一致备份：`~/Library/Application Support/ezBookkeeping/production/backups/<发布标识>`；
- 正式数据、对象存储和日志：Docker 命名卷，当前分别为 `ezbookkeeping-fork-recovery-data`、`ezbookkeeping-fork-recovery-storage`、`ezbookkeeping-fork-recovery-log`；
- 项目源码：`~/projects/ezbookkeeping`，不得兼作运行数据或备份目录。

标准目录只保存当前配置、最近发布前一致备份、一个重要 schema 边界备份和一个基线备份。更早的连续切服快照在确认新版本、即时回滚对象和保留备份均可用后移入废纸篓；历史容器和镜像只保留当前版本与一个即时回滚版本。构建缓存卷不属于业务数据，可在没有构建任务时删除并按需重建。

## 3. 一致备份

备份前优先停止正式 Web 容器。必须在同一停服窗口保存：

1. 全部用户数据库；
2. `personal_finance/import_files` 对象存储根；
3. 当前只读配置；
4. 正式镜像名、完整提交和 schema 版本；
5. 容器挂载、端口和重启策略的安全摘要。

备份目录不得进入仓库。备份介质继承原账单敏感级别，应限制访问、加密并设置保留期。聊天、日志和工单不得记录对象 key、原文件名、完整账户标识或原始交易内容。

## 4. 正式发布

对8080有用户可见影响的完整阶段采用：

1. `git fetch` 并确认目标主线可安全快进；
2. 工作树洁净、提交范围和验证证据完整；
3. 停服并执行一致备份；
4. 构建带完整提交哈希的可追溯镜像；
5. 保留当前容器为明确命名的即时回滚对象；
6. 复用正式数据、存储、日志卷和只读配置启动新容器；
7. 验证根页面、版本、迁移、聚合一致性和受影响用户流程；
8. 完整重启后再次验证；
9. 更新实施规划并按授权推送 `origin/main`。

文档、测试或运行行为不变的修改不切服，交付时明确说明刷新看不到变化。

## 5. 数据库迁移

- PF schema 只通过显式、连续、forward-only、可重入迁移升级；
- 启动前或发布窗口内使用当前二进制执行 `ezbookkeeping database update`；
- schema、唯一约束、条件更新和事务语义变化必须在 SQLite、MySQL、PostgreSQL 验证；
- 不以 XORM Sync2 作为唯一迁移机制；
- 旧二进制可以忽略新增 PF 表，但不承诺通用 down migration。

## 6. 恢复演练

1. 停止待恢复实例并保留现状副本；
2. 恢复匹配的数据库、对象存储和配置快照；
3. 使用目标二进制执行 `database update`；
4. 在服务仍停止时执行 `check-personal-finance --uid <UID>`；
5. 核对迁移版本、批次派生计数、证据关系、正式交易链接、对象状态和孤儿记录；
6. 启动后验证登录、总览、账单、证据和债务摘要；
7. 记录恢复点之后可能丢失或重复的核心账本变化。

一致性命令只输出脱敏聚合。Local filesystem 和 MinIO 可枚举对象；后端不支持可靠枚举时必须明确失败，不能把“不支持”解释为“健康”。

## 7. 删除与清理

- 废弃批次不得删除已 linked、已 posting 或已入账的证据；
- 删除原文件字节后仍保留哈希、批次、行、身份和证据关系；
- 清除用户数据先删除已登记对象，再在隐私事务中按依赖逆序清理 `pf_` 用户数据，之后继续核心数据清理；
- 失败操作必须可用同一请求幂等重试；
- 临时容器、卷、分支和 worktree 只在提交已集成、证据已记录且工作树洁净后清理；
- 使用明确路径和名称，不对宽泛目录执行递归删除。

## 8. 回滚限制

- 恢复 PF 数据不会自动撤销恢复点之后的核心正式交易；
- 对象存储和数据库没有跨系统事务，删除或上传失败依靠状态机和补偿收口；
- 交易已修改、已删除、被其他批次共享或绑定贷款关系时，自动撤销必须拒绝并展示影响；
- 数据库级回滚优先恢复一致备份，不手工改写迁移账本或业务状态冒充成功。
