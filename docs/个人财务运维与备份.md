# 个人财务运维、备份与恢复

本文说明阶段一个人财务导入数据的安全运维边界。它不替代部署平台自身的数据库与对象存储备份手册。

## 数据与删除边界

- 正式账本仍以现有 `Transaction`、账户、分类和标签为唯一权威；个人财务表保存原文件元数据、解析批次、原始证据、来源身份、posting 和证据关系。
- “废弃批次”只允许用于 `awaiting_source_account` 或 `ready` 且没有 linked 行、posting 或已入账计数的批次。它保留批次和证据，不删除正式交易。
- “删除原文件”只删除对象存储中的原始字节，并把文件状态幂等收口为 `deleted`。文件哈希、批次、行、身份和证据关系继续可查；重新上传完全相同的字节可以恢复同一文件身份的内容。
- 撤销影响接口只返回聚合计数。本阶段没有自动撤销正式交易；交易已修改、已删除、被其他批次共享或由历史关系复用时尤其必须人工处理。
- “清除所有数据”先幂等删除当前用户已登记的个人财务对象，再在一个隐私事务中按依赖逆序清理全部 `pf_` 用户数据，之后继续现有核心数据清理。失败后可用同一操作安全重试；`pf_schema_migration` 不属于用户数据，不能删除。

## 完整备份

CSV/TSV 导出只覆盖正式交易数据，不是个人财务完整备份。可恢复备份必须把以下两部分视为一个一致性快照：

1. 所有用户数据数据库（包括 `pf_` 业务表和 PF migration ledger）；
2. 配置所指向的 `personal_finance/import_files` 对象存储根。

备份时应停止 Web 服务，或使用数据库与对象存储都支持的同一时间点快照能力。不能在应用持续上传或删除原文件时，分别复制数据库和对象目录后宣称得到一致备份。备份介质应继承原账单的敏感级别，限制访问、加密并设置保留期；普通日志、工单和聊天中不得记录对象 key、原文件名、完整账户标识或原始字段。

## 恢复演练

1. 停止 Web 服务并保留待恢复实例的现状副本；
2. 恢复用户数据库和与之匹配的个人财务对象存储快照；
3. 使用当前二进制执行 `ezBookkeeping database update`，完成 forward-only schema 升级；
4. 在 Web 服务仍停止时，对需要核对的用户执行：

   ```text
   ezBookkeeping database check-personal-finance --uid <UID>
   ```

5. 确认批次派生计数、证据关系、正式交易链接和已登记对象状态没有不一致，并且对象清单中没有未登记最终对象或遗留临时对象，再启动服务。

该命令只输出脱敏聚合，不输出对象 key 或业务内容。Local filesystem 和 MinIO 支持停服对象枚举；通用 WebDAV 无法保证可靠枚举时命令会明确失败，不能把“不支持”解释为“健康”。WebDAV 用户级清理仍按数据库已登记 key 执行，不依赖枚举能力。

## 回滚限制

- PF schema 是 forward-only；回滚应用版本时旧二进制可以忽略新增 PF 表，但不承诺通用 down migration。
- PF 备份回滚不会自动撤销已经写入核心账本的正式交易。恢复前必须评估恢复点之后的账本变化，必要时人工对账。
- 对象存储和数据库无法共享事务。删除对象成功但数据库状态更新失败时，重复相同删除操作会幂等收口；上传补偿同样通过状态机恢复，不能手工改写状态冒充成功。
