# 用户需求与产品范围

> 本文定义用户要完成什么，不记录部署日志或测试数量。流程见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，状态见[实施规划](招财猫记账本实施规划.md)。基线为 b804bfc4，旧需求全文保存在[归档](归档/README.md)；第3.4节是本次确定、待代码落地的新目标。

## 1. 为谁解决什么问题

用户不定期获得银行、支付宝、微信支付账单，希望少做重复录入，也能理解资金变化、收支、负债与分期。系统自动处理证据充分或已获明确授权的正常事项，只把缺失和冲突集中询问。

目标是可解释、少操作、不重复记钱、失败能恢复，不是每行都猜一个结果。系统不代付、转账、投资或借款，模型不能替代真实资金记录。没有每个月的文件不应阻止管理贷款。

## 2. 核心用户旅程

| 用户目标 | 应有体验 | 不能发生 |
| --- | --- | --- |
| 打开自己的账本 | 识别身份，原动作在登录后继续 | 先显示别人的缓存，取消仍写入 |
| 导入多文件 | 独立进度、单项失败重试 | 一份失败清空全部，上传即计余额 |
| 确认账户 | 已知复用，未知询问 | 默认不明账户，把合并名称当真账户 |
| 核对歧义 | 原文可见，候选与影响范围明确 | 同额吞并，隐藏证据强迫猜测 |
| 完成入账 | 一次确认，整批原子，原请求恢复 | 半批成功，重试重复扣款 |
| 手工维护 | 必需金额/账户/时间明确，失败留输入 | 缓存推断成功，来源改写无痕 |
| 管理贷款/分期 | 一笔一张表，完整计划一次建立，漏月有方案可继续 | 每期重复录入、重复计费、有后期账单即已还 |
| 导出数据 | 一致版本，用户主动分享 | 半文件当完整，自动外发 |

## 3. 产品边界

### 3.1 入口和账户

当前导航为首页、明细、统计、我的及中央记账，菜单选择导入或记一笔；账户、分类、贷款为独立页面。以[实际路由](../miniprogram/app.json)和[自定义导航](../miniprogram/custom-tab-bar/index.js)为准。

人民币账本支持现金、银行卡、平台钱包、信用账户等资产/负债。期初余额或欠款用独立调整；账单日、还款日、信用额度可未填、修改、清空，不显示假零。停用保留历史，不继续新增/编辑普通交易；历史删除仍受账务保护。

分类最多两级，父级固定，同级排序、停用恢复，一级/二级都可记账。未分类可后补，不等于资金性质不明也能入账。

### 3.2 导入与证据

支持格式由解析器与已测试模板界定，不等于所有银行表格都能自动识别。列、方向、币种、日期或组成不明留下问题；排除不把整份文件变完整识别。

多来源同笔保留证据，只记应有交易。同额、同日、相似文字不能自动合并。核对直接看原始列和值，保留空值/零和额外列；强且唯一的退款证据才自动关联，无候选可待关联，到账与统计关系分开。

本人转账有两个资金端点，组合支付/还款先认真实账户再认组成；缺本息费不猜拆分。用户决定不被系统重算静默覆盖。贷款来源今后还要区分计划、出账、计费与实付，详见3.4目标。

### 3.3 正式账本、查询与维护

有效正式交易产生记账余额与收支，计划和预览不直接计入。明细组合月份/日期、账户、分类、来源、备注与导入范围；全选覆盖完整可选范围。

混选删除有版本、退款、贷款和现金保护，整组成功或失败。导入普通编辑主要改分类，后台更正/撤销存在不等于旧维护页仍开放。新方案费用真正写入后也必须覆盖这些保护，不能绕开旧关系校验。

### 3.4 贷款与分期（目标，尚待实施）

**一笔记录、一份完整方案、一张逐期表，用户不必每期上传文件。** 建立时分清现金借入、已记消费转分期、新消费和历史接入；本金/消费各记一次，总计划不重复加到负债。

固定费用在用户一次明确授权、确认计费日与起算范围后，可以使用时补齐到当前日期，归属各原计费月份。显示“按确认方案记账、未与银行账单核对”，计费用与对应负债，不自动扣银行卡、不自动还本金。未授权只预览缺项，支持一次批量确认；未知金额、浮动/变化方案单独核对，不强制交文件。

用户可不补历史，从确认日期和当前基准继续；更早缺失不造流水，既有记录保留并如实标注完整性。基准已含的费用不能再补成一份负债。后导入实单复用同一费用，差额经确认净调整；实际先记后建贷款也先吸收已有覆盖。

导入第N期只证明该来源内容，不推定前面全部已还。实际付款分配和明确人工确认才能形成相应进度；单期确认只影响该期，批量“确认已还至N期”显式说明范围及不新增流水。缺凭据不直接标逾期，未还/部分未还异常保留。

预计全期成本、已记费用（其中方案未核对）、真实付款与确认剩余本金在一页说明。信用卡整单还款不能整额重复关联多笔分期。提前结清取消未来计划非虚构退款；删除/归档停止后续自动记费但保留真实账目，删除方案费不被自动复活，重建不重复记费。

当前代码尚无上述自动记费/漏月同步，仍存在来源期号推算已还。实施与L01～L18验收统一看[改造方案](贷款与分期改造方案.md)，不能仅修改需求就标已完成。

### 3.5 隐私与恢复

凭据、原始账单不进仓库/普通日志/聊天，外部分享由用户触发。本机快照只加速，未知结果保留原请求核实；退出、切页面、清缓存不代表事务回滚。

个人导出覆盖受支持结构化关系；隔离库恢复不等于生产恢复功能。本版无账户注销及其专属云清除流程。新授权与费用关系落地时必须同步导出和最小权限。

## 4. 非本轮方向

未来资金情景、可选AI、复式分录或影子双写不因本轮新增授权记费而启动。固定方案记费是确定性规则，不需要决策模型或新的通用工作流。

## 5. 验收

按[业务规则与验收](招财猫记账本业务规则与验收.md)选择用例，在实施规划维护证据。界面可操作不等于账务正确，CI通过不等于真机通过。目标与当前差异明确写在相应章节，不顶部追加覆盖式说明。
