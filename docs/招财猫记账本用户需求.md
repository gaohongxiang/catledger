# 用户需求与产品范围

> 本文只定义用户要完成什么，不记录某次部署、测试数量或模型交接。现有运行逻辑见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，当前完成与待验收状态见[实施规划](招财猫记账本实施规划.md)。整理基线为 `b804bfc4`；旧需求全文保存在[归档](归档/README.md)。

## 1. 为谁解决什么问题

用户定期获得银行、支付宝、微信支付账单，希望少做重复手工记账，同时能核对资金从哪里来、到哪里去，查看收支、负债与分期。系统应该自动处理证据充分的情况，把真正缺信息或冲突的项目集中交给用户。

目标不是“每行都自动猜一个结果”，而是“可解释地整理、少重复操作、不重复记钱、失败可恢复”。系统不代付、不转账、不投资、不借款；也不以模型预测替代真实资金记录。

## 2. 核心用户旅程

| 用户目标 | 应有体验 | 不能发生 |
| --- | --- | --- |
| 打开自己的账本 | 识别既有身份，首次需要时设置资料；原操作可在登录后继续 | 未确认身份先显示别人的缓存；取消登录仍写入 |
| 导入多份账单 | 逐文件显示进度与错误，成功文件继续，失败文件原位重试 | 一份失败清空全部；文件上传就被算入余额 |
| 确认账户 | 已知归属复用；未知明确询问；真实账户与支付平台分开 | 默认创建不明账户；组合名称被当作虚构账户 |
| 核对有歧义记录 | 看得见相关原文、候选和处理范围；保存后继续 | 仅凭金额相似吞掉记录；隐藏证据强迫猜测 |
| 完成入账 | 确认所选范围，一次提交；重复点击或网络重试不重复入账 | 半批成功、结果丢失后再扣一次 |
| 手工记录或维护 | 金额、账户、日期、类型明确；失败保留输入 | 用缓存推断写成功；编辑导入原文不留关系 |
| 查看分期 | 一笔分期一张逐期表，预计成本与已发生费用分开 | 同份本金记两次；缺凭据直接断言逾期 |
| 导出个人数据 | 一致版本、可追溯、由用户主动分享 | 半文件当完整；自动发送到外部 |

## 3. 当前产品边界

### 3.1 入口和账户

实际导航为首页、明细、统计、我的及中央记账入口。中央菜单选择“账单导入”或“记一笔”；账户、分类、贷款有独立页面。以 [app.json](../miniprogram/app.json) 和[自定义导航](../miniprogram/custom-tab-bar/index.js)为准，旧底栏方案仅供历史追溯。

首版人民币账本支持现金、银行卡、平台钱包、信用账户等资产/负债类型。创建账户的期初余额或欠款用独立调整表示；负债的账单日、还款日和信用额度可选填、修改、清空，未填不当成零。停用账户保留历史，不允许继续新增/编辑普通交易；删除既有记录仍受账务约束。

分类最多两级，一级与二级都可以记账；支持同级排序、停用及恢复。父级固定，历史数据不因分类停用被删掉。未分类允许后补，与资金性质不明是两回事。

### 3.2 导入与原始证据

支持范围由现有解析器和已测试模板确定，银行 CSV/XLS/XLSX 并不意味着所有银行格式都能自动识别。含义不明的列、方向、币种、日期或资金组成必须留下问题；用户可以明确排除，但不能借此把整份文件改标为完整识别。

不同来源的同笔资金活动允许共存为证据，只记应有的正式交易。仅金额、时间、文本接近不能自动合并。原始列和值可在核对时直接查看，空值、零和额外列不被删去。退款只有明确、唯一的强证据才自动关联；无合适候选可保留待关联退款，到账与统计关系分开处理。

本人转账区分转出、转入账户；组合支付和合并还款先确认真实账户，再确认已有模型支持的金额分配。没有本息费构成，不推测贷款拆分。用户的明确决定不能被后续系统重算静默覆盖。

### 3.3 正式账本、查询和维护

正式交易影响余额、收支和净值，原始来源、计划、预览不直接计入。明细支持月份/日期、账户、分类、来源、备注及导入批次范围筛选；全选必须覆盖当前筛选范围的全部可选记录，而非仅当前页。

手工与导入账目可混选删除，受版本、退款、贷款和现金余额保护；整组成功或失败，不跳过冲突。删除保留必要来源及审计。导入交易的普通编辑主要修改分类；历史后台更正/撤销接口存在，不等于旧维护页仍对用户开放。

### 3.4 贷款与分期

当前分期产品口径是“一笔记录、一张逐期表”。创建保存完整方案和成本，后续账单或明确手动确认更新对应期次。本金、利息、费用和真实还款分别处理，不重复建立同一笔负债。

导入第 N 期并有效关联，或用户确认到第 N 期，形成连续进度；缺单期来源不自动等于未还或逾期。明确未还/部分未还异常不得被后续期号掩盖。点期次查看来源、补充缺失费用或调整计划；“显示更多”追加内容，不丢已展开记录。

删除分期只归档管理记录并解除来源/编号关系，原账目和来源保留，可重新建立。普通旧贷款兼容实际借还、计划和整组维护，不因为界面合并就自动对账。

### 3.5 隐私和恢复

凭据和原始账单不进入普通日志、仓库或聊天。外部分享必须由用户触发。本机快照只是加速，写入结果未知时保留原请求核实；退出、切页面和缓存清理不能等同于服务端操作回滚。

个人导出覆盖受支持的结构化数据和关系；隔离库恢复测试不是生产恢复功能。本版不提供账户注销及其专属云端清除流程。

## 4. 尚未成为当前能力的方向

未来资金状态、付款承诺、安全线、情景测算、可选 AI 解释或决策建议，以及复式分录/影子双写等，保留为候选研究方向。它们不出现在当前功能完成清单，不为其提前增加空壳接口或数据表。是否启动需独立明确收益、边界与授权。

## 5. 需求怎样验收

界面可操作不等于账务正确；自动化通过不等于真机通过。按[业务规则与验收](招财猫记账本业务规则与验收.md)选择相关用例，再在实施规划记录精确版本与未完成项。产品行为改变时原位更新本文件相应章节，不再在顶部追加“最新口径”覆盖旧正文。
