# 用户需求与产品范围

> 本文定义用户要完成什么，不记录部署日志或测试数量。流程见[项目逻辑说明](招财猫记账本入账逻辑说明.md)，状态见[实施规划](招财猫记账本实施规划.md)。旧需求全文保存在[归档](归档/README.md)；第3.4节对应本轮贷款改造，开发验证与上线状态分别记录。

## 1. 为谁解决什么问题

用户不定期获得银行、支付宝、微信支付账单，希望少做重复录入，也能理解资金变化、收支、负债与分期。系统自动处理证据充分或已获明确授权的正常事项，只把缺失和冲突集中询问。

目标是可解释、少操作、不重复记钱、失败能恢复，不是每行都猜一个结果。系统不代付、转账、投资或借款，模型不能替代真实资金记录。没有每个月的文件不应阻止管理贷款。

## 2. 核心用户旅程

| 用户目标 | 应有体验 | 不能发生 |
| --- | --- | --- |
| 打开自己的账本 | 识别身份，原动作在登录后继续 | 先显示别人的缓存，取消仍写入 |
| 导入多文件 | 独立进度、单项失败重试 | 一份失败清空全部，上传即计余额 |
| 确认账户 | 已知复用，未知询问 | 默认不明账户，把合并名称当真账户 |
| 核对歧义 | 原文可见，候选与影响范围明确 | 同额吞并，隐藏证据强迫猜测 |
| 完成入账 | 一次确认，整批原子，原请求恢复 | 半批成功，重试重复扣款 |
| 手工维护 | 必需金额/账户/时间明确，失败留输入 | 缓存推断成功，来源改写无痕 |
| 管理贷款/分期 | 一笔一张表，完整计划一次建立，漏月有方案可继续 | 每期重复录入、重复计费、有后期账单即已还 |
| 导出数据 | 一致版本，用户主动分享 | 半文件当完整，自动外发 |

## 3. 产品边界

### 3.1 入口和账户

当前导航为首页、明细、统计、我的及中央记账，菜单选择导入或记一笔；账户、分类、贷款为独立页面。以[实际路由](../miniprogram/app.json)和[自定义导航](../miniprogram/custom-tab-bar/index.js)为准。

首页大卡片展示全账本总览，不显示月份或月份切换：当前净资产取全部账户账面余额，累计收入、累计支出取所有已入账的有效交易。首页不再并列显示累计结余，避免把收支差误认为当前余额；按月收支及结余在统计页查看。

人民币账本支持现金、银行卡、平台钱包、信用账户等资产/负债。期初余额或欠款用独立调整；账单日、还款日、信用额度可未填、修改、清空，不显示假零。停用保留历史并说明余额及贷款操作限制；停用账户详情可恢复原账户继续使用，不补造交易、改本金或开启记费。重名先处理冲突，不覆盖其他账户。历史删除仍受账务保护。

分类最多两级，父级固定，同级排序、停用恢复，一级/二级都可记账。常用生活用途直接作为大类，各类使用能辨认用途的线条图标。餐饮细分美食、饮品、水果零食；自动分类优先具体商品与用途证据，不能用宽泛历史记忆盖过细类或仅凭平台名猜测。混合用途可保留大类或待分类，人工选择和已入账记录保持。未分类可后补，不等于资金性质不明也能入账。

### 3.2 导入与证据

支持格式由解析器与已测试模板界定，不等于所有银行表格都能自动识别。列、方向、币种、日期或组成不明留下问题；排除不把整份文件变完整识别。

多来源同笔保留证据，只记应有交易。同额、同日、相似文字不能自动合并。核对直接看原始列和值，保留空值/零和额外列；强且唯一的退款证据才自动关联，无候选可待关联，到账与统计关系分开。

整理账目各页签及翻页都按日期从早到晚，一组多笔以最早真实成员排序，组内同样按日期排列；未知日期放最后。交易核对和分类都可按商户、交易描述、分类名称或交易日期搜索当前页签的整批记录，支持年月日、年月和月日；搜索不改变整批数量或决定范围。已分类显示实际分类名称，二级分类带父类名称；用户可逐笔修改，使用分类管理中的同类一级或二级分类，手工选择优先于自动识别。核对页签依次为待核对、已核对、重复交易、已排除；已核对与重复交易列表统一显示“查看”，详情直接展开多份原始交易并可修改同笔判断。已排除也能打开原文，排除分组可展开。银行与微信/支付宝即使摘要不同，也应在账户、金额、方向、明确时间及支付渠道吻合时提示同笔候选；完整范围内双方唯一的建议集中预览，一次确认全部并可取消跨页例外，逐笔判断每次展示具体两条，在底部直接点“不是同一笔／是同一笔”保存，拒绝一对不影响其他关系。入账前选错可修改：重复来源可恢复多笔，确认不同笔可重新合并，误关联历史账目可返回核对；保留原文与人工字段，未决事项继续核对，同身份重复不能伪造新交易。确认只保存本批草稿，历史已记账另选已有交易，最终整批入账才影响余额。候选与已确认重复分开计数，具体可靠来源决定和退款关系保留。

正常启动自动进入账本，只保留简洁加载，不展示连接、休眠等技术说明或增加进入确认；失败后可直接重试。身份确认后尽早展示正确归属的首页快照并标明更新状态，费用同步继续执行。核对弹窗先反馈、原文自动补齐；必需数据未齐不能确认，局部失败可重试，输入与跨页选择不被后台更新覆盖。大范围分批保存准确显示已保存及待核实进度，响应丢失沿原请求恢复。

本人转账有两个资金端点，组合支付/还款先认真实账户再认组成；缺本息费不猜拆分。用户决定不被系统重算静默覆盖。首次整理失联恢复原请求和原批次，成功后读取失败只提示结果待刷新。已识别关闭/退款矛盾不得以待关联绕过；未知状态当前可看原文或排除，扩展资金确认仍需模板证据。贷款来源区分计划、出账、计费与实付，详见3.4。

### 3.3 正式账本、查询与维护

有效正式交易产生记账余额与收支，计划和预览不直接计入。明细组合月份/日期、账户、分类、来源、备注与导入范围；全选覆盖完整可选范围。

普通手工与导入账目单笔或混选删除只确认一次，永久移除正式交易；有版本、完整退款组、同源付款分配组、贷款/费用历史及现金保护，整组成功或失败。没有回收站、恢复或永久忽略名单，误删可重新添加或主动重导；重导继续核对与有效交易防重。删除成功但刷新失败明确提示“已删除，列表待刷新”。导入普通编辑主要改分类，后台系统更正/替换/撤销仍保留原历史，不等于旧维护页开放。方案费用也受这些保护；删除抑制、差额更正和真实退费从贷款详情确认。

### 3.4 贷款与分期

**一笔分期、一张逐期表，勾选已还后保存，同时记好该期利息和手续费。** 不要求每期上传，也不要求先设置自动记费或另做历史授权。

首次从第6期账单建立分期，账单直接放到第6期；列出第1～6期，默认勾选已还，用户可取消。保存就是提交选择，不再弹第二次确认。已有身份明确的同费直接复用；独立手工费用由用户在逐期预览明确选用，推荐不自动合并，支持查找跨月原账；缺失费用记入各自原月份，归属导入时选定的信用卡/贷款账户。历史补记保留当前已确认余额，不补造银行卡扣款。

后来导入第8期，询问第7期及尚未选择的第8期是否已还；明确选过未还或部分还款的不重复询问。以后不导入，就直接点期次列表的“记本期还款”，选实际付款账户、日期和金额，保存时一并处理本息费。付款账户沿用这笔贷款上次实际付款账户，没有记录时由用户选择；费用仍属于对应贷款账户。已经记过的扣款可选已有账目，不能再扣一次。

默认勾选和页面读取本身不写账。旧记录也不在升级时自动补息，打开后列出需补记的已还期次，用户可修改后一次保存。新流程不自动记未来费用；此前已生效的自动设置保留停止入口，显式保存新的已还选择时停止旧自动设置。

整笔贷款／分期删除只确认一次，展示实际撤销数量。撤销计划独占新增且没有有效银行来源认领的账及成对余额校正；原有账、银行已认领账和更正后的正确账保留。共享付款、外部退款或归属不明整次阻止并指向原业务处理。保留账仍可维护和关联；重建用新ID，原付款不再扣钱，单独取消费用不自动复活。删除成功但刷新失败明确提示已删除。

管理只保留编辑资料与删除记录；已记付款从对应期次查看，无独立记录页签。差额、退款和一次实收覆盖等特殊情况在该期费用里处理；本金、原始账单、收费身份、实际付款和退款保护保持独立，不能凭金额相同合并。阶段与验证状态见[实施规划](招财猫记账本实施规划.md)，兼容旧费用功能及 L01～L18 见[方案](贷款与分期改造方案.md)。

### 3.5 隐私与恢复

凭据、原始账单不进仓库/普通日志/聊天，外部分享由用户触发。本机快照只加速，未知结果保留原请求核实；退出、切页面、清缓存不代表事务回滚。

个人导出覆盖受支持结构化关系；隔离库恢复不等于生产恢复功能。本版无账户注销及其专属云清除流程。授权、费用身份、账单来源、付款分配和审计均纳入导出与最小权限。

## 4. 非本轮方向

未来资金情景、可选AI、复式分录或影子双写不因本轮新增授权记费而启动。固定方案记费是确定性规则，不需要决策模型或新的通用工作流。
