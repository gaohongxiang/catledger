# MINI-1906UI：第一版视觉落地

基线 main@1b37788ced1b3ca4cdf4f8a9275bc94db2ec6f62。使用用户选定的第一版视觉及六张现状截图，不重新选风格；参考图数据与品牌图标不视为业务事实。状态与负责人以实施规划看板为准。

## 范围与验收

1. 首页沿用已交付样板：常规正文、中等标题、自然字距、完整金额和轻卡片。仅暖橘净值卡允许轻微渐变，其他主题配色保留。
2. 文件阶段每种状态只有一个主动作；解析完成不再显示过期的开始解析和添加提示。失败重试、继续添加、返回恢复沿用现有处理器。
3. 账户以结果卡片呈现，新建时处理方式、可编辑名称和账户类型保持三项同一行，以两条细分隔线区分；左侧仅小面积陶橘强调，右侧白底，类型可在本格内换行但控件不纵向堆叠；建议与确认分开，不以展示调整自动确认账户。
4. 核对与分类保留为不同维度；数量明细可展开，排除、重复、未知和原文入口不隐藏。
5. 组合付款弹层优先展示总金额、用途、账户金额及核对说明；所有金额计算、零金额规则、必填项、事务和提交门禁不变。
6. 本期不改后端、API、数据库、身份、关系推断或来源语义，不新增运行时 UI 依赖。

## 实施

- 首页使用之前的补丁作为起点，复核后集成到本次分支。
- 在原 WXML/WXSS 内调整展示；只新增一个维护本地展开状态的 record-summary 组件；不修改 Page 业务控制器，不新增业务状态机。
- 先建立回归测试，再实现文件状态互斥、保留绑定、账户确认口径及金额输入。
- 实际 WXML/WXSS 的浏览器映射只用于视觉候选检查，不能代替微信开发者工具、键盘及 iOS/Android 真机验证。
- 提交到独立分支供审查，不自动合并或部署。

## 当前验证与回退边界

- 本地 Node 22：根目录 166 项通过，包含新增首页 14 项和导入展示 12 项；`npm run check` 与 `git diff --check` 通过。
- 导入页面真实 WXML/WXSS 的浏览器映射：6 主题 × 4 宽度 × 11 种虚构数据状态，共 264 场景，横向溢出及选定按钮可用性断言通过。这不是原生控件/真实上传/真机验收。
- 隔离源码由固定 SHA 的工作区快照恢复；本地未包含历史 V1 提交。原有 `compare-bills` 历史差分测试在该浅工作区无法解析历史提交，未修改或跳过该测试。完整 Node 18 / MySQL 8.4 验证由保留完整 Git 历史的 PR CI 执行；是否通过以远端实际记录为准。
- 未运行微信开发者工具、iOS/Android 真机、原生输入法及实际财务写操作。阶段保持待验收；不得自动合并、上传体验版或部署。
- 回退只涉及本批小程序展示、组件、测试和文档，不需要数据迁移；全局六主题 registry、API、资金计算与全部云函数不变。
