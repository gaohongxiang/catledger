# MINI-1906 财务信息闭环设计

## 领域边界

`SourceEvidence -> EconomicEvent -> ReviewIssue -> Transaction` 仍是唯一导入主链。分类被提升为经济事件的必备业务字段：确定性规则和用户历史映射可以自动填充；其余事件由 `category_assignment` 问题批量确认。账户归属解决资金落点，分类解决收支用途，两者互不覆盖。

退款交易自身不复制分类。报表通过 `original_transaction_id` 读取原消费分类并做负向冲减，因此后续补改原消费分类会即时反映到退款净额。

## 服务边界

- `catledger-import`：生成/处理分类问题；在整批 posting 事务中提升来源分类映射。
- `catledger-api`：提供正式账本的统计维度和已入账未分类交易批量补全；所有写入按用户、交易版本和分类性质校验。
- 小程序：只展示服务端冻结的成员和汇总，不在客户端扩大批量修改范围。

## 接口

- `statistics.get` 增加 `cashFlowTrend`、`metrics`、`uncategorized`；保留现有字段兼容旧客户端。
- `categories.unclassified` 返回当月未分类收入/支出分组及成员版本。
- `categories.assignTransactions` 原子地为一个冻结请求中的交易写入同性质分类；失败整体回滚。

## 界面

- 导入最终确认：财务摘要在前，技术审计折叠在后；入账成功后提供明细、分类补全、余额校正和统计入口。
- 统计：六个月双序列趋势、每日收支双柱、分类结构排行、未分类行动提示。
- 账户：页首三项财务汇总，整行账户入口，异常余额状态，详情层内放管理动作，停用账户默认收起。

## 验证

先分别用最小测试证明：空分类仍可 ready、退款分类 SQL 使用退款自身分类、统计缺少趋势/指标、账户操作常驻。修复后重跑同一测试，再执行两云函数全量测试、根目录契约/UI 测试、WXML/WXSS/JS 编译与生产依赖审计。
