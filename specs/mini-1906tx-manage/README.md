# MINI-1906TX-MANAGE：导入记录、撤销再导入与手动批量删除

状态：待验收。基线 main `66f3e16f`；当前主会话串行负责 API、导入服务、共享接口、客户端、测试和文档，无并行文件所有者。分支 `codex/mini-1906tx-manage`；用户授权加上导入管理及手动多选删除，并沿用本会话更新授权。无新表、迁移或云资源。

## 设计

1. 用途：明细中一次删除多笔手动账目；导入历史中选定某次导入，核对影响后撤销，再选择原文件导入。
2. 视觉：沿用现有暖色编辑式账本；不改变原筛选行和搜索位置。色板 #faf8f4、#ffffff、#29231e、#746a60、#d97732；危险文字沿用 #a95132，所有主题使用既有 token。
3. 字体：PingFang SC / Source Han Sans SC / Noto Sans CJK SC；正文 28rpx、辅助 24rpx、按钮 26rpx，最小触控 88rpx；继承既有设计系统，不增加字体或图标依赖。
4. 布局：列表左侧选择圈与右侧完整金额形成非对称信息层级；顶部筛选后有管理行，选择工具条随滚动固定。导入记录左侧文件和时间，右侧状态；撤销详情列出删除数、复用数、账户变化和关联阻断，不向用户展示内部身份术语。

## 契约

- `transactions.deleteMany`：requestId + 1..100 个唯一 transactionId/version。可信 uid、用户锁、同一事务内验证手动来源、类型、版本、贷款、组外退款和合计现金变化。停用账户可删除；原消费及退款可同组删除；成功统一软删除、递增版本/账本修订并保存回执。错误整组回滚；同键并发和响应丢失只能完成一次。
- 明细选择仅限已加载手动记录，最多100笔；加载下一页保留选中，换查询/刷新/退出页面清空选择。确认框冻结所选 ID 和版本。缓存失效覆盖交易、账户、首页和统计。
- `financeUpdates.list`：当前用户 posted/undone 历史，createdAt/updateId 倒序的签名游标，默认20、最多40；只返回导入摘要与最多5个文件名，不返回原始账单行。
- `financeUpdates.undoImpact/undo`：只删本次 created，保留 reused。当前版本进入 previewToken；更改过分类的记录可先重新预览再撤销，预览后的任何变化拒绝旧令牌。退款、贷款、现金、旧批次缺审计及账户/映射保留规则继续有效。
- 已 committed 的同字节文件：无任何活动 FinanceUpdate 且有 undone 历史时，重新开放已有解析批次；原文件哈希、来源身份、原始行及旧更新全部保留，新的整理/入账生成新的 FinanceUpdate。仍在入账的文件保持重复保护。重复上传复用唯一文件，新上传冗余副本按既有策略清理。
- 新删除/撤销使用 pending-ledger-write 的 exact 模式；不同在途操作只查回执，不因当前确认重发另一组。已完成旧操作清理后可执行当前选择；未确认则返回原操作处理。没有实际在途请求时不查询或显示恢复提示。
