# MINI-1906UI2：第一版视觉落地

状态：待验收。基线 `main@1b37788ced1b3ca4cdf4f8a9275bc94db2ec6f62`；任务分支 `codex/mini-1906ui-warm-refinement`。本目录承接先前首页补丁，不另建视觉体系。

## 已确认需求

采用用户选定的第一版视觉：清秀字感、自然字距、白色轻卡片、暖橘局部强调。原六张用户截图是主线现状。生成图里的金额、总资产标签、正负号和操作状态只作占位，不能代替真实业务规则。

范围为首页、首页选中时的底栏、导入工作台及核对弹层。现有六主题保留，主题 registry 不改。只有首页和导入页的暖橘表面使用局部变量；其他主题沿用自己的配色。不得增加跨端框架、字体下载或前端依赖。

## 页面与实现边界

- 首页：WXML/WXSS 调整，页面 JS、登录/刷新/跳转、净值口径和图表输入保持不变。标题 500、正文 400；金额不强制 DIN 窄体。月度任一金额超过 12 字符时改纵向卡片，保留原字符串。
- 文件：未选文件只显示一个选择入口；队列非空或上传中才显示解析按钮；全部队列已处理后显示结果与确认账户入口。单文件失败、独立重试、已入账防重和成功文件可继续沿用原逻辑。
- 账户：展示建议、已选择、已保存、历史排除的区别；新建名称和类型纵向排列，仍使用原有输入事件及批次保存动作。已匹配不等于已确认。
- 整理：核对和分类分别计数，数量等式可展开；全部、排除、重复数量持续可见，不改分类可跳过政策或未知门禁。
- 付款：总额与金额差额在上方，组成金额可编辑；必填说明改为有标签的多行输入。同层来源证据在付款问题中可展开，其他问题仍直接显示。保留分页和失败重试。
- “全部分配”仍调用原函数把总额放到选中项，其他项置零/清空；不改称“填入剩余”。两账户整数差额联动、只确认账户场景、零金额组成、资金性质和目标账户限制不变。

仅新增 `recordSummaryExpanded`、`issueSourceExpanded` 展示开关和已有验证结果的说明字段；不改变财务算法、请求体、请求幂等、后端、公共接口、数据库迁移、用户身份和正式入账事务。

## 验收条件

1. 当解析队列为空且文件已处理时，不再出现“开始解析”或“添加后可开始”；成功文件可继续，全部失败时继续按钮禁用。
2. 当用户只展开数量或来源时，不产生服务请求、不保存决定；已排除的未知记录不因此提高完整度。
3. 当组合金额已平但缺必填依据、付款账户重复、目标无效或金额超额时，保存仍禁用，并说明需要核对；有效性只来自已有 model。
4. 当付款只需确认账户时，不展示金额及说明输入，不改变该场景的原门禁。
5. 当资金未知、仍有阻塞问题或服务端尚未允许提交时，“确认整批入账”仍禁用。
6. 返回、账户选择、原始证据、付款用途、退款、聚合还款、分类和整批维护入口保留；没有创建新路由或替代真实数据。
7. 六主题及窄屏下没有横向溢出；长金额、负号、小数和长账户名可读取；原生键盘与安全区必须另行实机验收。
