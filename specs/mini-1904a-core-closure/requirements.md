# MINI-1904A 需求：核心账本收口

## 1. 目标与范围

在不改变“首页 / 明细 / 中央记账 / 账本 / 我的”信息架构的前提下，补齐分类真正可管理、退款关联原消费、受保护页面统一登录体验，并移除“我的”中的重复账本入口。同步形成依赖风险处置结论。

本任务不实现账单导入、数据导出、用户注销、正式上传审核或发布；这些仍分别属于 MINI-1905～1907。

## 2. 用户故事与验收

### R1 分类管理

- 当已登录用户进入分类管理时，系统应分别显示活动和已停用的支出/收入分类。
- 当用户新建或改名分类时，系统应规范化名称，并在同一用户、同一收支方向内拒绝活动重名。
- 当用户调整分类顺序时，系统应在一个事务中保存完整顺序，重复请求不得造成重复副作用。
- 当用户停用分类时，系统应保留历史交易；已停用分类不得用于新交易，但允许重新启用。
- 当并发修改同一分类时，系统应使用版本号拒绝静默覆盖。

### R2 退款

- 当用户记录退款时，系统应要求选择一笔未删除的原支出、退款入账账户、金额和时间。
- 当退款成功时，账户余额应增加，本月支出及原支出分类金额应按退款净额减少，收入不得增加。
- 当累计有效退款超过原支出金额时，系统应拒绝整个写入并回滚。
- 当原支出已有退款时，系统应禁止把它改成其他类型、把金额改到低于累计退款额或直接删除。
- 当退款被修改或软删除时，余额和所有统计应同步恢复正确口径。

### R3 登录与信息架构

- 当未登录用户直接进入记账、账户、分类或个人统计子页面时，系统应显示同一登录面板；登录成功后留在当前页面继续原操作。
- 未登录浏览不得调用个人业务接口，也不得创建内部用户或默认分类。
- “我的”页面不得再显示“账本设置”；账户与分类只从一级“账本”进入。

### R4 安全与质量

- 所有分类、退款查询和唯一约束必须包含服务端 `uid`，客户端身份字段继续被拒绝。
- 所有写操作必须支持请求幂等；修改、停用、恢复和排序必须处理并发冲突。
- 迁移必须连续、forward-only、可重入；自动测试覆盖事务回滚、跨用户隔离和退款净额统计。
- 上线前必须记录 `wx-server-sdk` 传递依赖风险的可达性和处置，不盲目采用不兼容降级。
