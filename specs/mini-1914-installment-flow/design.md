# 实现设计

用户已于 2026-09-23 明确要求实现。沿用既有微信身份、MySQL 用户锁事务、幂等回执和来源证据，独立工作目录 codex/mini1914-installment-flow 包含当前主目录未提交基线，回交时只同步本任务增量。

- 分期方案仍由既有贷款与计划引擎维护；新增进度及单期例外，不用伪造还款交易来标灰。完整表同时兼容原已保存计划修订与旧实际付款分配。
- 新迁移 0024 为贷款增加进度/归档字段；分期来源明细保留银行本金、利息和费用的独立行，按用户、账户、明确分期编号绑定贷款。来源身份和实际费用各有独立唯一约束，避免重复导入及手动后导入的重复支出。
- 银行映射增加明确分期字段，同时识别受限的分期类型、编号和期号文案。本金属于账单的分期明细，不制造第二笔消费或银行卡扣款；利息/费用沿用正式 expense。无法唯一归属时进入待建立分期，允许后续关联。
- API 提供完整分期视图、期次详情/来源、进度与本期补记、待关联来源及关联/归档。创建资料时可同事务接收来源，不产生保存成功但关联失败的半成品。所有写入接受版本与幂等键。
- 所属账户位于详情最上方；“修改已完成期数”以浅绿 mini 按钮紧跟“逐期还款”标题同排展示，宽随文字、44rpx 高。保存成功显示 1.5 秒原生轻提示，顶部不常驻成功卡片，失败与重试入口保留。逐期表首次取 20 期，居中“显示更多”逐批向下追加；移除页码与前后分页，保留展开内容，全部展开后隐藏按钮。失败、重复点击、版本冲突及重新读取后的迟到响应均有保护。
- 详情直接点击期次补充或查看来源，进度可一次更新；移除三个旧入口。旧付款的维护链接只出现在该期来源内。分期列表显示待建立来源，手动新建与从来源新建汇入同一表单。
- 界面用途为查看并维护一笔分期；沿用用户截图的浅绿账单布局、#F1F6F3/#FBFDFC/#173A30/#A94B40，PingFang SC 与 DIN Alternate 数字、30rpx 卡片和四列逐期表；当前期用窄绿边，完成期变灰，缺失提示贴在该期日期下。补充表单采用原生底部面板，金额自动带入，不引入新的管理导航。
- 验证覆盖解析字段、同一期分行、连续进度、缺记录与明确异常、来源晚建、手动/导入交错、防重复、版本冲突、用户隔离、删除恢复、原子回滚、旧记录兼容以及原生交互。只使用合成账单写入隔离库。

新增原生入口：`pages/installment-sources/index` 展示待归属的信用卡分期账单，可新建或归入既有分期；`pages/loan-detail/installment-sheet.wxml` 承载逐期维护。
