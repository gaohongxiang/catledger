## 实际行为

- 新建或从信用卡账单补建同一分期；银行明确分开的本金、利息、手续费及期号保留为来源，可先入账后建立分期。未知原本金和首次日期不从单期金额猜测。
- 完整方案、总本金、全期预计成本创建后即可查看。有效第 N 期来源或手动确认至 N 将前 N 期标灰；不伪造历史流水。第 11 期缺记录只提示补充，明确未还/部分未还保留异常。
- 信用卡分期本金不重新记消费/欠款；实际整单还款仍是转账。费用入账按银行明细或明确手动补记，每期每种费用只记一次，之后的银行来源可复用。不同银行来源身份和金额冲突不会自动吞并。
- 详情沿用用户参考的浅绿信息卡、总成本卡和四列逐期表。点期次直接查看来源、确认进度、补记缺失费用和调整本期；正常分期移除三个独立入口。底部保留编辑记录信息、删除记录；删除归档管理记录并解除来源/编号关系，保留原账单与金额，可重新建立或关联。
- 无完整分期方案的旧普通借款保留原借还维护；旧付款可从期次来源定位。来源撤销、费用删除/修改后回读有效进度并失效相关缓存。

## 契约和数据

`0024_installment_tracking.sql` 增加贷款进度/归档字段以及分期身份绑定、分项来源表，用户范围外键和唯一约束覆盖同来源及同一期的有效费用。运行角色权限与导出同步，导出 schemaVersion=25；0025 仅修复旧归档关系。7 个分期 API 的参数、分页、版本和幂等规则在 `shared/catledger-api.json`；银行 statementKind/字段映射在 `shared/catledger-import.json`。银行 profile/policy v2、adapter/parser/normalization v3。服务端验证信用账户后才启用本金明细分支，普通银行贷款本金仍保留原现金流语义。

费用、来源、进度、版本及回执在既有可信用户锁事务内处理。关联失败回滚整个操作，包括从来源新建资料；手动费用被导入复用后禁止单独撤销。导入来源撤销通过既有账单维护；不改原始银行字段。两函数独立打包相同 installment-items 规则，工程检查防止漂移。
