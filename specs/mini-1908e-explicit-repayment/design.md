# 契约与实现

使用现有实际借还主表及交易成员作为财务分组；增加 `catledger_loan_repayment_details`，记录用户确认的负债账户、本息费及处理方式。已确认实际还款允许暂时没有贷款分配；不另造转账候选队列。pending = active 实际还款 + 确认明细 + 无贷款分配。历史数据不回填。

新增 API `loans.bookRepayment`、`loans.assignRepayment`、`loans.releaseRepayment`。手动入账与确认/立即分配同事务；以后分配要求付款版本和贷款版本，核对负债账户、本金基线和整条本金时间线。解除待办只撤销贷款管理确认，保留已入账流水。正式财务分组不能单独编辑成员。

新增导入命令 `financeUpdates.setRepayment`：只修改 review 状态下指定版本事件的用户决定。普通转账/明确借款还款可切换；不覆盖原始证据。入账拆分本金转账、利息/费用支出，或已计负债的费用随本金转账。已选贷款的分配与整批入账同事务，版本冲突不降级为暂不关联。

API 与导入包共用相同的独立还款领域模块（随各函数打包，检查内容一致），不跨部署包 require。源事件和交易关系沿用现有 source 维护契约；用户锁、幂等回执、金额边界、身份隔离保持现有机制。

## 界面设计

1. 目的：让用户在实际付款入账时明确普通转账或借款还款，只看到可行动的关联待办。
2. 风格与色彩：沿用暖橙手账；米白 #FAF8F4、正文 #2C2823、主操作 #BE5B24；不增加装饰性卡片。
3. 字体：原生 PingFang SC 正文及现有 serif-title 标题；金额沿用 money-number。
4. 布局：复用原生输入和选择行；先账户/实际总额，再本息费，再贷款关系，最后明确确认。导入明细提供设置入口；贷款首页仅在 count > 0 显示“待关联还款 · N 笔”。
