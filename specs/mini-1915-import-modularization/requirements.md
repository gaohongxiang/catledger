# MINI-1915 一期验收要求

当前状态与验证见 [实施规划](../../docs/招财猫记账本实施规划.md)。一期包含导入模块化、文档收敛、相关测试整理和缓存测量/条件性简化，不是重写整个项目。范围见 [README](README.md)，操作边界见 [design](design.md)，步骤见 [tasks](tasks.md)。

## R1. 业务行为等价

- 相同来源、账户目录、已入账记录和人工决定，应产生相同的有效事件、核对问题、来源归属、关系、分类、金额和入账结果。
- 保持同来源重复、身份冲突、同额独立、历史疑似重复、人工确认的分支和优先级；不能靠金额、时间或文本相近自动合并。
- 保持银行分期本金、利息和费用的语义：本金不重复记消费、费用防重、来源晚关联和分期进度不漂移。
- 来源明确值、持久映射、本批决定和人工字段保留原优先级；规则歧义登记差异，不顺手统一。
- 事件保存保留引用校验、关系上下文、可入账判断、原因、事件版本和操作来源；保留 saveEvent/saveEvents 差异及旧计划 preserveReferences、actionSource: 'semantic' 路径。
- refreshAccountGroups 保留旧引用展开、问题/成员/映射更新及无候选时的无业务变更路径；不为刷新无条件新增行动或递增批次版本。

## R2. 事务、身份与副作用

- 使用既有服务端可信身份、原事务入口和同一连接；不信任客户端 uid。子模块不新开事务、不独立提交、不把写入移出事务。
- 保留各操作自己的锁获取顺序、版本检查位置、拒绝条件、行动与事件/问题/映射/关系写入次序、完整回滚和幂等回执；不为统一外观重排。
- recalculateUpdateCounts 的“历史同步 → 草稿可达性 → 计数与批次版本更新”是有副作用的步骤，不是可随意重用的读统计。synchronizeHistoricalReviews 包含失效关联恢复和候选同步，不能只保留同名底层候选函数。
- 批量账户映射保持同一事务、共享映射索引和原一次批次收尾；不退化为逐项网络请求/事务。单项、批量、修订不得互调公开命令来共享事务。
- 正式入账保留整批原子写入、来源唯一约束、锁内历史复查、账户物化、分期费用和交易写入顺序；不重排 finance-update-posting.js 的 SQL。
- 受影响场景覆盖重放、并发、版本过期、历史变更、中途失败、成功响应丢失和用户隔离；已覆盖用例继续复用。

## R3. 公开与存量契约

- 草稿、旧语义计划、已入账批次和本机持久请求沿原流程继续/恢复；不要求清库、删草稿或重新导入。
- 公开 action 集合、请求/响应、错误码、schema、身份键、摘要、游标、规则/计划版本、回执不变。五个工厂方法不等于五个公开 action，不给内部 reviseAccountMapping 新增网络入口。
- 移动内部函数时同提交更新生产消费者和测试，不新增转导出、旧协议 fallback、能力探测或双实现。不得把现有同协议的完整响应恢复误当作旧协议兼容而删除。
- createReviewIssueService 继续作为正式入口。现有内部服务方法的消费者以 P0 清单为准，不在等价拆分中擅自删除或公开它。
- 需要改变业务、存储、缓存一致性语义或公开契约的内容，单列差异与后续范围，不伪装为结构优化；其余可独立验证的工作继续。

## R4. 页面、异步与写入恢复

- 读结果只回填有效用户会话、页面、批次、视图版本及当前问题/弹层；翻页、切项、关闭、隐藏、卸载或退出登录后的失效读取不得回填。
- 写命令事实与渲染分开：页面失效不等于服务端回滚；既有草稿/回执协议确认结果或保留原请求恢复。不得因离开页面丢恢复状态、换 requestId 或再发一笔入账。
- 退出登录保留原隔离/清理规则，旧用户回执不得进入新用户状态，也不得为了保存回执跨用户落盘。
- runtime 只协调生命周期、页面活动 epoch、订阅/释放和共享 UI；import-view-session 管读版本/游标/分页；import-draft-session 管草稿队列、在途请求、幂等键、postFlight。只保留各自必要权威，不复制会话、存储格式或全局 store。
- 编辑时延后后台投影，关闭后按原顺序应用；写成功而摘要失败保留成功事实。过期 finally 不得解除新操作的 busy。
- 原始记录同层直接展示当前页的原始列和值，保留空值、零、重复列、编码语义、单项重试与超长原文入口；不改布局/导航。
- 生命周期、WXML 事件和共享字段有明确 owner；各流程不得暗中清空别人的状态。既有 boundedSetData 只包装一次，保留差异更新及回调。
- P0 发现原实现违反以上不变式时记录复现、影响及独立修复范围，不放宽断言或混入结构提交；影响当前阶段安全的问题未解决，不得宣称该阶段验收通过。

## R5. 减复杂度与依赖边界

- 入口能直接定位事务、场景、规则和存取；core/read/maintenance/semantic-plan-upgrade 不再为公共能力依赖核对总服务。新公共模块不反向依赖命令入口/场景，读路径不调用写收尾。
- 纯规则不依赖 SQL、连接池、微信、存储或服务工厂；可保留原确定性对象修改行为，不为纯函数名义额外深拷贝。
- 每移出一组页面方法就移除对应旧覆盖；过渡清单不得新增冲突或双执行。P4 出口 paged.enhance 为零，生命周期和状态 owner 明确。
- 不按行数/每条 SQL/每个函数拆文件；不创建占位接口、控制器基类、通用容器、插件引擎或纯转发层。薄入口确有公开契约/事务职责时保留，不能因文件短就删除。
- 对代表性账户确认、历史核对和入账恢复路径，提交前后入口、实际处理者和共享状态 owner 对照。至少消除指定的反向依赖和覆盖链；文件变多不算收益，不额外增加无职责的调用跳转。
- 常规 API、贷款模型及两函数部署边界不重做；共享规则一致性保留，禁止跨部署包 require。来源规则默认审计，银行/资金方向改语义不纳入本期。

## R6. 等价证据、资源与交付

- 合成比较保留金额、账户、业务日期、顺序含义、来源/关系、决定、版本和错误码。生成 ID 按实体类别一致一一映射，外键/行动引用跟随映射；不能删 ID 后只比较数量金额。
- 只排除列明的非业务时间等噪声；确定性身份键、摘要、游标和业务时间不删除。优先使用既有测试注入点，不新造运行时框架。
- 保持响应、SQL、setData 和缓存硬预算；同时比较实际 SQL/云请求次数、响应字节、派生计算和 setData 次数。不新增逐事件查询、额外整批扫描或前端全集常驻，不以仍低于预算放过无解释退步。
- 数量/字节等确定性指标原则上不增加；异常有理由也需评估影响。耗时使用同环境可比样本，记录冷/热条件和波动，不能凭一次测量承诺提速。
- 复用现有工程检查、Node 测试和隔离 MySQL；每阶段记录 SHA、通过/失败/跳过、实际差异和回退依赖。后续依赖前项时逆依赖正常 revert，不回滚数据、不删草稿、不强推。
- 代码入口变化同步入账逻辑说明、架构和现行说明；当前状态集中在实施规划。源码、原生工具、云端、体验版、真机分别报告，未执行不算通过。
- 一期内实施/测试/文档/提交/推送沿用户交接授权；没有另行授权不合并 main、不部署、不迁移云数据库、不新增云资源、不上传/审核/发布或操作真实账目。

## R7. 文档和相关测试收敛

- 根 README 与 docs/README 只保留产品定位、稳定结构、启动方法与权威入口，不再各自维护一份当前任务队列、部署版本或测试总数。实施规划是当前状态唯一记录，specs 保留契约、任务与证据链接而不复制整套看板。
- 历史事实明确日期/SHA/历史性质，保留有效链接和审计证据；不能因“精简”删除迁移、已发布记录、验收要求或把猜测写成最新状态。A2/A3 等长期设计标为本期范围外，不擅自永久取消。
- 不要求每次小修同时新建多份模板；只更新受影响契约/入口和必要记录。本期不新增并行状态台账或另一套文档体系。
- 只整理本期触及的测试；删除/合并断言前记录“保护目标 → 已有或新增替代验证”。保留财务、隔离、幂等、回滚、恢复、分页、隐私的正反场景，以及真正保护 UI 布局/可访问性/忙碌禁用的约束。
- 可替换纯粹绑定内部函数位置或源码表达式的重复正则，不能一概删除静态/WXML/样式检查，不能以测试数减少为目标。替代用例先在正确基线上通过，并能捕捉相关行为破坏；不得通过改测试掩盖生产差异。

## R8. 缓存测量与条件性简化

- 必须测量冷/热读取、同参数并发、前台恢复、写后读取、失败写/超时重试和用户切换；沿原 observer/测试替身记录请求、revision/tag 变化、失效与渲染计数，不记录真实账单/绑定值，不新建监控平台。
- 标签承担依赖失效及写屏障，全局 dataRevision 承担跨响应的新旧判断；两者不能因看似重叠就删一套。写前/写后失效、前台验证和必要历史复查不视为可随意省略的重复。
- 只在当前客户端读取链路内消除已证明语义冗余的订阅、调度、派生或刷新；必须说明触发条件、移除内容、前后计数和为何仍满足一致性。保留相同用户/环境隔离、迟到读拒绝、写屏障、force、knownRevision/unchanged、快照恢复、TTL/前台策略及原错误恢复。
- 不修改服务端 revision/公开协议、快照 schema、缓存新鲜度窗口，不增加缓存层/离线库，不绕过 organize/历史核对/锁内复查来减少请求；不为去重吞掉需要渲染的变化或丢失回调。
- 缓存条件项需独立小提交与定向回归，不能混进 P1-A 或页面搬迁。没有等价证据或收益，记录保留原实现；需要新协议/一致性策略/跨端重构，登记后续。测量和判定完成是必做出口，不强制产生缓存代码差异，也不宣称此时已有性能提升。
