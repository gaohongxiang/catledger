# MINI-1915 验收要求

方案已按评审修订；实施状态：**未开始**。以下是结构重构约束，不是新增产品需求。范围见 [计划入口](README.md)，实施顺序见 [任务](tasks.md)，具体边界见 [设计](design.md)。

## R1. 业务行为等价

- 相同来源、账户目录、已入账记录和人工决定，应产生相同的有效事件、核对问题、来源归属、关系、分类、金额和入账结果。
- 保持同来源重复、身份冲突、同额独立、历史疑似重复、人工确认的现行分支和优先级；不能靠金额、时间或文本相近自动合并。
- 保持银行分期本金、利息和费用的现行语义：本金不重复记消费、费用防重、来源晚关联和分期进度不漂移。
- 来源明确值、持久映射、本批决定和人工字段发生交互时保留原优先级；规则歧义登记差异，不顺手统一。
- 事件保存保留引用校验、关系上下文、可入账判断、原因合并、事件版本和操作来源。`saveEvent` 与 `saveEvents` 原有差异不能在搬迁时合并；旧计划的 `preserveReferences` 和 `actionSource: 'semantic'` 路径保留。
- `refreshAccountGroups` 保留旧引用展开、问题/成员/映射更新以及无候选时的无业务变更路径；不能为了“刷新”无条件新增行动或递增批次版本。

## R2. 事务、身份与副作用边界

- 整理、核对与入账使用既有服务端可信身份、原事务入口和同一连接；不信任客户端 uid。子模块不新开事务、不独立提交、不把写入移到事务外。
- 保留各操作自己的锁获取顺序、版本检查位置、拒绝条件、行动与事件/问题/映射/关系写入次序、失败回滚和幂等回执。不为统一外观而重排。
- `recalculateUpdateCounts` 现有的“历史同步 → 草稿可达性 → 计数和批次版本更新”是一个有副作用的事务内步骤，不能作为廉价读统计重复调用。`synchronizeHistoricalReviews` 仍含失效关联恢复与候选同步，不能只保留同名底层候选函数。
- 批量账户映射继续在同一事务内完成，复用映射索引并执行原有一次批次收尾；不得退化为逐项网络请求或逐项事务。单项、批量、修订操作不得通过互调公开命令共享事务。
- 正式入账保留整批原子写入、来源唯一约束、锁内历史复查、账户物化、分期费用校验及交易写入顺序；本轮不重排 `finance-update-posting.js` 的 SQL。
- 受影响场景覆盖请求重放、并发、版本过期、历史变更、中途失败、成功响应丢失及用户隔离；基线已覆盖的用例继续复用。

## R3. 契约与旧数据兼容

- 已有草稿、旧语义计划、已入账批次及本机持久请求可沿原流程继续或恢复；不能要求清库、删除草稿或重新导入。
- 公开 action 集合、请求/响应、错误码、schema、身份键、摘要、游标、规则/计划版本和回执内容不变。工厂返回五个方法不等于五个公开 action；不得给未注册的 `reviseAccountMapping` 新增网络入口。
- 对外契约和存量数据兼容不等于保留旧内部路径：移动纯规则/存取时，同一提交更新生产消费者与测试，不增加转导出、旧协议 fallback、能力探测或双实现。
- `createReviewIssueService` 仍是正式命令组装入口，不属于待删除的内部兼容层。原内部服务方法是否仍被调用以 P0 清单为准；不要在等价拆分中擅自删除或公开它。
- 必须改变业务输出、持久字段、版本或公开契约的内容，单列业务变更与迁移评估；其余可独立验证的结构工作继续，不将缺陷修复伪装成搬迁。

## R4. 页面、异步响应与写入恢复

- 读取结果只能回填仍有效的用户会话、页面、批次、视图版本及当前问题/弹层。翻页、切核对项、关弹层、隐藏、卸载或退出登录后的失效读取不得回填。
- 已发送写命令的结果与页面渲染分开：旧页面可以停止显示，但命令事实由既有草稿/回执协议确认或用原请求恢复。页面失效不等于服务端回滚，不得因此丢掉可恢复状态、生成新 requestId 或再发一笔入账。
- 退出登录仍遵守原用户隔离与清理规则；旧用户的回执不得写入新用户状态，也不得为保存回执而跨用户落盘。
- `runtime` 仅负责生命周期、页面活动 epoch、订阅/释放和 UI 协调；`import-view-session` 保有读视图版本、游标与分页缓存；`import-draft-session` 保有草稿队列、在途请求、幂等键和 `postFlight`。不引入第二套会话、缓存、持久格式或全局 store。
- 编辑时延后后台投影；关闭弹层后按现行顺序应用。写成功而摘要失败时保留成功事实和恢复入口，不能覆盖输入或把已入账显示成未提交。
- 原始记录继续在同层直接展示当前页的原始列和值；保留空值、零、重复列、原始编码含义、单项失败重试及超长原文入口。
- 生命周期、WXML 处理函数与共享字段只有明确的所有权。`busy`、`currentIssue`、待应用后台视图等由清单指定 owner 协调，不以对象合并顺序决定，也不让流程互相暗中清空状态。
- P0 发现原实现违反以上不变式时，先记录可复现基线缺陷和影响；不得用放宽断言掩盖，也不得将修复混入结构提交。影响当前阶段安全的缺陷未解决时，该阶段不能宣称验收通过。

## R5. 可理解、可检查的模块边界

- 从公开/内部服务入口能直接定位事务、场景处理、共享规则和存取，不需要追页面覆盖链或大型分支找到实际执行者。
- 纯规则模块不依赖 SQL、连接池、微信页面、存储或服务工厂；确定性规则可保持现有对象修改语义，不为“纯函数”额外深拷贝或改变返回行为。
- core/read/maintenance/semantic-plan-upgrade 不再为公共能力依赖 `review-issue-service`；新公共模块不反向依赖命令入口或场景。读取路径不能调用带写副作用的收尾函数。
- 每次移出一组页面方法就移除对应旧覆盖；剩余覆盖有清单、不新增冲突、不双执行。P4 出口彻底移除 `paged.enhance`，但保留有界 `setData`。
- 只按真实职责建立模块，不按行数、每条 SQL 或每个函数拆文件；不创建占位接口、控制器基类、通用容器或插件引擎。
- 来源接入沿用既有 profiles/解析器契约；本轮 P5 默认只审计银行身份与方向差异，不改变其实现。两函数仍独立部署并保持共享规则一致，不引入跨包 require 或新构建发布体系。

## R6. 等价证据、资源预算与交付

- 固定合成输入的前后比较保留金额、账户、业务日期、顺序含义、来源归属、关系、决定、版本和错误码。生成 ID 可按实体类别建立一致的一一映射，所有外键/关系/行动引用须同步映射；不能删除 ID 字段后只比较数量和金额。
- 只排除经列明的运行时间等非业务噪声；确定性身份键、摘要、游标与业务时间不作为噪声删除。需要固定生成 ID/时钟时优先使用已有测试注入点，不为测试新造运行时框架。
- 保持现有响应、SQL、`setData`、缓存硬预算；同输入还须比较实际 SQL 次数、云请求次数、响应字节、派生计算和 `setData` 次数。未超上限不代表允许无解释退步，不新增逐事件查询、额外整批扫描或前端全集常驻。
- 数量/字节等确定性指标原则上不增加；确有技术性差异须列出原因与影响并评估，不能仅以“仍低于预算”放行。耗时比较记录相同环境和波动范围，不用一次墙钟测量宣称提升或回归。
- 复用现有 Node 测试与隔离 MySQL，不按新文件数重复建测试。补缺失接缝的行为测试；字符串和依赖断言仅证明结构，不替代账务与恢复验证。
- 每阶段记录精确 SHA、原位置/消费者、通过/失败/跳过、差异解释、剩余风险与正常 revert 入口；行数减少不是完成证据。依赖后续提交时按逆依赖顺序撤回，不回滚业务数据、不删除草稿、不强推。
- 代码入口变化同步入账逻辑说明、架构、相关现行说明和实施规划。原生工具、云函数、体验版、真机验证分别报告；未执行不计通过。
- 当前授权是文档修订与任务分支推送；Astra 收到用户转交的实施指令后按其范围实施、测试和推送。没有额外授权不合并 main、不部署、不执行云数据库迁移、不上传/审核/发布、不操作真实财务记录。
