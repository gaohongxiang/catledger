# MINI-1915：一期减复杂度与导入模块化

边界已按 2026-09-24 一期整合冻结；当前实施状态和验证记录仅维护在 [实施规划](../../docs/招财猫记账本实施规划.md)。本规格定义范围，不证明合并、发布或真机验收已完成。

## 一期目标与范围

在不改变账务、公开协议和现有交互的前提下，减少实际维护负担：公共职责不再依赖核对总入口，页面不再靠隐式覆盖运行，当前状态不在多个文档重复维护，测试不过度绑定内部写法，缓存不继续叠加没有证据的新机制。

**一期是一个交付批次，不是一个巨型提交，也不是只实施 P1。** P0 → P1-A → P1-B → P2 → P3 → P4 → P5 是一期内部步骤；沿原任务分支小步验收。项目级审查不等于全项目重构，文件数或行数下降不是完成目标。

| 一期工作 | 必做结果 | 范围上限 |
| --- | --- | --- |
| 导入模块化 | 解除公共能力倒置；拆场景和页面覆盖；写清事务与状态所有权 | 原导入核对服务、工作台及其真实消费者；不重新拆普通 API 或贷款体系 |
| 文档收敛 | 根 README/文档索引只导航；实施规划维护当前状态；历史记录注明时间与性质 | 修订现有文件，不新建第二个看板、文档框架或一批重复交接文件 |
| 相关测试整理 | 先映射保护目标，补行为覆盖，再删除确实重复或只锁定内部写法的断言 | 只整理本期触及的测试和缓存测量用例，不全库更换测试框架 |
| 缓存测量与条件性简化 | 给出关键链路的请求/失效/渲染证据；有等价证据才做局部减法 | 既有读取链路内的小改；没有可证明冗余时保留实现并记录结论，不能虚报已优化 |

保留微信原生小程序、两个云函数、MySQL、云存储，以及来源证据 → 经济事件 → 正式交易、可信身份、原子事务、幂等回执、版本和恢复机制。缓存测量是必做，缓存代码变化是条件项；其判定不能拖住其他已可独立验收的工作。

**本期不做：** 复式分录/不可变账本迁移、影子双写与历史回填、SQLite/Redis/新缓存层、微服务/新框架、插件引擎/AI、全站 UI 重设计、普通交易/贷款模型重写，以及改变来源语义或正式入账 SQL。历史长期规划保留，但不作为 MINI-1915 一期交付依赖；不自动取消其他任务，也不自动启动下一期。

## 内部步骤与停止边界

| 步骤 | 交付内容 | 出口 |
| --- | --- | --- |
| P0 | 调用/副作用/状态清单，文档导航收敛，相关测试映射，缓存和资源基线 | 原实现的问题与新回归可区分；不带不明失败重构 |
| P1-A | 纯规则及字段掩码原样提取，同提交更新消费者和测试 | 首个业务代码提交不动 SQL、事务、页面、版本 |
| P1-B | 事件/问题存取、有效投影和事务内收尾 | core/read/maintenance/upgrade 不再为公共能力依赖总服务 |
| P2 | 账户映射含分组刷新 → 普通决定与历史核对 → 明确还款 | 五工厂方法/四对应公开入口均有归属，原事务不重排 |
| P3 | 生命周期和请求适配唯一协调，再迁移上传 | 读视图和持久命令各守原所有权，旧页面不丢写入事实 |
| P4 | 账户/交易核对、入账展示及相关测试整理 | 移除 enhance，关键行为和页面预算不退步 |
| P5 | 缓存条件项判定/实施、来源边界审计、最终门禁、文档与候选交付 | 记录完成/保留/后续三类结果，不为凑优化强改代码 |

每个提交只处理一个可验证职责；结构搬迁、缓存减法、测试替换和基线 bug 修复分开提交。发现需要改变数据/规则/公开接口/缓存一致性语义的内容，退出本期该子项并记录，不继续扩大任务。详细副作用、缓存准入和验证要求见 design 与 requirements，不在入口重复复制。
