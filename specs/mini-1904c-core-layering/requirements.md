# MINI-1904C 核心服务分层需求

## 目标

在不改变现有小程序界面、公共 action、请求响应字段和 MySQL schema 的前提下，收口正式账本后端的内部边界，为 MINI-1905 账单导入保留唯一、可复用的正式入账入口。

## 范围

- 将交易写入、交易查询、统计报表和纯业务校验拆成独立模块；
- 首页与完整统计在一次只读一致性快照内完成读取；
- 公共契约与服务端动作、客户端调用之间建立自动漂移检查；
- 同步当前架构说明和任务状态。

## 非目标

- 不实现文件上传、账单解析、整理或导入入账；
- 不新增、删除或修改数据库表与字段；
- 不改变登录、页面、主题和用户可见文案；
- 不部署云函数，不合并或推送分支。

## 验收条件

1. 当现有客户端调用任一公开 action 时，系统应保持原有请求、响应和错误码语义。
2. 当执行交易写操作时，系统应继续在用户范围的幂等事务内完成校验和写入。
3. 当读取首页或统计数据时，系统应在同一 MySQL 只读一致性快照内完成该响应的全部查询。
4. 当服务端动作或客户端调用与 `shared/catledger-api.json` 不一致时，自动测试应失败并指出漂移。
5. 当运行现有测试时，非数据库测试应全部通过；有测试库时，既有 MySQL 集成测试也应保持通过。
