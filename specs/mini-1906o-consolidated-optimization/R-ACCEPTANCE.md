# MINI-1906R 本机候选验证

2026-09-14。恢复批次基线 `05bac3a4`；本批只修测量和反例定位的复杂导入热点。动态状态见主看板 0.5 / 19.4。原有 O1～O3、PERF0～5 及记一笔/导入界面和导航保留。

## 环境与范围

Node 24.14.1、MySQL 8.4、loopback、新建合成隔离库、独立 API/import 最小权限账号；V8 old-space 256 MiB。每场景每规模一份样本，不称 P95；heap 为动作前后值，RSS 为进程生命周期高水位，不能冒称动作内存峰值。云端、真机、正式容量未验证；无部署、云迁移或真实账本操作。

六类负载均验证 1000 / 5000 / 24990 行。组合付款与多目标还款上限各生成 49980 笔正式交易；先走一次真实公开确认命令，其余相同拆分在隔离库播种，不能称全量逐页点击性能。解析、种子构造不混入整理动作耗时；历史复制用 BOM 改文件字节，仍是每文件 4998 条交易。

各上限复杂动作和用户锁均满足预先冻结的 20 s；post SQL 满足 `120 + 12 * ceil(rows/100)`。同用户手工写在导入持锁后开始，按锁序等待；独立用户同时成功。所有具体等待、持锁、响应字节、关系数、金额守恒及 SQL 指纹见 [R-METRICS.json](R-METRICS.json)。只保存摘要与无绑定值指纹，不保存原账单或身份日志。

普通负载补回归：1000 / 5000 / 24990 行入账分别 0.395 / 1.190 / 8.425 s，上限 1561 SQL、1028 B、用户锁 8.387 s；原 20 s 动作 / 10 s 锁目标保留。

上限测量并非一次全通过：先后复现退款/账户组平方扫描、代表成员错误执行计划、两处全量序列化导致的 256 MiB 堆失败、历史关联 85.139 s，以及升级 24.291 / 21.350 s。分别以索引、集合、有界上下文和惰性 SQL 行序列化修复。升级最后采样定位已确认组去重约 5.340 s；稳定反例从 1000002 次读取降至 5000 次以内。夹具空行超 CSV 上限单独修正，未放宽产品上限或超时。
