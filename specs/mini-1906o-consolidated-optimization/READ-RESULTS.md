## 结论与范围

READ-0～3 已形成源码、契约、隔离测试和原生合成证据。主要收益是减少冗余请求、后续分页汇总与长列表数据桥接量。冷启动和写后返回的最新数据耗时没有明显改善证据；没有候选云端或手机性能达标的结论。

- 普通失效保留可展示快照，同时撤销新鲜标记；更新中和失败均明确标注上次结果。请求合并、写屏障、会话与迟到响应保护保留。
- API 缓存读取在同一个 REPEATABLE READ 只读事务取得可信身份、十进制修订和数据。条件读取与 `reads.validate` 使用单一协议，不探测能力、不回退旧协议。两函数全部相关写路径的事务/重放覆盖见 [READ-REVISION-AUDIT.md](./READ-REVISION-AUDIT.md)。导入清理使用稳定请求号，修复重复清理推进修订的问题。
- 跨前台合并一次版本确认；身份确认后才能恢复匹配环境/用户的本地快照。上限 12 项、512 KiB、单项 96 KiB、24 小时、流水最多 3 页；写盘失败只影响缓存，退出和淘汰不清除待核实原请求。合并写盘延后到下一任务，执行前复核会话。
- 覆盖写失效和前台校验后移除贷款详情等自动加载的无条件 force。贷款内容先独立恢复，陈旧上下文禁止作为编辑/付款依据；写后并行目录失效时自动补读。
- 流水 cursor 页省略 summary，保留首屏原有汇总口径；签名游标绑定用户、筛选和修订。跨版本重取首屏，不拼接。按 `transactions[index]` 追加，选择状态按字段更新；已确认删除后刷新失败不会重建原写请求。

没有改布局、样式或贷款入口，没有重做旧 PERF/S/R、导入真分页、小回执或批量 SQL。没有新数据库、第二套余额、迁移、权限变更或部署。READ-4 本轮只做热点和计划评估：本机确有聚合 SQL 成本，但当前云端分层等待和手机证据不足，不额外引入余额投影、统计聚合或索引。

## 同条件后端与页面逻辑对照

原始初测是 [READ-BASELINE.json](./READ-BASELINE.json)。收尾时重新运行旧源码得到 [READ-BASELINE-RERUN.json](./READ-BASELINE-RERUN.json)，与最终源码的 [READ-AFTER.json](./READ-AFTER.json) 对照：同一 Apple M2 Max、macOS arm64、Node 24.14.1、专用 MySQL 8.4 容器、回环 TCP；相同合成分布、0/1,000/10,000/50,000 行，每档每接口 3 次，表中为 50,000 行中位数。不是手机耗时，也不是 p95。

| 测量项 | 优化前 | 最终候选 | 解释 |
| --- | ---: | ---: | --- |
| 首页完整读取 handler | 120.13 ms | 108.91 ms | SQL 仍是主要成本，未改聚合算法，不将波动算作该算法的优化成果 |
| 统计完整读取 handler | 185.50 ms | 163.92 ms | 同上，未宣称冷加载已解决 |
| 流水首屏 handler | 59.49 ms | 55.11 ms | 汇总仍保留 |
| 流水第二页 handler | 57.69 ms | 39.44 ms | 约减少 31.6%；样本量有限 |
| 流水第二页 SQL 时间 | 57.31 ms | 38.18 ms | summary SQL 从 1 次变 0 次；总语句从 6 变 5 |
| 未变前台的后端读取 | 完整首页 120.13 ms / 4,381 B | `reads.validate` 1.84 ms / 74 B | 一次轻校验，4 条事务/身份语句、0 聚合；字节为 data JSON，不含平台传输封装 |

优化前 50,000 行首页 SQL 中位数 119.43 ms，统计 183.80 ms，分别接近整个 handler 耗时。连接获取约 0.01～0.03 ms，身份 SQL 约 0.13～0.34 ms，响应序列化约 0.01～0.08 ms。因此本机后端主要等待在业务 SQL；SQL 指纹、源码位置、连接、身份、序列化与残余控制流时间分别记录在原始指标。`businessSqlMs` 是总 SQL 减身份 SQL，仍包括事务控制，不冒充纯业务 CPU。账户聚合 EXPLAIN 也在两份指标的 `account-plan` 项：保留实际 access/key/估算行数，未据此执行新索引。

真实页面代码 VM 使用固定每次 40 ms 合成等待。贷款返回 41.18→0.43 ms，请求 1→0；第十页最大 setData 116,439→12,295 B，约减少 89.4%。冷启动 86.57→88.78 ms，写后返回 83.46→84.07 ms，未证明提速。同会话均 0 请求；后台仍需 1 次请求，但从完整读取变轻校验。弱网失败两次尝试、约 387 ms，最终候选恢复旧快照约 1 ms，最新数据未就绪。这些数值仅验证逻辑和桥接代理，不能替代真实渲染、网络与交互证据。

候选指标的 `dirty:true` 来自未提交的观测文件和临时依赖链接；测量时 `git diff --exit-code HEAD -- miniprogram cloudfunctions shared` 通过。业务源码没有未提交补丁；临时依赖在提交前移除。基线通过 git archive 取得指定提交，不切换或重置任何工作树；仅基准脚本的 Git 元数据来源适配到归档标记。
