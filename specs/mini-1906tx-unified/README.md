状态：待验收。基线 main `34a0d50d`；当前主会话串行负责 API/import、共享契约、页面、验证和文档；独立分支 `codex/mini-1906tx-unified`。承接 MINI-1906TX-MANAGE 的真机反馈，用户明确要求记一笔和导入账目统一多选删除，沿用会话更新授权。

## 设计

1. 用途：明细统一选择和删除手动/导入账目，包括混选；导入历史只是按来源查看账目的快捷入口。删除不依赖历史整批撤销信息。
2. 视觉：沿用暖色编辑式账本和既有主题 token，#faf8f4 / #ffffff / #29231e / #746a60 / #d97732，删除色 #a95132；不新增视觉体系。
3. 字体：PingFang SC / Source Han Sans SC / Noto Sans CJK SC，正文28rpx/辅助24rpx/按钮26rpx，沿用既有触控尺寸。
4. 布局：明细左勾选右金额，固定选择工具条；导入历史左文件/时间、右剩余账目数；查看某次导入时以顶部来源提示替代月份选择，可随时返回全部明细。

## 契约

- `transactions.deleteMany` 接受 1..100 个当前用户的 manual/import 收入、支出、转账、退款，按所选 ID/version 整组原子软删除，允许混选和已停用账户；保留版本、贷款、组外退款和最终现金余额约束。保留原始证据、导入历史、账户、映射和分类规则，不撤销 FinanceUpdate。
- `transactions.list` 新增 `importUpdateId`。普通查询仍必须有 month；指定导入时可省略月份，查询跨月的本次直接关联正式账目（包含复用，排除 refund_original 和被替代链接）。参数、签名游标、用户隔离和汇总同源；无权访问的导入返回 NOT_FOUND。
- `financeUpdates.list` 增加当前有效账目数量 transactionCount；历史状态不因账目删除伪装成 undone。页面移除整批撤销及其影响查询，改为“查看账目”，零账目显示“账目已删除”（历史零入账显示“无账目”），可重新选择文件导入。
- 原始文件因后续删除而缺少有效账目时，用户重新上传同字节文件可复用原始解析证据并创建新的 FinanceUpdate，保留旧证据。仍有活动整理时复用/替换既有草稿；尚有效来源仍按身份去重，不重复入账。部分删除的同一多交易来源仍视为已入账，避免把保留分项重复记账；全部分项删除后可完整重导。
- 在途删除保持原始请求/所选集合，换会话清除私有视图；未知旧操作不能因新选择被重放。当前入口不再生成整批撤销请求。
