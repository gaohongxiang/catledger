# MINI-1904B 需求：小程序视觉系统收口

## 1. 目标与范围

在不改变“首页 / 明细 / 中央记账 / 账本 / 我的”信息架构、登录门禁与财务口径的前提下，将现有界面收口为“暖橘编辑式轻账本”。解决卡片堆叠、字阶与间距随意、底栏与弹层样式混杂、主题令牌同时控制语义和几何等问题。

本任务主要修改微信原生小程序的视觉、布局和公共界面组件，并在视觉验收中收口客户端连接状态与只读请求重试；不修改云函数、MySQL、公共 API、服务端身份规则、金额口径或账单导入能力。

## 2. 用户故事与验收

### R1 统一视觉基线

- 当用户在任意一级页面间切换时，小程序应使用一致的页边距、字阶、分区标题、点击反馈、图标和安全区规则。
- 当界面展示普通信息时，系统应优先使用留白、字号、对齐和细分隔线建立层级，不得把每一组内容都放进厚重阴影卡片。
- 当背景渲染时，系统不得使用格纸、噪点或与账务内容竞争的装饰纹理。

### R2 稳定的主题架构

- 当用户切换六套主题时，系统应保持页面信息架构、字阶、间距、触控尺寸和安全区不变。
- 当主题提供视觉差异时，系统只允许其改变品牌色、边框倾向、受控圆角和阴影强度，不得改变业务组件尺寸、数据或财务颜色语义；收入在所有主题中保持绿色，支出保持红色。
- 主题主卡保持各自原有明度，不为追求统一前景色而压暗整张卡；小标签与说明使用 `heroInk` / `heroMuted`，大金额单独使用 `heroValueInk`，并满足大字对比度要求。
- 当主题值无效或本机存储失败时，系统应回退到暖橘主题且页面仍可用。

### R3 轻量财务总览

- 当用户查看首页时，系统应依次展示净值、本月收支、近半年趋势、活动账户和最近账目，不得恢复创建账户卡或页内记账按钮。
- 当首页存在多条交易时，最近账目只展示最新 3 条并保留“全部”入口，避免摘要页下半部形成完整列表的视觉重量。
- 首页重色摘要使用页面外框线，标题、图表、账户和最近账目使用统一内内容线，避免文字与圆角卡片外沿机械贴齐产生越界错觉。
- 当趋势数据存在时，系统应用收入和支出双系列显示时间趋势，并通过标签或线型辅助颜色语义。
- 当未登录、无数据、加载或出错时，系统应保留同一信息骨架并显示轻量状态，不得用营销式卡片替换整个页面。

### R4 高频操作的紧凑与可用性

- 当用户查看明细时，系统应将日期、收支摘要、筛选和账目列表紧凑排列，不在顶部放置“记一笔”。
- 当用户点击底部中央加号时，系统应弹出可明确关闭的底部面板，其中“导入账单”是主操作，“手动记一笔”是次操作。
- 当用户点击图标、行或按钮时，有效点击区应不小于 `88rpx`，相邻点击区应保持有效间隔，固定底栏不得遮挡滚动内容。
- 中央记账入口应保留不小于 `112rpx` 的有效点击区，但可见色块不得填满点击区；使用 `88rpx` 轻量圆形加号、细白边和柔和阴影，只轻微上浮，并在下方显示与其他导航同字阶、同灰度的“记账”，避免形成压住底栏的厚重焦点。

### R5 页面职责不回退

- 当用户打开“账本”时，系统应只提供“账户管理”和“分类管理”两个同规格入口及必要摘要。
- 当用户打开“我的”时，系统应显示用户头像昵称、主题、数据与隐私、关于和退出登录，不得出现账户设置或账本设置。
- 首页与“我的”应共用同一头像回退规则：只有已登录且用户主动选择头像时显示用户头像，其余情况显示品牌 Logo，不使用另一套中性占位图。
- 当未登录用户触发受保护操作时，系统应继续使用统一登录面板，登录成功后留在触发位置并继续原操作。

### R6 连接状态可信且可恢复

- 当 `bootstrap` 成功而账户摘要暂时失败时，“我的”应继续显示个人账本已连接，并把失败限定为数据暂未同步，不得让用户误以为登录或账本身份失效。
- 当 `bootstrap` 或只读查询遇到明确的网络、超时或云端瞬时错误时，客户端应在短延时后自动重试一次；写动作不得由通用调用层自动重放。
- 当开发者工具缺失 AppID/项目上下文时，客户端应返回可识别的开发环境错误且不重复请求；正常用户错误只保留可操作说明，不展示平台堆栈、OpenID、内部用户标识或数据库信息。
- “我的”只保留头像旁的一处连接/同步状态和轻量重试入口，不在页面底部重复同一错误或客户端技术说明。

## 3. 视觉契约

- 方向：`Editorial / magazine`，中文产品名为“暖橘编辑式轻账本”。
- 默认色：暖橘 `#D97732`、暖米白 `#F8F3EA`、纸面 `#FFFDF9`、主墨 `#29231E`、灰绿 `#64705D`。
- 字体：中文展示与正文使用 `PingFang SC` / `Source Han Sans SC`，数字使用 `DIN Alternate`。这是微信原生小程序为中文覆盖、包体和跨设备稳定性对通用 UI 技能字体禁令的必要覆盖。
- 布局：左侧信息轴、右侧金额轴；以留白和细线为主，仅净值、中央加号和底部面板使用强层级。

## 4. 非目标

- 不新增 Web 端、跨端框架、远程字体、动画库或第三方 UI 框架。
- 不实现账单解析、上传或批量入账。
- 不为了视觉改造而改变财务数据、请求序列或登录语义。
