# MINI-1906A1 实施计划

> 状态：未开始。必须先完成 MINI-1906V；本阶段不得新增 JournalEntry / Posting。

- [ ] 0. 冻结基线与失败证据
  - 记录仓库、迁移、两支函数和体验版基线
  - 为不可达草稿、修正现金负数、撤销副作用和聚合局部修正建立失败测试
  - 枚举所有导入维护写入口和余额/统计读取入口
  - 冻结公开冲突码、规则版本和兼容响应字段
  - _Requirement: A1-R1, A1-R6_

- [ ] 1. 增加最小审计迁移
  - 为账户草稿 superseded 状态和必要来源动作增加字段
  - 为本批创建账户、映射和分类别名补足可安全撤销的来源证据
  - 添加 uid 复合索引、唯一约束和外键
  - 保持 forward-only、可重入和 checksum
  - _Requirement: A1-R2, A1-R4, A1-R6_

- [ ] 2. 收口账户草稿物化
  - 从最终 ready 事件端点、有效映射草稿和聚合分配计算可达集合
  - posting 只物化可达草稿
  - 修改决定、排除和放弃时 supersede 不可达草稿
  - 覆盖重放、并发和历史草稿兼容
  - _Requirement: A1-R2, A1-R6_

- [ ] 3. 统一修正影响与现金门禁
  - 实现旧影响、新影响和账户净差额纯领域函数
  - `correctionImpact` 返回完整交易集合、冲突、规则版本和摘要
  - `correct` 锁定完整集合并核对预览 token
  - 修正复用与手工交易/首次 posting 等价的现金不可透支语义
  - 覆盖退款依赖和版本变化
  - _Requirement: A1-R3, A1-R6_

- [ ] 4. 收口整批撤销副作用
  - `undoImpact` 返回交易、账户、映射、别名、关系和外部依赖摘要
  - 撤销软删除本批创建交易并更新事件/关系审计状态
  - 停用仅由本批创建且未被其他事实使用的账户
  - 撤回没有独立使用证据的映射和分类别名
  - 外部修改、退款引用或后续使用时拒绝静默覆盖
  - _Requirement: A1-R4, A1-R6_

- [ ] 5. 实现多交易事件整体维护
  - 所有维护动作锁定完整 EventTransaction 集合
  - 聚合还款按冻结候选和守恒金额原子重建
  - 其他多交易事件返回必须整批撤销的稳定结果
  - 小程序隐藏危险的单笔编辑入口
  - _Requirement: A1-R5, A1-R7_

- [ ] 6. 接入小程序影响预览与刷新
  - 展示账户差额、将保留/停用对象和冲突原因
  - 确认动作携带 expected token 与同一 requestId
  - 完成后统一刷新账户、明细、统计和导入记录
  - 补齐公共契约、模型和云调用策略测试
  - _Requirement: A1-R1, A1-R7_

- [ ] 7. 完成全量验收
  - 根目录、两支函数单元测试和 MySQL 8 全量集成测试
  - 迁移重跑、事务回滚、并发、幂等、跨用户隔离和日志隐私
  - 真实微信身份走通普通修正、聚合重建、整批撤销和统计刷新
  - 生产依赖审计、`git diff --check` 和范围匹配的代码审查
  - 同步业务规则、架构、入账逻辑、现行说明和实施规划
  - 取得单独授权后再更新开发云、上传体验版、合入并推送
  - _Requirement: A1-R1-A1-R7_

## 执行门禁

1. MINI-1906V 未完成不得开始任务 0。
2. 四个失败测试未建立不得修改生产实现。
3. 可达集合和副作用来源无法由服务端证明时，宁可拒绝操作，不根据名称或时间猜测。
4. 影响预览与执行摘要不一致时必须返回冲突。
5. A1 完成前 Transaction 始终是余额和统计唯一权威。
6. 不开始 JournalEntry、Posting、历史分录回填、贷款、多币种或 AI。
7. 数据模型、迁移、公共 API、幂等和撤销规则由单一主负责人串行冻结。
